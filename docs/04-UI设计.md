# UI 设计

桌面工具的界面布局、交互、编辑保存机制、验证反馈、规划中功能。所有 tbl 系统的硬性约束都在 @01；这里只讲面向用户的呈现与操作。

## 1. 整体布局

#### 顶层 3 个大区

| 大区 | 位置 | 尺寸 | 责任 |
|------|------|------|------|
| **Toolbar** | 顶部 | 32px | 撤销/重做 + 当前 Project 保存 / 重新加载（详见 @5.1） |
| **TreeSection + GridSection** | 中部填充 | 自适应高度 | 配置树 / 表格 二选一聚焦 |
| **BottomPanel** | 底部 | 默认 120px，可拖拽 | 两个 tab：**日志**（操作日志，独立于表格区）+ **Excel 文件**（`.excel` 目录卡片浏览器 + 同步面板入口，详见 @6） |

#### 中部两个子大区

| 大区 | 位置 | 尺寸 | 责任 |
|------|------|------|------|
| **TreeSection** | 左 | 默认 240px，最小 220px，可拖拽，无最大限制 | 配置树（4 段：标题 / 顶部功能区 / 过滤功能区 / 节点列表，三层节点 project → group → node） |
| **GridSection** | 右 | 自适应宽度 | 当前选中节点的表格详情（5 段子区域） |

调节线、滚动条等具体行为见 @1.5。

### 1.2 区域归属原则

每个 UI 元素都明确归属一个大区，不跨级悬浮：

- **属于「当前选中表」的所有控件归属 GridSection**：表名标题、表级开关、公式栏、状态栏，宽度都跟随表格区。
- **属于「项目浏览」的控件归属 TreeSection**：新建项目按钮 / 排序下拉、搜索 / 过滤 / 完整组、节点列表。
- **全局命令归属 Toolbar**；**日志 / Excel 文件浏览归属 BottomPanel**。

这样读者一眼就能从位置反推归属：选中 cell 时看到的「B3 │ 战士」公式栏，本质是 `GridSection` 的子组件，它窄于 `Toolbar`、宽于 `TreeSection`，自然不会让人误以为是全局栏。

### 1.3 GridSection 子区域

`GridSection` 是表格大区，从上到下 5 段子区域，全部与 `GridArea` 等宽：

| 子区域 | 高度 | 内容 |
|--------|------|------|
| **GridHeaderBar** | 24px | 表名（含图标 + 路径）+ 副标题（行列数 / 模式）+ 「自动列宽」勾选 |
| **GridRibbon** | 24px | 表级视图开关（仅渲染影响），见 @5.2 |
| **FormulaBar** | 22px（动态） | 选中单元格时显示坐标 + 公式栏；未选中时 0 高度收起 |
| **GridArea** | 自适应 | 固定表头 + 可滚动数据区 |
| **StatusBar** | 20px | 当前选区 + 光标位置 |

未选中任何节点时，`GridSection` 显示居中占位文本「选择左侧节点查看详情」，子区域条仍可见但内容为空。

### 1.4 TreeSection 子区域

`TreeSection` 是配置树大区，4 段子区域，宽度跟随大区：

| 子区域 | 高度 | 内容 |
|--------|------|------|
| **标题栏** | 24px | 「项目列表」固定标签 |
| **顶部功能区** | 自适应 | 新建项目按钮 + 排序下拉 |
| **过滤功能区** | 自适应 | 搜索框 → 过滤下拉 → 完整组勾选（顺序固定） |
| **节点列表** | 自适应填充 | 树形导航，可滚动 |

### 1.5 拉伸调节与滚动条

#### 大区拉伸调节

| 调节线 | 位置 | 行为 |
|--------|------|------|
| **左右调节线** | TreeSection 与 GridSection 之间（垂直走向） | 鼠标悬停光标变 ↔，左右拖动改变两者宽度 |
| **上下调节线** | 中部（树+表格）与 LogPanel 之间（水平走向） | 鼠标悬停光标变 ↕，上下拖动改变 LogPanel 高度 |

约束：

- TreeSection：默认 240px，最小 220px（功能区搜索框 + 过滤下拉的最小可读宽度），无最大限制
- LogPanel：默认 120px，最小 40px（保留标题 + 一行日志可见，避免拖到 0 后找不回）；上限由窗口高度决定
- Toolbar / GridHeaderBar / GridRibbon / FormulaBar / StatusBar 不可拖拽，固定高度
- 用户拖拽后的尺寸保留在会话内（不持久化到配置）

> 实现：slint 没有内置 splitter，手写 4px `Rectangle` + `TouchArea(mouse-cursor: ew-resize/ns-resize)` + `pressed-x/y` 累加 delta，详见 @05.2。TreeSection 内层多一层 border + padding，搜索框最小可读宽度对应外层 220px。

#### 滚动条

滚动只发生在「内容超出可视区」的局部，不在整窗口级别：

| 区域 | 滚动方向 | 行为 |
|------|----------|------|
| **TreeSection 节点列表** | 双向（H + V） | 节点超出 → 右侧出垂直条；名字过长被窄面板截断 → 底部出水平条 |
| **GridArea 数据区** | 双向（H + V） | **表头水平随数据滚动同步、垂直固定**；**行号列垂直随数据滚动同步、水平固定**；列 / 行号 gutter 永远停在自身轴 |
| **LogPanel 列表** | 垂直 | 内容超出可视区 → 右侧出垂直条；按时间倒序，最新日志在最上方 |

#### 滚动条样式

- 滚动条只在区域有 hover / 滚动时显示，离开后淡出
- 内容不足时不显示滚动条（不留空白槽）
- TreeSection 与 GridArea 的水平 / 垂直滚动条独立，互不影响

### 1.6 窗口标题栏

原生 OS 标题栏显示 `tablet vX — <版本库分支>`（@03.8.6 `workspace info` 同一套探测）：

| 仓库状态 | 标题 |
|---|---|
| Git 分支 | `tablet v1.2.3 — main @ 8c47a4f` |
| Git detached HEAD | `tablet v1.2.3 — HEAD@abc1234` |
| SVN | `tablet v1.2.3 — trunk@12345` |
| 无版本库 | `tablet v1.2.3` |

分支取**工作区所在仓库**（不是 `tablet.exe` 所在目录），启动加载时探测一次；
作用是让策划一眼看到当前在哪个分支改配置，避免改错分支。外部切分支后需重新打开 / 重载工作区。

## 2. TreeSection（配置树大区）

左侧主区域，**四段式**：标题栏 / 顶部功能区 / 过滤功能区 / 节点列表。所有控件宽度跟随大区。所有 project 同时加载、同时展示在一棵树里——**没有"切换 project"概念**，跨 project 复制粘贴节点是自然操作。

```
┌────────────────────────────────────────┐
│  项目列表                              │ ← 标题栏
├────────────────────────────────────────┤
│  [新建项目]  [排序: ID ▼]              │ ← 顶部功能区
├────────────────────────────────────────┤
│  搜索: [search________]                │
│  过滤: [全部 ▼]                        │ ← 过滤功能区
│  ☐ 完整组                              │
├────────────────────────────────────────┤
│  ▼ 📦 slg-test                         │ ← project 根（顶层，opened）
│      ▼ hero                            │ ← group（中层）
│          📊 HeroBase                   │ ← node（叶层）
│          📊 HeroSkill                  │
│      ▼ global                          │
│          📋 GameConst                  │
│  ▶ 📦 slg-prod                         │ ← 折叠的 opened project
│  ▷ 📦 mini-game                        │ ← closed project（灰态、无展开三角）
└────────────────────────────────────────┘
```

### 2.0 多 Project 同时管理

**核心模型**：启动时扫描 `<repo-root>/projects/` 全部加载到 `ProjectEngine`，树视图把每个 project 显示为顶层节点（📦 图标 + name）；下面挂 group → node 两层。所有 project 始终在内存里，节点选中可在任意 project 之间切换，**不存在"卸载当前/加载下一份"的切换概念**。

#### Opened / Closed 两态

每个 project 有两种状态，由 TreeSection 顶部「新建项目」旁的开关 + 右键菜单切换：

| 状态 | 内存 | 树展示 | 可选中/可编辑 | 参与搜索/过滤 |
|------|------|--------|---------------|--------------|
| opened | 已加载 | 正常 + 三角展开 | ✅ | ✅ |
| closed | 仅元信息（id/name），不读 .tbl | 灰态（opacity 0.5/0.7）+ 无展开三角 | ❌（点击仅响应右键） | ❌ |

关闭 ≠ 删除：`closed` 仅卸出内存，磁盘文件保留；下次扫描仍可见。强需求：策划本机有十几个 project，平时只工作在 1-2 个，关掉其它降内存 + 减少树噪音。

| 维度 | 决策 |
|------|------|
| 节点定位键 | `(project_id, group, name)` 三元组 |
| 引用范围 | `@TableName` / `@EnumName` 仅在同 project 内解析；跨 project 引用 = 验证错误 |
| 新建落点 | 新建 group / table 默认落到选中节点所在 project；空选时落第一个 opened project |
| 跨 project 复制粘贴 | 走 `engine.node_clipboard`（见下），与系统剪贴板独立。单节点冲突自动加 `_copy`；整组粘贴冲突时弹命名确认框，确认后改子项名并改写组内引用；指向目标项目不存在的引用按验证错误暴露 |
| 搜索 / 过滤范围 | 仅扫描 opened project；closed 不参与匹配（避免命中却点不开） |
| 首屏展开状态 | opened project 默认按用户上次会话的展开/折叠状态恢复（不持久化具体节点级展开） |
| Project 标签显示 | `[ui] show_meta_id = false`（默认）显示 `instance_meta.name`；`true` 显示 id |
| 排序键 | TreeSection 顶部下拉控制（@2.3）：ID / 名称 / 已打开 / 创建时间 / 手动 |

#### node_clipboard（节点级剪贴板）

引擎内部维护一份独立于系统剪贴板的 `node_clipboard`，专用于树节点 / Group 复制粘贴。

| 入口 | 写入内容 |
|------|---------|
| Group 右键「复制 Group(含全部内容)」 | `Group { name, nodes: [...] }` 整组深拷贝 |
| 节点右键「复制」 | 单节点深拷贝（Table / Constant / Enum） |

右键菜单的粘贴项文案保持固定（「粘贴节点」/「粘贴为 v3」/「粘贴为 .tbl Group」…），
不把 clipboard 内容拼进 label；不满足条件的项**直接不出现**（见 @2.4）。

**整组粘贴有两种目标后端**：节点在内存里 `.tbl` / `xlsx` 同型，所以这只是"换一个保存写入器"，
不是数据转换（`paste_group_as`，@02.26.8）。

| 粘贴位置 | 行为 |
|---------|------|
| Project 根节点 | 仅当 clipboard 是 Group 时显示两条：粘贴为 `.tbl` Group / 粘贴为 Excel Group；有同名组或子项时先弹命名确认（@4.2 node_clipboard） |
| Group 节点 | 显示「粘贴节点」+ 两条整组粘贴；粘贴节点落到该 group（后端由目标组决定）；整组粘贴同样先做命名预检 |
| Table/Constant/Enum 节点 | 仅显示「粘贴节点」，落到该节点所在 group；项目内同名冲突 = 自动尾缀 `_copy` / `_copy2`；组内引用随子项改名改写 |

跨 project 是天然支持的：在 A project 复制后切到 B project 任意节点右键粘贴即可。

**整组粘贴先预检、冲突才弹框**：`preview_paste_group()` 在真正落数据前同时检查组名和每个子项的项目级唯一性
（Table / Constant / Enum 平铺命名空间，忽略大小写）。

| 预检结果 | 行为 |
|---------|------|
| 无同名组、无同名子项 | 直接粘贴，名字保持不变 |
| 任一冲突 | 弹「粘贴 Group」对话框：组名 + 子项列表（每行可编辑），冲突项预填 `_copy` / `_copy2` |
| 对话框确认 | 用用户确认的名字一次性完成改名 + 组内 `@xxx` / `ref_exists` 引用改写，全部属于同一个撤销事务 |
| 对话框取消 | 不写入任何数据 |

组内引用随子项改名改写（例如 `A → HeroA` 后 `@A` 变 `@HeroA`）。因此粘贴出的新组内部引用仍然指向**新组自己的**
子项，不会误指到原组的同名节点。指向目标 project 不存在目标的引用按验证错误暴露。

单节点「粘贴节点」不做弹框：目标位置明确、没有子项列表，冲突时直接按项目级唯一命名加 `_copy` / `_copy2`。

#### 老项目兼容

启动扫 `<repo-root>/projects/`：

| 情况 | 处理 |
|------|------|
| `projects/` 不存在但旧 `config/` 存在 | **自动迁移**：移动 `config/` → `projects/default/config/`、合并 `*.tblschema` → `projects/default/project.tblmanifest`、写 `project.toml`（@02 老结构迁移） |
| `projects/` 存在 | 列出所有子目录作为 project 全部加载；不再保留老 `config/`（迁移已完成） |
| 都不存在 | 弹「新建项目」对话框（@6.6），强制选模板创建首个 project |

### 2.1 交互

| 操作 | 效果 |

| 点击三角形 ▶/▼ | 展开/收拢组 或 展开/收拢 project 根 |

### 2.2 状态标记

| 标记 | 颜色 | 含义 |
|------|------|------|
| `+` | 绿 | 新建未保存 |
| `*` | 黄 | 已有文件被修改 |
| `-` | 红 | 标记删除，保存时生效 |
| `!` | 红 | 节点存在验证错误（详见 @5.4） |

组聚合子项：所有子项删除→`-`，有新建子项或自身新建→`+`，有修改子项→`*`。Project 根节点同样按聚合规则展示该 project 整体状态（聚合所有 group + 子节点）。

判断：
- 新建：`original` 为空
- 修改：序列化当前内容 ≠ `original`（"改回去"自动清除脏标记）
- 删除：`deleted = true`

### 2.3 功能区

TreeSection 标题栏下挂两条功能区：

#### 顶部功能区（项目级）

| 顺序 | 控件 | 用途 |
|------|------|------|
| 1 | 新建项目 | 弹「新建项目」对话框（@6.6），3 tab：空 / 从文件 / 从模板 |
| 2 | 排序下拉 | 项目顶层排序键：ID / 名称 / 已打开 / 创建时间 / 手动；会话内生效，未持久化 |

「已打开」排序：opened 在前、closed 在后；同态内回退到 ID 排序。「手动」预留拖拽排序入口（当前未实装）。

#### 过滤功能区（节点级）

| 顺序 | 控件 | 用途 |
|------|------|------|
| 1 | 搜索框 | 名称模糊匹配（实时过滤，placeholder「名称 / 拼音首字母」） |
| 2 | 过滤下拉 | 状态过滤：全部 / 改动 / 新增 / 修改 / 删除 |
| 3 | 完整组勾选 | 命中匹配组时显示该组所有未删子项（忽略 filter+search） |

closed project 不参与搜索 / 过滤匹配（@2.0），灰态展示在树里但不会被命中而隐藏。

#### 搜索匹配规则（`tablet_core::name_matches`）

query 与节点名都先 lowercase，任一命中即视作匹配；空 query 永远命中。

| 规则 | 例 | 命中 |
|------|------|------|
| 字面子串 | name = `HeroBase`，输 `hero` / `ero` / `Base` | ✓ |
| 拼音首字母子串 | name = `英雄表` → 派生 `yxb`，输 `yxb` / `YXB` / `xb` | ✓ |
| 中英文混合 | name = `HMM英雄表` → 派生 `hmmyxb`，输 `hmmyxb` / `mmyxb` / `yxb` | ✓ |
| 拼音全拼（不实现） | name = `英雄表`，输 `yingxiong` | ✗ |
| 字母不连续匹配 | name = `HeroBase`，输 `hb` | ✗ |

派生规则：每个汉字取该字 pinyin 首字符，非汉字（ASCII / emoji / 标点 / 空格）原样保留 + lowercase。两端前端共用同一份 `name_matches`。

#### 过滤下拉选项

| 选项 | 显示 |
|------|------|
| 全部 | 所有节点 |
| 改动 | 新增 + 修改 + 删除 |
| 新增 | 仅新建节点 |
| 修改 | 仅已修改节点 |
| 删除 | 仅标记删除节点 |

#### filter 与 search 的组合语义

filter 与 search 是**并行的 AND 条件**，不是先后管道——这点容易写错（只在原始集合做 OR 命中会丢子项）：

- 子项级显示 = `passes_filter(子项) ∧ name_matches(子项, search)`
- 组级显示 = `(组通过 filter ∧ name_matches(组名, search))` ∨ `(组内有任一子项级显示命中)`
- 组关闭时不展开子项；组展开时只列出"子项级显示"为真的子项
- 空 query 退化为纯 filter；filter = 全部 退化为纯 search

#### 完整组勾选

勾选后，**只要组本身被 filter+search 通道命中**，该组所有未删子项**忽略 filter 与 search 全部展开**——便于在过滤态下快速浏览整组上下文。仅过滤 `deleted`。

### 2.4 右键菜单

| 目标 | 菜单项 |
|------|--------|
| Project 根（opened） | 见 @2.0 「Project 根节点右键菜单」（17 项） |
| Project 根（closed） | 见 @2.0（4 项） |
| Group | 新建 Table（v3）/ 新建 Table（v2）、新建 Constant、新建 Enum、用 Excel 打开（整组 / 原文件）、复制 Group、粘贴节点、粘贴为 v3 / 粘贴为 v2（剪贴板是 Table 时出现，格式只是序列化方式，直接换算）、粘贴为 .tbl Group / 粘贴为 Excel Group、重命名、删除；**xlsx 组**另有「重新加载」 |
| Node | 校验规则...（常量不显示）、复制、粘贴节点、粘贴为 v3 / v2（剪贴板是 Table 时）、重命名、删除 |

**菜单项只在可用时出现**：菜单由 `MenuAction` 枚举 + `sections_for`（层级/顺序/分组）+ `entry`（可用性与文案）组合而成；不可用的项直接隐藏，不展示置灰项。例如剪贴板为空时不会出现任何「粘贴」项，剪贴板不是 Table 时没有「粘贴为 v3/v2」。

**命名输入框带示例**：新建 / 重命名的 InputDialog 在输入框下方给一行灰色示例，直接照着抄即可 ——
组名「例：hero；可用中文，如 战斗系统」，节点名「例：HeroBase（大写字母开头，只用英文、数字、下划线）」。

**跨 project 复制粘贴**：在 project A 的节点上右键复制 → 在 project B 任意节点上右键粘贴。节点名在项目内冲突时自动加 `_copy`；粘贴节点的自引用随之改写，指向 B project 不存在目标的引用按验证错误暴露。

## 3. GridArea（表格本体）

GridArea 是 GridSection 的核心子区域，承载固定表头 + 可滚动数据。三种 mode（Table / Constant / Enum）共用同一组渲染规则，差异在表头结构。

### 3.1 单元格类型系统（CellKind）

所有单元格统一抽象为 `CellKind`，决定交互行为：

| 类型 | 交互 | 用途 |
|------|------|------|
| ReadOnly | 不可编辑、深灰底 + 半灰文字、无 hover 高亮 | Constant/Enum 固定表头、Table id 列的 export/type/field 三格 |
| Text | 双击编辑 | 普通数据、表头 desc/field |
| TypeEnum | 单击弹出类型选择器（默认；可配） | Table 表头 type 行 |
| ExportEnum | 单击下拉（默认；可配） | Table 表头 export 行 |
| TypeEnumCol | 双击弹出类型选择器（默认；可配） | Constant type 列 |
| ExportEnumCol | 双击下拉（默认；可配） | Constant export 列 |
| Ref | 双击弹出引用选择器（默认；可配） | 列类型为 `@Xxx` 的数据格 |

**呼出方式可配（@4.2）**：picker 类单元格的单击 / 双击行为由 `[ui] picker_trigger_header` / `picker_trigger_data` 控制，表头与数据区独立。默认 header=single、data=double，让数据区单击始终是无副作用的"瞄准"动作（Ctrl+C/V 批量复制粘贴 ref id / enum 值的前提）。

ReadOnly 表头单元格的具体分布详见 @01.5.5；只读列不可删除/重命名（右键菜单中相应项禁用）。

数据格的下拉箭头（Ref / TypeEnumCol / ExportEnumCol）**只在有值或当前选中时显示**；
空占位行不画，避免每列重复 5 个倒三角。表头的 type/export 箭头不受影响，始终保留。

### 3.2 存储值 vs 展示值（重要约定）

单元格在 UI 模型层（`grid.data` / `HeaderCell.text`）**始终存「真实存储值」**——即写入 .tbl 文件的形式。渲染层在画的瞬间通过 `display_for_*` 转换为 UI 展示值。

| 列类型 | 存储值（grid.data） | 展示值（painter） |
|--------|----------------------|-------------------|
| ExportEnum / ExportEnumCol | `cs` / `c` / `s` / `-` | 前后端 / 客户端 / 服务器 / 不导出 |
| Ref（@EnumName + 开关开） | enum 条目 id（如 `1`） | 对应 entry.name（如 `WARRIOR`） |
| Ref（@TableName 或开关关） | 表/枚举 id | 同存储值 |
| 其它 | 原字符串 | 同存储值 |

由此自动得到的好处：
- **复制粘贴 round-trip**：剪贴板永远是 `cs` 而不是「前后端」，粘到别处直接落地
- **公式栏/编辑缓冲一致**：编辑态读 `grid.data` 直接拿到存储值
- **校验/序列化无歧义**：底层逻辑只看一种字符串

下拉编辑组件按同规则：`edit_buffer` 写存储值（点击「前后端」实际写 `cs`），渲染时再翻译。新增带「展示≠存储」的列类型时，**必须同时在 `display_for_cell` / `display_for_header` 增加分支**，不允许把展示值塞回 `grid.data`。

展示值还有一层「单行化」：固定单行的展示位（网格格 / 折叠公式栏 / 引用选择器）遇多行值只取首行、末尾补 `…`，见 @5.3。这同样只作用于展示串，不碰存储真值。

#### 展示与可编辑性是独立维度

ReadOnly 仅控制 **能否编辑、能否右键操作、是否显示下拉箭头**；它不影响 **展示规则**。最典型的例子是 Table 表头的 id 列 export 行：

| 维度 | 取值 |
|------|------|
| 存储值 | `cs` |
| kind | `ReadOnly`（id 列 export/type/field 三行不可改） |
| 展示值 | `前后端`（与其它 export 列一致） |

误区：曾经的实现里 `display_for_header` 仅匹配 `ExportEnum/ExportEnumCol` kind，导致 id 列虽然存的是 `cs` 但因为 kind 是 ReadOnly 被原样画出，与同行其它列「前后端」不一致。修法是按 **行位置**（Table 第二行就是 export 行）触发翻译，不依赖 kind。

#### 存储值边界

slint 是纯展示层，`HeaderCell.text` / `DataCell.text` 直接存展示值；存储真值由 `AppState.engine` 持有，Rust 的 `convert::build_grid` 在产出快照时翻译。复制 / 编辑 / 序列化等业务逻辑都从 `AppState.engine` 读写存储真值，不会从展示快照里取值。

### 3.3 Table 模式

```
┌────┬──────┬──────┬──────┬────────┐
│    │  A   │  B   │  C   │   D    │  ← 列字母行
├────┼──────┼──────┼──────┼────────┤
│    │英雄ID│ 名称 │ 血量 │ 技能组 │  ← desc (Text)
│    │前后端│前后端│服务器│ 前后端 │  ← export (ExportEnum)
│    │ int  │ str  │ int  │List<int>│ ← type (TypeEnum)
│    │ id   │ name │ hp   │ skills │  ← field (Text，id 列 ReadOnly)
╞════╪══════╪══════╪══════╪════════╡
│  1 │ 1001 │ 战士 │ 100  │ 1;2;3  │
│  2 │ 1002 │ 法师 │  80  │ 4;5    │
│  3 │      │      │      │        │  ← 扩展空行（自动追加 5 行）
└────┴──────┴──────┴──────┴────────┘
```

- 表头固定，不随数据滚动
- 数据行数 = 第一列（ID 列）非空的行数
- 扩展空行允许直接输入新增数据
- ID 列字段名固定 `id`，不可编辑/不可删除（见 @01.5.2）

### 3.4 Constant 模式

```
┌────┬──────────┬───────────┬───────┬──────┬──────────┐
│    │  A       │  B        │  C    │  D   │  E       │
├────┼──────────┼───────────┼───────┼──────┼──────────┤
│    │ name     │ type      │ value │export│ desc     │  ← 固定表头 (ReadOnly)
╞════╪══════════╪═══════════╪═══════╪══════╪══════════╡
│  1 │max_level │ int▾      │ 100   │前后端▾│最大等级 │
│  2 │start_pos │Tuple2…▾   │ 5,10  │前后端▾│出生坐标 │
└────┴──────────┴───────────┴───────┴──────┴──────────┘
```

列定义：name (Text) / type (TypeEnumCol) / value (Text) / export (ExportEnumCol) / desc (Text)。

### 3.5 Enum 模式

```
┌────┬──────┬──────────┬──────────┐
│    │  A   │  B       │  C       │
├────┼──────┼──────────┼──────────┤
│    │  id  │ name     │ desc     │  ← 固定表头 (ReadOnly)
╞════╪══════╪══════════╪══════════╡
│  1 │  1   │ WARRIOR  │ 战士     │
│  2 │  2   │ MAGE     │ 法师     │
│  3 │  3   │ ARCHER   │ 弓手     │
└────┴──────┴──────────┴──────────┘
```

列定义：id (Text) / name (Text) / desc (Text)。

### 3.6 列宽（自适应 + 手动调节）

列宽是**视图状态**，不是业务数据；不写 `.tbl` / `project.toml` / `tablet.toml`。

- **默认自适应**：节点打开时按表头（Table 4 行 / Constant、Enum 1 行）+ 数据抽样估算，
  最小 60px、最大 480px；CJK 按全角、ASCII 按约 0.62em 估，留 8% 余量。
  枚举 `name` 这类列默认就能完整显示。
- **手动拖宽**：拖动列字母行右边界；拖动后该节点切到手动模式（「自动列宽」自动取消），
  手动范围 40–800px。
- **双击边界**：**手动调整的快捷操作**——只把该列按内容设成手动宽度，不重算/不修改
  自动宽度；自动模式下会切到手动（其它列保持当前宽度），与拖动一致。
- **「自动列宽」**（GridHeaderBar 右侧勾选，按当前节点记忆）：
  - 勾选 = 使用自动宽度；取消 = 使用手动宽度；
  - **自动数据和手动数据是两套独立数据**：手动操作永不修改自动值，勾选自动时忽略
    手动值，取消勾选时使用手动值（没有手动宽度时取消不生效，保持勾选）；
  - 只有真实变化才写入，**不触发 dirty / 保存闸门 / 校验**。
- 列宽按**列名**记录：插入/删除/重排列不丢；改名后退回自适应。
  自动宽度在节点切换、「显示引用名称」/被引用展示列变化、列集合变化时重算；
  同一节点内编辑数据不重算（避免列跳动），需要重算时双击列边界把该列设成手动宽度。

**持久化**：`.data/user-data.json` 的根结构 `UserData.ui.grid`（本机、被 `.gitignore`
忽略、独立保存通道，见 @03.6.2）；换 checkout 不共享，换机器/重新 clone 不带过去。

### 4.1 选中

| 操作 | 结果 | 视觉 |
|------|------|------|
| 单击单元格 | 选中单格 | 浅蓝背景 + 蓝边框 |
| 单击行号 | 选中整行 | 整行浅蓝 |
| 单击列字母 | 选中整列 | 整列浅蓝（含表头） |
| 拖动单元格 | 选中矩形区 | 区域浅蓝 |
| 拖动行号 | 选中多行 | 多行浅蓝 |

### 4.2 编辑触发

picker 单元格（TypeEnum / ExportEnum / TypeEnumCol / ExportEnumCol / Ref）的呼出方式由 `[ui]` 两个独立旋钮控制（@03.4.10）：
- `picker_trigger_header` —— 表头 picker（Table type / export 行）：默认 `single`
- `picker_trigger_data` —— 数据区 picker（Ref 列 / Constant type / export 列）：默认 `double`

Text 单元格永远是双击进 LineEdit；ReadOnly 永远不可编辑。

| 操作 | 默认行为 | 说明 |
|------|---------|------|
| 单击 Text / picker 单元格（任意区域） | 选中 | 进入选区，可 Ctrl+C/V |
| 双击 Text 单元格 | 文本编辑框 | Enter 确认 / Esc 取消 |
| 单击表头 picker（默认 single） | 直接弹 | type 行弹类型选择器、export 行弹下拉 |
| 双击数据区 picker（默认 double） | 弹 picker | export 列弹下拉、type 列弹类型选择器、Ref 列弹引用选择器 |
| 公式栏输入 | Text 单元格选中后 | Enter 提交 |

**为什么数据区默认 double？** 早期版本数据区单击立即弹 picker，**没法选中 ref / enum cell**——选中之后才能 Ctrl+C/V 批量复制粘贴 ref id / enum 值。改 double 后单击稳定为"瞄准选中"。

**为什么表头默认 single？** 表头每列 type / export 各一格，几乎不需要批量改、也很少需要"先选中一片表头再操作"，single 直接弹少一次点击。

切到反向模式后体感会变：例如数据区设 `single` 后，单击 ref cell 直接弹 RefPicker，要批量复制就只能先 Esc 关弹窗再瞄准。两个旋钮独立可调，按口味来。

### 4.3 编辑保存策略

由 `[ui] auto_commit_on_blur` 控制（见 @03.4.10）：

| 配置 | Enter | 点击空白 / 其它单元格 |
|------|-------|------------------------|
| true（默认） | 保存 | 自动保存 |
| false | 保存 | 丢弃编辑 |

无论配置如何：Enter 始终保存，Esc 始终取消。

## 5. 全局与表格区组件

界面有 5 处条形子区域。**Toolbar 与 LogPanel 是顶层全局**，**GridHeaderBar / GridRibbon / FormulaBar / StatusBar 是 GridSection 内部子区域**（与 GridArea 等宽，跟随表格大区）。

### 5.1 Toolbar（顶部全局工具栏）

```
[撤销] [重做] │ [保存] [重新加载]  当前项目：SLG 测试 ●
```

按钮按「会话历史 / 项目动作」分组；按钮组后方的 `当前项目` 是撤销、重做、保存共同的**命令目标**（docs/12 §4）。

| 按钮 | 行为 |
|------|------|
| 撤销 | 撤销 active Project 的上一步；无 active 或栈空时禁用 |
| 重做 | 重做 active Project 的下一步；无 active 或栈空时禁用 |
| 保存 | 保存 **active Project**（不是全部）；成功后清空该项目的撤销/重做；无 active 时禁用 |
| 重新加载 | 重扫 `projects/` 重读全部 .tbl；有未保存改动先弹确认，确认后清空全部撤销历史 |

- **当前项目标签**：显示树当前口径（`[ui] show_meta_id` 决定 id/name），无 active 时显示 `当前项目：—`；有未保存改动时末尾亮 `●`。
- 撤销/重做是**项目级**命令，不放 GridRibbon；树上的 `⭐` 继续作为 active 的空间提示。
- 「保存全部」不再占主按钮区；如需要，后续放到 `文件` 菜单，逐项目保存并逐项目清栈。
- 快捷键：`Ctrl+Z` 撤销、`Ctrl+Y` / `Ctrl+Shift+Z` 重做、`Ctrl+S` 保存；正在文本编辑时 `Ctrl+Z` 仍归文本框自己。
- 点击 Toolbar 按钮会先提交当前单元格编辑，再执行命令；因此点「撤销」可以撤掉刚刚提交的那一步。

旧版工具栏的其它入口已经按"作用域"下沉到对应位置：

| 导出 / 导出 Schema / 合并 Schema | Project 根右键菜单（@2.0） |

### 5.2 GridRibbon（表级功能 bar）

GridSection 第二条子区域，类似 Excel 工具栏下面那条「字体/对齐/换行」选项条：放视图开关 + 表级动作按钮，仅影响渲染或当前节点。归属表格大区，宽度跟随 GridArea。

```
┌───────────────────────────────────────────────────────────────┐
│ [还原] [Excel 编辑] [校验规则]  [☑] 显示引用名称  被引用展示列: [ID ▼] │
└───────────────────────────────────────────────────────────────┘
```

#### 当前控件

| 控件 | 类型 | 作用 | 默认 | 启用条件 |
|------|------|------|------|----------|
| 还原 | 按钮 | 把当前选中的节点恢复成**盘上的样子**（`records` / `schema.fields` / `name` / `display_field`），见 @02.26.4。**还原本身也是一步可撤销操作**（docs/12） | — | 选中节点 + 盘上确实有它 + 它现在和盘上不一样（新建未保存的节点置灰） |
| Excel 编辑 | 按钮 | `.tbl` 组：调起系统 Excel 打开当前节点的临时副本，关闭后自动回填；**工作簿组**：先落盘再用 Excel 打开原工作簿（详见 @06 / @02.26.8） | — | 选中叶节点；工作簿组不受「已有 Excel 会话」限制 |
| 校验规则 | 按钮 | 打开节点级「校验规则」面板（@6.10 / @01.10.7）：增删规则、调整优先级、设置级别 | — | 选中 Table / Enum（常量不支持，@01.8.8） |
| 显示引用名称 | 勾选框 | 视图**总闸**（@10）：勾上时，`@EnumName` / `@TableName` 引用列按**目标节点的「被引用展示列」**渲染；不勾一律显示存储的 id | 关 | 仅当选中 Table / Constant 时启用（Enum 没有引用列） |
| 被引用展示列 | 下拉框 | 设当前**表 / 枚举节点**被引用时的展示列（@10）。表选项 = `ID` + `str`/`int`/`txt` 字段；枚举选项 = `name`/`desc` | 表：`ID`；枚举：`name` | 仅当选中 Table / Enum 时启用 |

> 「显示引用名称」是全局视图总闸，会话内状态、不持久化；「被引用展示列」是节点自身属性，写进 `project.tblmanifest`（@10.4）。二者是**总闸 × 节点设定**：设了节点的被引用展示列，还需勾上总闸才生效。

#### 引用类型分类

`@xxx` 是 type 系统的子类型，按被引用对象分两类，**两类都支持"被引用展示列"**（@10）：

| 类型 | 形如 | 被引用展示列来源 |
|------|------|-----------|
| 枚举引用 | `@HeroType`（指向 Enum 节点） | 目标的 `name` / `desc`；**未设默认 `name`** |
| 表引用 | `@HeroBase`（指向 Table 节点主键 id） | 目标 str/int/txt 叶子列（如 `name` / `title`）；未设默认原始 id |

被引用展示列缺失（列不存在 / 类型不合格 / 该格为空）时回落显示原始 id。

#### 不影响范围（即便勾上也不变）

- 内置导出枚举（前后端 / 客户端 / 服务器 / 不导出）——这些走 ExportEnum 渲染规则，与本总闸无关
- 编辑场景（公式栏 / 双击编辑 / 引用选择器内）——始终是 id，避免"看到名字、改的是 id"的割裂
- Constant 的 `value` 列走同一条 `@X` 引用渲染路径（与 Table 引用数据格一致）

> 总闸状态全局保留一份（不绑定到节点），切回节点时维持上次勾选状态。Constant / Enum 选中时禁用总闸是因为它们没有"引用数据列"，勾上也观察不到视觉变化。

### 5.3 FormulaBar（公式栏）

GridSection 第三条子区域，单元格内置编辑组件的「长内容辅助查看 + 编辑」延伸。**仅在选中单元格时显示**；未选中时整条收起为 0 高度。

- 左：Excel Name Box 风格的选区地址。单格 `B3`；区域 `A1:C1`；整列 `A:A`；整行 `1:1`。区域 / 整行 / 整列时内容区为空、强制折叠，避免保留上一格的 raw 内容和展开高度。
- 右：根据单元格类型决定行为

| 单元格类型 | 公式栏行为 |
|-----------|-----------|
| Text | 可编辑，缓冲 = 真实存储值；折叠态 Enter / 失焦提交 |
| ExportEnum / ExportEnumCol | 只读 + 🔒 提示，展示底层 raw（`cs` / `c` / `s` / `-`，**不是**翻译后的"前后端"）。编辑走单元格下拉 |
| TypeEnum / TypeEnumCol | 只读 + 🔒，展示类型字符串。编辑走类型选择器弹窗 |
| Ref | 只读 + 🔒，展示底层 id（**不受**「显示引用名称」总闸影响）。编辑走引用选择弹窗 |
| 表头单元格（desc/export/type/field 行） | 公式栏不参与，编辑由表头自身的双击/下拉处理 |

picker / ReadOnly 列只读 + 显示底层 raw 是为了：
1. 对齐 Excel 心智模型 —— 单元格展示翻译值，公式栏永远是底层真值
2. 关掉 picker 校验旁路 —— 早期版本对 picker cell 公式栏可编辑，能直接打字塞入非法值（不存在的 ref id、非法 export 短码）；只读后只能走 picker 弹窗，校验保证写入合法
3. 视觉上用淡色文字 + 🔒 暗示 "不可改"，避免误以为 Text 但点不动

设计目的：解决 Text 单元格内容过长被截断（picker 列内容本身短，无此需求）。

#### 展开态（多行编辑）

公式栏最右有展开箭头（`▶` / `▼`），默认折叠为单行 22px，展开后高度变 `Theme.formula-expanded-h`：

| 操作 | 行为 |
|------|------|
| 点 `▶` 展开 | 高度变大，内容换成多行 `TextEdit`（自动换行 + 滚动条）；Text 列同时进入编辑态 |
| 展开态 Enter | **插入换行**（不是提交）——展开态的语义就是多行编辑 |
| 点 `▼` 收起 | 先提交再折叠 |
| 点区域外（失焦） | 提交（受 `[ui] auto_commit_on_blur` 约束，@4.3） |

展开态内容 = **存储真值原样**（`formula_raw`），tab / 换行 / 引号都不动，从 CSV / Excel / JSON 复制进来的文本原样保留；复制出去同样原样。折叠态则显示单行化的展示值（见下）。`expanded` 只是 UI 局部状态，session 内记忆、不落盘。

#### 单行化展示（重要）

单元格值**允许**含换行（`txt` 列合法、Excel 导入会带 Alt+Enter，@01）。但网格行高固定 22px、折叠公式栏也是单行盒子，而 slint 的 `Text` 即使 `wrap: no-wrap` 也会在 `\n` 处强制断行，且 1.17 没有 `maximum-line-count` —— 原样输出会让一个 40 行的值画到格子外面，**糊掉整块表格**。

所以凡是固定单行的展示位，一律先过 `convert::util::one_line`：遇 `\r\n` / `\r` / `\n` 时只取**第一行**、末尾补 `…`。覆盖网格数据格、表头格、折叠公式栏、引用选择器的 id/辅助列。

不用 `⏎` 之类的换行标记字符，是因为字形不一定在字体回退链里（实测 `⏎` U+23CE 与 `▾` U+25BE 在本机都渲染成豆腐块），而 `…` 正是 slint `overflow: elide` 自己在画的字符，一定有。

**只影响展示**：编辑缓冲、复制、保存、校验全部读 `AppState.engine` 的存储真值，换行不会被改写（@3.2）。展开态公式栏显示真实换行。

另外两处兜底：公式栏和网格单元格都加了 `clip: true`，保证编辑框里再长的内容也不会画到栏 / 格外面。

### 5.4 验证错误展示

数据通过 cell→row→schema→table→project 五层验证（@01.8、@01 附录 A），UI 上的错误反馈分散在多个区域：

| 位置 | 表现 |
|------|------|
| GridArea 数据单元格 | 红色边框（1.5px） |
| GridArea 表头单元格 | 红色边框（1.5px），按 `ValidationError.header_row` 归到对应行（type 行 / field 行） |
| StatusBar | 选中单格且该格有错误时，坐标后追加 `⚠ 错误原因`；只有警告时追加 `警告：原因`（不带红框） |
| TreeSection 节点 | 状态标记后追加红色 `!` |
| TreeSection 组节点 | 子项有错误时同样追加 `!`（聚合） |
| LogPanel | 加载、保存失败时输出具体错误位置 + 错误信息（@01.附录A.5 格式） |

**错误与警告分开**（@01.10.7 的 `severity`）：红框、树上 `!`、保存闸门只表达 **error**；**warning** 只出现在 StatusBar、LogPanel（`[警告]` 前缀）与工具栏计数（`N 错误 / M 警告`）里。同一格可以同时命中错误与警告：状态栏优先显示错误，没有错误才显示警告。

加载项目时即触发一次 `revalidate_all`，红框/`!` 在打开就可见，不依赖用户先编辑触发；reload / 生成测试 / 清空 后同样会重新跑全表验证。

实时验证开关 `[ui] realtime_validate` 见 @03.4.10.2。

**联动刷新**：改一个节点的数据后，依赖它的节点（`@本节点` 引用、`ref_exists(本节点.列)`）会被连带重算，不需要等保存或全量验证（@01.8.10）。

GridSection 最末子区域，显示当前选中状态。归属表格大区，与 GridArea 等宽。

| 选中类型 | 显示 |
|---------|------|
| 单格 | `B3` |
| 矩形区 | `B2:D5 (4行×3列，共12格)`；公式栏左边同步显示 `B2:D5` |
| 单行 | `第3行` |

### 5.6 LogPanel（底部全局日志）

顶层第三大区，独立于表格区。带「日志」标题栏 + 可滚动列表区，记录加载 / 保存 / 验证 / 导出等操作输出。

每条日志带级别与时间：

| 级别 | 颜色 | 用途 |
|---|---|---|
| Info | 次要文字色 | 正常操作：加载 / 保存 / 导出成功 |
| Warn | 黄色 | 未阻断的告警：外部文件变化、验证警告、跳过项 |
| Error | 红色 | 保存失败、导出失败、解析失败、被阻断的操作 |

日志栏左侧提供过滤：**全部 / Info / Warn / Error**，右侧显示各级别数量。
用户只想看 `Error` / `Warn` 时不会在大量 Info 里翻找。日志按时间倒序，最新在最上方。
每条日志固定单行（18px），超长内容省略，避免长错误把面板撑高。
日志面板高度可拖拽。

## 6. 弹窗组件

### 6.1 模态规则

所有弹窗（类型选择器、引用值选择器、导出对话框、Schema 导入导出、删除确认、命名输入等）遵循 Windows 常规模态规则：

- 弹窗显示时父级 UI 被半透明遮罩盖住，遮罩拦截所有鼠标点击（即父级不可点）
- 多层弹窗时只有最顶层可操作；子弹窗关闭后才能回到父级弹窗，以此类推
- 退出方式：点击「确定 / 取消 / 关闭」按钮，或点击窗口外的遮罩区域（等同取消）
- **例外：项目设置对话框没有「取消」**（@6.7）。它是「直接编辑 + 跟上次保存比」的范式，
  编辑实时落内存、关闭即保留，反悔靠字段上的还原按钮；点遮罩 = 确定。

按钮排布统一约定（Windows 习惯）：

- 一律**右下角**对齐
- 顺序固定（视觉左→右）：**辅助按钮 → 主操作 → 取消**
  - 例：`[清空] [确定] [取消]`、`[导出] [取消]`、`[导入] [取消]`
- **取消始终在最右**，主操作（确定/导出/导入...）紧邻其左，对齐 Windows 系统对话框习惯
- 实现：通过 `modal::dialog_buttons` 封装 `right_to_left` 布局；行宽用 `ui.min_rect().width()` 撑满已布局的内容宽度（不能用 `available_width()`，在 `Window::resizable(false)` 下值不准确，会导致按钮贴左）

`List<@X>` / `Set<@X>` 列单元格打开的是多选：单击行勾选/取消（可多行），行高亮显示勾选态，底部预览显示「已选 N 项: id;id...」；「确定」把勾选 id 按项目 List 分隔符拼成列表写回。「当前值」输入框仍可直接手输 id 列表，手动输入会同步刷新行勾选态。

#### Table 列展示策略

通过 `[ui.ref_picker] default_strategy` 配置默认值，弹窗内可临时切换（每次重开恢复配置默认）：

| 策略 | 名称 | 规则 |
|------|------|------|
| `auto` | 智能 | id + 最多 2 个辅助列；跳过 export = `-`、类型以 `@` 开头的引用列、类型含 `<` 的复合列 |
| `full` | 全部 | id + 所有 export ≠ `-` 的字段 |

> 列数多时弹窗内表格出现水平滚动；表头随数据水平滚动同步。

#### 表头双行（desc + field）

- field 行渲染英文字段名（id / name / hp / ...）
- desc 行渲染对应中文说明，从 schema `desc` 取
- 任一辅助列 desc 全为空时只渲染 field 一行（避免空行浪费）
- Enum 引用没有 schema desc，desc 行硬编码 "ID / 名称 / 描述"

#### 交互

- **当前值**：顶部输入框，与列表选中双向同步；允许直接手输任意值（不要求命中列表），确认时优先以此为准
- **搜索**：模糊匹配 id 或任一辅助列；命中"id 子串 ∨ 任一 extras 子串"
- 整行可点选中，hover 高亮；双击行 = 确定
- 列分隔与行底渲染网格线，便于对齐阅读
- [清空] 把单元格置空（视作未引用）
- 引用值为空时单元格视觉淡灰
- 引用目标不存在时弹窗顶部展示警告条；确定按钮仍允许提交（手动输入合法）

#### 数据范式：直接编辑 + 跟上次保存比

**没有 apply buffer、没有快照、没有修改标记，也没有「取消」。** 对话框直接编辑内存里的 `Project`；「这个字段和盘上不一样吗」由 `Project::original_meta` / `original_separators` / `original_export` 回答（@02.26.2）——和树上的分层脏同一个道理：**脏是算出来的**。

| 动作 | 行为 |
|---|---|
| 编辑任意字段 | 直接落内存的 `Project`；**只该字段**变淡蓝底 + 出现右侧还原按钮 |
| 改回原值 | 蓝色与按钮**自动消失**（不需要在编辑路径上补任何一笔） |
| 点字段的 ↺ | 把 `original_*` 的对应叶子写回 |
| `[全部还原]` | `meta` + `separators` + `[export]` 整体回到上次保存；仅当三块真的偏离盘上时才可用 |
| `[应用模板]` | 把**全局配置**的 separators / export 灌进来。与「还原」不是一回事：还原的目标是上次保存值，套用的目标是全局值 |
| `[确定]` / 点遮罩 | 关闭 |

**还原按钮的宽度常驻**（不亮时只藏 `opacity`），否则每敲一个字整行都会左右跳一下。

**提交点是「保存项目」，不是「确定」**（@02.26.3）。所以改完直接关窗 = 接受改动（树上亮 🟡）；要反悔就点字段上的 ↺ 或 `[全部还原]`。这些还原动作同样走项目级历史记录，关窗后仍可用 Toolbar 撤销/重做（docs/12）。

**高亮的参照物是「上次保存时」，不是「打开对话框时」。** 所以改完没保存、关掉、再打开，那些字段**仍然是蓝的**；`[全部还原]` 也会一并丢掉打开对话框**之前**的未保存改动。这是设计要的效果。

`[全部还原]` 只管 `meta` / `separators` / `[export]`（`Project::settings_changed()`），**刻意不含数据改动**——它还原不了数据，就不该为数据改动亮起来。

#### tab 3：校验策略（@01.10.7）

照 EDA 的 DRC 思路：**级别只表达「多严重」，要不要拦保存是策略**。三个级别各给一个动作：

| 动作 | 红框 / 树上 `!` | 日志 / 状态栏 | 阻断保存 |
|------|----------------|--------------|----------|
| 阻断保存 | ✅ | ✅ | ✅ |
| 仅提示 | — | ✅ | — |
| 忽略 | — | — | — |

默认：error = 阻断保存，warning = 仅提示，info = 忽略。改动直接落内存的 `Project.config.validate`，与其它设置一样**保存项目时**写进 `project.toml` 的 `[validate]`；文件是完整配置，默认策略也显式落盘。

#### tab 0 身份

| 字段 | 说明 |
|------|------|
| 项目 ID | **只读**（显示为 🔒 + id）。id 在「新建项目」/「复制(克隆)」对话框里定；之后改 id 要搬目录、风险大，不在这里开 |
| 项目名 / category / version | 落 `schema.meta`，随「保存项目」写进 .tblschema |

#### tab 1 分隔符

25 个分隔符 leaf 的 LineEdit，按「基础」/ `Map` / `List<TupleN>` / `Map_TupleN` / `Map_List` 分组排版（详细规则见 @01.10）。

| 操作 | 行为 |
|------|------|

**分隔符重校验挪到关闭时**，不是每次按键——对话框是模态的，背后的 grid 没人看。用一个 `sep_touched` 会话标记把守（凡写过 `schema.separators` 就置位），关闭时统一跑一次 `revalidate_all`。

**不能改成「关闭时 `separators != original_separators` 才校验」**：会话 1 把 A 改成 B 并关闭（错误按 B 重算），会话 2 把 B 还原成 A 再关闭——此时两者相等，等式守卫会跳过重校验，而 `validation_errors` 里留的还是按 B 算的。标记是粘的，所以那个序列会被正确重算。

#### 与项目设置的三处不对称（都是有意的，@02.26.6）

1. **参照物是「打开对话框那一刻的 tablet.toml」，不是住在数据结构上的 `original_*`。**
   因为「确定」**就是**写盘点，「内存 ≠ 盘上」的窗口恰好只有对话框开着的时候——
   关掉就没有「不一致」需要留存，所以那边的还原天然只在会话内有意义。
2. **保留「取消」。** 项目设置去掉它是因为「关闭 ≠ 提交」（提交点是「保存」）；
   这里「确定」就是落盘点，去掉取消等于**关窗即改工作区配置**——工作区级、立即生效，
   分隔符还会触发全项目重校验，这个副作用比项目设置重得多。
   因此**也不做页面级「全部还原」**：取消已经是它了，区别只是关不关窗。
3. **编辑缓冲保留。** 项目设置那边我们把 buffer 删了（直接编辑 `Project`）；这里不行——
   `engine.global_config` 是活的工作区状态，别的东西会读它，它的 `project_management`
   段自己还会变。

#### 字段级高亮与还原

与 @6.7 一样：`**-modified` 由后端算好推上来（**按 tab 分块比**，见 @02.26.6），改过的字段
淡蓝底 + 右侧还原按钮；点它把快照里的对应叶子写回编辑缓冲。

|---|---|---|
| UI 设置 | 8 个（4 布尔 / 4 下拉） | `UiKey` |
| 分隔符 | 25 个 leaf | `SepKey`（与 `project.tblmanifest` 的 `# @sep` 同一套） |
| 导出设置 | 29 个 leaf | `ExportKey`（与项目设置那份**同一个**） |

`[使用默认值]` 把当前 tab 填成**硬编码默认值**（不是快照值）——它和「还原」不是一回事。

#### 写盘

### 6.10 校验规则面板

节点级校验规则的编辑入口（@01.10.7），模态对话框，940 × 680。入口两处：GridRibbon 的「校验规则」按钮、树节点右键菜单「校验规则…」（仅 Table / Enum；常量不支持，@01.8.8）。**不在列上挂右键**。

交互采用**列优先的 master-detail**：先选列，再看/改这一列的规则。规则本来就是列的属性，平铺列表既表达不了「这一列有几条」，也看不出优先级。

```
┌ 校验规则 — error/ErrorCode  (Enum) ────────────────────────────────────── ✕ ┐
│ 先选列，再为这一列添加规则。同一列内按从上到下的顺序执行与报告；级别决定是否阻断保存。│
│ ┌ 列 ──────────┐ ┌ 列 "name" · 文本 ─────────────────────────────────────┐ │
│ │ id   系统唯一 │ │ 规则（优先级从上到下）        [+ 添加规则][删除][上移][下移]│ │
│ │ name    2 条 │ │ ┌───────────────────────────────────────────────────┐ │ │
│ │ desc         │ │ │ 1  ref_exists(Lang.key)                    警告    │ │ │
│ │              │ │ │ 2  unique()                                错误    │ │ │
│ │              │ │ └───────────────────────────────────────────────────┘ │ │
│ │              │ │ 编辑选中规则                                        │ │ │
│ │              │ │   类型: [ref_exists(节点.列) ▼]   级别: [警告 ▼]    │ │ │
│ │              │ │   目标: [Lang ▼] . [key ▼]                          │ │ │
│ │              │ │   本列每个非空值都必须出现在目标节点的目标列中…      │ │ │
│ └──────────────┘ └─────────────────────────────────────────────────────┘ │
│ 本节点校验结果                    错误 0 · 警告 2                          │
│   [警告] error/ErrorCode B3:[FOO] -> 引用值 FOO 不存在于 Lang.key          │
│                                                     [确定]    [取消]       │
└────────────────────────────────────────────────────────────────────────────┘
```

#### 区域

| 区域 | 内容 |
|------|------|
| 左：列清单 | 节点的全部列。徽标：`N 条`（该列规则数）/ `系统唯一`（id、enum name 等）/ `不支持规则`（复合类型，置灰不可选） |
| 右：规则列表 | **只显示选中列**的规则。系统内置规则（@01.8.11）以灰色「系统」标在前面，不可选中、不可删除、不可调序；用户规则在后，行序即该列内的优先级 |
| 右：编辑器 | 选中规则的「类型 / 级别 / 参数」；类型下拉只列该列**适用**的验证器，切换类型时参数区与说明随之变化。参数按验证器显示：`ref_exists` = 目标节点/列；`range`/`len` = 下限/上限；`one_of` = 候选值；`matches` = 正则；`required_if` = 条件列 + 值；`compare` = 比较列 + 运算符 |
| 底部 | 本节点全部错误与警告（`[验证]` / `[警告]`），顶部给 `错误 N · 警告 M` |

#### 类型约束（UI 直接不给非法组合）

| 列类型 | `unique()` | `ref_exists()` |
|--------|-----------|----------------|
| `int` / `long` / `float` / `bool` / `str` / `txt` | ✅ | ✅ |
| `@Xxx` 引用列（值为 id） | ✅ | ✅ |
| `List<>` / `Set<>` / `Map<>` / `Tuple*` / `MapList` | ❌ | ❌ |

- 目标节点只列出**至少有一张标量列**的 Table / Enum；目标列只列出标量列。
- 手写 schema 里把规则挂到复数类型列上 → 校验层报 `RuleTypeIncompatible`（级别取规则自己的级别）。

#### 行为

- 打开时对**当前选中节点**取规则；右键菜单打开时按被右键的节点。默认落在第一张支持规则的列上，并选中该列的第一条规则。
- 编辑**实时生效**：每次改动写回节点并重跑该节点校验，结果区同步刷新。「取消」用打开时的快照还原。
- 「+ 添加规则」在列尾追加一条规则并选中：系统已保证唯一的列默认给 `ref_exists`，其余给 `unique()`。
- 上移 / 下移只与**同列**的相邻规则交换，不影响其它列的相对顺序。
- `ref_exists` 未选全目标时「确定」置灰。
- 字段改名会同步改写本表规则里的列名。

## 7. 保存机制

### 7.1 延迟写盘

所有创建/修改/删除操作只改内存，不立即落盘：
- 新建 Group/Table/Constant/Enum → 内存创建，标记 `is_new` / `dirty`
- 编辑数据 → 改内存，序列化对比自动计算 dirty
- 删除 → 标记 `deleted`，节点仍在树中显示（带 `-`）
- 复制 → 内存复制，标记新建

### 7.2 保存按钮

点击保存时统一处理：
1. 新建组 → `create_dir_all`
2. dirty 节点 → 序列化写 .tbl
3. deleted 节点 → 删除 .tbl 文件，从内存移除
4. 空组 → 删除目录

未保存关闭程序 = 丢弃所有修改。

### 7.3 进程锁

同目录下的 `.data/tablet.lock` 防止多实例编辑同一项目。启动时检查 PID 是否存活。

## 8. 行颜色标记展示

数据行带 `#@c:RRGGBB` 标记时，UI 表格中该行显示对应背景色（详见 @01.9）：

- 仅展示，不提供标色入口（标色在 Excel 中完成）
- 行号列同步显示颜色，便于快速识别

## 9. 退出提示（规划中）

未保存修改时退出 → 弹出确认（保存 / 放弃 / 取消）。

### 10.1 已使用

| 符号 | 用途 |
|------|------|
| 📁 | Group 文件夹（`.tbl` 组） |
| 📗 | Group 工作簿（`.xlsx` 组，节点 = sheet，@02.26.8） |
| 📊 | Table |

| 🔢 | Enum |
| ▶ ▼ | 树展开箭头 |
| ☑ ☐ ▣ | 复选框（含半选） |
| ✅ ⚠️ | 状态（新增 / 已存在覆盖） |

#### 字形常量类（字面量只写一处）

**所有字形字面量集中在 `crates/app-slint/src/icons.rs`**，分两层：

1. **`G_*` 原始字形** —— 每个字面量在整个 crate 只出现一次。
2. **语义常量** —— 允许**多个语义指向同一个原始字形**。典型例子：树节点的展开三角
   （`TRI_EXPANDED`）与单元格右上角的下拉箭头（`DROPDOWN_ARROW`）都是 `▼`，
   两者都写 `= G_TRI_DOWN`。换字形只改第 1 层一处，所有别名自动跟着走。
   复合标签（`📊 表引用`）走函数 `ref_label_table()`，前缀字形同样取自 `G_TABLE`，
   不重抄字面量。

`.slint` 侧不能 import rust 常量，所以约定：**字面量只在 icons.rs 写**，启动时
`icons::wire()` 一次性推给 `ui/icons.slint` 的 `global Icons`，`.slint` 里只写
`Icons.xxx`。新增字形三步：① icons.rs 加 `G_*` + 语义别名 → ② icons.slint 加同名
kebab-case 属性 → ③ `wire()` 里推一次。漏 ② 编译不过；**漏 ③ 不会编译失败，只是值
永远是空串**（图标不显示），所以有一条测试直接读两份源码比对来兜住这个接缝。

⚠️ `app.slint` 必须 `import { Icons }` + `export { Icons }` —— 只在被 import 的文件里
`export global` 是不够的，入口文件不 re-export 的话 Rust 侧根本拿不到 `crate::Icons` 类型。

**刻意不进常量类的**：
- `@preview` 组件里的 mock 数据（`icon: "📁"`、`grid-title: "📊 hero / HeroBase"`）——
  preview 是独立的静态渲染，不跑 `wire()`，接了 Icons 反而会渲染成空。运行时这些值全部
  被 Rust push 覆盖。
- Rust 日志 / 提示文案里的 `→ ← × ·`——它们是散在散文里的排版标点，不是图标。
  这四个都在 WGL4 里，跨平台安全。

**状态**：❌ ❗ ✔️ ⏳ 🔄 🚫

**操作**：➕ ➖ ✏️ 🔍 💾 📥 📤 🗑️ 📎

**标记**：🟢 🟡 🔴 ⬤ ○ ● ◆ ◇ ★ ☆

**结构**：📄 📂 🏷️ 🔗 📐 ⚙️

### 10.3 渲染说明

- slint 走系统字体 fallback 链，需要确保链中含 emoji 字体（Windows / macOS 默认即可，Linux 桌面通常需要 `fonts-noto-color-emoji` 之类）
- 组合符号（如 ⚠️ = U+26A0 + U+FE0F）在某些字体下可能显示为文本样式
- 单色符号（▶▼☑☐▣●○）渲染最稳定，不依赖彩色 emoji 表
- 彩色 emoji 在 Windows / macOS 表现一致

#### 实测踩过的坑（2026-10-14，Windows 11 默认字体链）

选新符号前先别凭直觉挑，以下是本机实测**渲染成豆腐块**的：

| 符号 | 码位 | 结论 |
|------|------|------|
| ⏎ | U+23CE RETURN SYMBOL | 方块，全线不可用 |
| ▾ ▸ | U+25BE / U+25B8 小三角变体 | 方块；同族的 ▼▶（U+25BC/U+25B6，WGL4 覆盖）正常 |

**一般规律**：`▶▼◀▲●○■□`（U+25A0–25FF 里 WGL4 覆盖的那批）稳；几何图形区的「尖角/小号变体」（U+25B8、U+25BE、U+25B9…）不一定有。`…`（U+2026 省略号）安全 —— 它在 WGL4 里，而且 slint 的 `overflow: elide` 自己就在画它，所以任何能正常 elide 的环境都一定有这个字形。这也是 @5.3 单行化用「首行 + `…`」而不是插换行标记字符的原因。

**当前彩色 emoji 用量**（`📊`24 `📁`13 `🔢`13 `📋`9 `📦`3 `🔒`3 等，共 40+ 处）是已知的跨平台风险点：Linux 桌面不装 emoji 字体就是一片方块。要彻底摆脱，得把这批换成单色符号或纯文字——目前未做。

## 11. Excel 同步面板与文件浏览器

底部面板「Excel 文件」tab 提供两条独立于「Excel 编辑桥接」（@6）的交互：**卡片式文件浏览器** + **同步面板**。
（工作簿组不参与这两条：它自己就是工作簿，没有"两份拷贝要同步"这回事，@02.26.8。）

### 11.1 Excel 文件浏览器

数据源：`<project_root>/.excel/*.xlsx`（与 excel_bridge 的 `.tbl-cache` 独立）。

- 每文件一张卡片（高 28px）：📄 图标 + 文件名
- **单击**行 = toggle 选中；选中态 = `Theme.border-selected` 边框 + `Theme.bg-row-selected` 背景
- **双击**行 = 系统默认程序打开 xlsx（纯查看，不建编辑会话 / 不监控 / 不回写）
- 工具栏 4 个按钮（40×18 小方块）：`同步` / `刷新` / `删除` / `打开`
  - `删除` 无选中时整钮 0.4 透明度且点击忽略；有选中时删除选中文件
  - `打开` 打开所有选中文件，无选中则兜底打开第一个
- 空列表显示灰色 `(无 Excel 文件)`

### 11.2 Excel 同步对话框

标题「Excel 同步」，尺寸 920×550，底部「刷新」+「关闭」。数据模型 `EsRow` 每行对应一个 (group, table) 或 (group, xlsx sheet) 配对。

**表头 4 列**：`组 / 节点`（200px）｜`tablet(行x列)`（100px）｜`操作`（180px）｜`Excel(行x列 | 匹配+差异)`（180px），列间 1px 分隔线。

**每行状态 + 操作按钮**（按场景只渲染匹配按钮）：

| 场景 | 显示 | 操作 |
|------|------|------|
| 完全匹配（两侧列一致） | tablet `N行 M列` / Excel `N行 M列 \| K匹配` | `数据→` / `←数据` |
| 仅 tablet 多列 | `tbl_more_cols` | `数据→` / `←数据` / `补列→` |
| 两侧各有独有列 / 仅 xlsx 多列 | `hdr_mismatch` / `xlsx_more_cols` | `强制→` |
| tablet 有、xlsx 无 | `(新节点)` 蓝字 | `创建→` |
| xlsx 有 sheet、tablet 无 | `(新 sheet)` 蓝字 | `←导入` |
| 表头首列不匹配 | 红色 `blocked_reason`（表头不符合规范） | 仅 `⛔` |

**视觉反馈**：
- 行两侧 `N行 M列` 有差异时用 `Theme.mark-modified`（改动色）高亮；**desc 差异也算差异**（只改了描述的行同样亮出按钮）
- checkbox 为静态矩形（无交互），table 行恒为 checked
- 所有操作即时执行，结果写 UI 日志（`[同步]` / `[同步失败]`）；`数据→` / `←数据` 无差异时拒绝（`数据已同步，无需操作`）

Excel 侧的表头是 4 行（desc / export / type / 列名），同步交换的是 **desc + 数据**；`←数据` 回读后会正常置上未保存标记，需保存当前 Project 才落盘。详见 @6 §7.2。

**操作按钮 → 核心操作**：`数据→` = `Push{MatchedOnly}`；`←数据` = `Pull`；`补列→` = `Push{WithTabletColumns}`；`强制→` = `Push{WholeTable}`；`创建→` = `CreateFile`；`←导入` = `ImportSheet`（尚未实现，点下去如实报错）。

**按钮由 plan 决定，不由 .slint 决定**：`EsRow.ops: [EsOp]` 就是 core 算好的那份「这一行允许做哪些操作」，面板 `for op in row.ops` 逐个画出来。以前可见性谓词写在 `.slint` 里、行为写在 Rust 的 `match act` 里，两套规则手工对齐——还漏出过同一个「强制→」画两遍这种毛病。点击回传的是**操作本身**（`EsOp.code`），不是它在列表里的下标。
