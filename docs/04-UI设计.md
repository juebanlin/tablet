# UI 设计

桌面工具的界面布局、交互、编辑保存机制、验证反馈、规划中功能。所有 tbl 系统的硬性约束都在 @01；这里只讲面向用户的呈现与操作。

## 1. 整体布局

### 1.1 区域划分

#### 顶层 3 个大区

| 大区 | 位置 | 尺寸 | 责任 |
|------|------|------|------|
| **Toolbar** | 顶部 | 32px | 全局命令按钮（保存 / 重新加载，详见 @5.1） |
| **TreeSection + GridSection** | 中部填充 | 自适应高度 | 配置树 / 表格 二选一聚焦 |
| **LogPanel** | 底部 | 默认 120px，可拖拽 | 操作日志（独立于表格区） |

#### 中部两个子大区

| 大区 | 位置 | 尺寸 | 责任 |
|------|------|------|------|
| **TreeSection** | 左 | 默认 240px，最小 220px，可拖拽，无最大限制 | 配置树（4 段：标题 / 顶部功能区 / 过滤功能区 / 节点列表，三层节点 project → group → node） |
| **GridSection** | 右 | 自适应宽度 | 当前选中节点的表格详情（5 段子区域） |

调节线、滚动条等具体行为见 @1.5。

### 1.2 区域归属原则

每个 UI 元素都明确归属一个大区，不跨级悬浮：

- **属于「当前选中表」的所有控件归属 GridSection**：表名标题、表级开关、公式栏、状态栏，宽度都跟随表格区。
- **属于「项目浏览」的控件归属 TreeSection**：新建项目按钮 / 排序下拉、搜索 / 过滤 / 完整组、节点列表。
- **全局命令归属 Toolbar**；**与具体节点无关的产出归属 LogPanel**。

这样读者一眼就能从位置反推归属：选中 cell 时看到的「B3 │ 战士」公式栏，本质是 `GridSection` 的子组件，它窄于 `Toolbar`、宽于 `TreeSection`，自然不会让人误以为是全局栏。

### 1.3 GridSection 子区域

`GridSection` 是表格大区，从上到下 5 段子区域，全部与 `GridArea` 等宽：

| 子区域 | 高度 | 内容 |
|--------|------|------|
| **GridHeaderBar** | 24px | 表名（含图标 + 路径，如 `📊 hero / HeroBase`） + 副标题（行列数 / 模式） |
| **GridRibbon** | 24px | 表级视图开关（仅渲染影响），见 @5.2 |
| **FormulaBar** | 22px（动态） | 选中单元格时显示坐标 + 公式栏；未选中时 0 高度收起 |
| **GridArea** | 自适应 | 固定表头 + 可滚动数据区 |
| **StatusBar** | 20px | 当前选区 + 光标位置 |

未选中任何节点时，`GridSection` 显示居中占位文本「选择左侧节点查看详情」，子区域条仍可见但内容为空。

### 1.4 TreeSection 子区域

`TreeSection` 是配置树大区，4 段子区域，宽度跟随大区：

| 子区域 | 高度 | 内容 |
|--------|------|------|
| **标题栏** | 24px | 「项目列表」固定标签 |
| **顶部功能区** | 自适应 | 新建项目按钮 + 排序下拉 |
| **过滤功能区** | 自适应 | 搜索框 → 过滤下拉 → 完整组勾选（顺序固定） |
| **节点列表** | 自适应填充 | 树形导航，可滚动 |

### 1.5 拉伸调节与滚动条

#### 大区拉伸调节

| 调节线 | 位置 | 行为 |
|--------|------|------|
| **左右调节线** | TreeSection 与 GridSection 之间（垂直走向） | 鼠标悬停光标变 ↔，左右拖动改变两者宽度 |
| **上下调节线** | 中部（树+表格）与 LogPanel 之间（水平走向） | 鼠标悬停光标变 ↕，上下拖动改变 LogPanel 高度 |

约束：

- TreeSection：默认 240px，最小 220px（功能区搜索框 + 过滤下拉的最小可读宽度），无最大限制
- LogPanel：默认 120px，最小 40px（保留标题 + 一行日志可见，避免拖到 0 后找不回）；上限由窗口高度决定
- Toolbar / GridHeaderBar / GridRibbon / FormulaBar / StatusBar 不可拖拽，固定高度
- 用户拖拽后的尺寸保留在会话内（不持久化到配置）

> 实现：slint 没有内置 splitter，手写 4px `Rectangle` + `TouchArea(mouse-cursor: ew-resize/ns-resize)` + `pressed-x/y` 累加 delta，详见 @05.2。TreeSection 内层多一层 border + padding，搜索框最小可读宽度对应外层 220px。

#### 滚动条

滚动只发生在「内容超出可视区」的局部，不在整窗口级别：

| 区域 | 滚动方向 | 行为 |
|------|----------|------|
| **TreeSection 节点列表** | 双向（H + V） | 节点超出 → 右侧出垂直条；名字过长被窄面板截断 → 底部出水平条 |
| **GridArea 数据区** | 双向（H + V） | **表头水平随数据滚动同步、垂直固定**；**行号列垂直随数据滚动同步、水平固定**；列 / 行号 gutter 永远停在自身轴 |
| **LogPanel 列表** | 垂直 | 内容超出可视区 → 右侧出垂直条；自动「粘底」（新日志追加时自动滚到末尾），用户手动上滑后停止粘底，回到底部后恢复 |

#### 滚动条样式

- 滚动条只在区域有 hover / 滚动时显示，离开后淡出
- 内容不足时不显示滚动条（不留空白槽）
- TreeSection 与 GridArea 的水平 / 垂直滚动条独立，互不影响

## 2. TreeSection（配置树大区）

左侧主区域，**四段式**：标题栏 / 顶部功能区 / 过滤功能区 / 节点列表。所有控件宽度跟随大区。所有 project 同时加载、同时展示在一棵树里——**没有"切换 project"概念**，跨 project 复制粘贴节点是自然操作。

```
┌────────────────────────────────────────┐
│  项目列表                              │ ← 标题栏
├────────────────────────────────────────┤
│  [新建项目]  [排序: ID ▼]              │ ← 顶部功能区
├────────────────────────────────────────┤
│  搜索: [search________]                │
│  过滤: [全部 ▼]                        │ ← 过滤功能区
│  ☐ 完整组                              │
├────────────────────────────────────────┤
│  ▼ 📦 slg-test                         │ ← project 根（顶层，opened）
│      ▼ hero                            │ ← group（中层）
│          📊 HeroBase                   │ ← node（叶层）
│          📊 HeroSkill                  │
│      ▼ global                          │
│          📋 GameConst                  │
│  ▶ 📦 slg-prod                         │ ← 折叠的 opened project
│  ▷ 📦 mini-game                        │ ← closed project（灰态、无展开三角）
└────────────────────────────────────────┘
```

### 2.0 多 Project 同时管理

**核心模型**：启动时扫描 `<repo-root>/projects/` 全部加载到 `ProjectEngine`，树视图把每个 project 显示为顶层节点（📦 图标 + name）；下面挂 group → node 两层。所有 project 始终在内存里，节点选中可在任意 project 之间切换，**不存在"卸载当前/加载下一份"的切换概念**。

#### Opened / Closed 两态

每个 project 有两种状态，由 TreeSection 顶部「新建项目」旁的开关 + 右键菜单切换：

| 状态 | 内存 | 树展示 | 可选中/可编辑 | 参与搜索/过滤 |
|------|------|--------|---------------|--------------|
| opened | 已加载 | 正常 + 三角展开 | ✅ | ✅ |
| closed | 仅元信息（id/name），不读 .tbl | 灰态（opacity 0.5/0.7）+ 无展开三角 | ❌（点击仅响应右键） | ❌ |

关闭 ≠ 删除：`closed` 仅卸出内存，磁盘文件保留；下次扫描仍可见。强需求：策划本机有十几个 project，平时只工作在 1-2 个，关掉其它降内存 + 减少树噪音。

| 维度 | 决策 |
|------|------|
| 节点定位键 | `(project_id, group, name)` 三元组 |
| 引用范围 | `@TableName` / `@EnumName` 仅在同 project 内解析；跨 project 引用 = 验证错误 |
| 新建落点 | 新建 group / table 默认落到选中节点所在 project；空选时落第一个 opened project |
| 跨 project 复制粘贴 | 走 `engine.node_clipboard`（见下），与系统剪贴板独立。`@ref` 字段不自动改写，dangling 引用按验证错误暴露给用户解决 |
| 搜索 / 过滤范围 | 仅扫描 opened project；closed 不参与匹配（避免命中却点不开） |
| 首屏展开状态 | opened project 默认按用户上次会话的展开/折叠状态恢复（不持久化具体节点级展开） |
| Project 标签显示 | `[ui] show_meta_id = false`（默认）显示 `instance_meta.name`；`true` 显示 id |
| 排序键 | TreeSection 顶部下拉控制（@2.3）：ID / 名称 / 已打开 / 创建时间 / 手动 |

#### Project 根节点右键菜单

opened project（11 项）：

```
┌────────────────────────────┐
│  保存                      │ → 仅落盘该 project 的脏改（其它脏 project 不动）
│  导出...                   │ → 弹「数据导出」对话框（@6.4），仅作用于该 project
│  导出 Schema...            │ → 弹「导出 Schema」对话框（@6.5），节点级
│  合并 Schema...            │ → 弹「导入 Schema」对话框（@6.5），把外部 .tblschema 合并入本 project
│  ─────                     │

│  复制(克隆)...             │ → 弹「复制项目」对话框（@6.8），内存深拷贝当前 project 为新 project

│  在文件管理器打开          │

```

#### node_clipboard（节点级剪贴板）

引擎内部维护一份独立于系统剪贴板的 `node_clipboard`，专用于树节点 / Group 复制粘贴。

| 入口 | 写入内容 |
|------|---------|
| Group 右键「复制 Group(含全部内容)」 | `Group { name, nodes: [...] }` 整组深拷贝 |
| 节点右键「复制」 | 单节点深拷贝（Table / Constant / Enum） |

写入后右键菜单上对应粘贴项的 label 实时反映 clipboard 内容：「粘贴节点(HeroBase)」/「粘贴 Group(hero)」。

| 粘贴位置 | 行为 |
|---------|------|
| Project 根节点 | 仅当 clipboard 是 Group 时显示「粘贴 Group」；同名 group 已存在时拒绝（弹错） |
| Group 节点 | 显示「粘贴节点」 + 「粘贴 Group」两条；后者把 clipboard group 作为新组贴入该 project |
| Table/Constant/Enum 节点 | 仅显示「粘贴节点」，落到该节点所在 group；同名节点冲突 = 自动尾缀 `-copy` / `-copy2` |

跨 project 是天然支持的：在 A project 复制后切到 B project 任意节点右键粘贴即可。`@xxx` 引用字段不改写，B project 没有同名引用目标时按验证错误暴露。

#### 老项目兼容

启动扫 `<repo-root>/projects/`：

| 情况 | 处理 |
|------|------|
| `projects/` 不存在但旧 `config/` 存在 | **自动迁移**：移动 `config/` → `projects/default/config/`、合并 `*.tblschema` → `projects/default/project.tblschema`、写 `project.toml`（@02 老结构迁移） |
| `projects/` 存在 | 列出所有子目录作为 project 全部加载；不再保留老 `config/`（迁移已完成） |
| 都不存在 | 弹「新建项目」对话框（@6.6），强制选模板创建首个 project |

### 2.1 交互

| 操作 | 效果 |
|------|------|
| 点击三角形 ▶/▼ | 展开/收拢组 或 展开/收拢 project 根 |
| 双击 project 名 / 组名 | 展开/收拢 |
| 单击配置项 | 选中，右侧 GridSection 显示详情；该节点所在 project 自动成为新建/活跃落点 |
| 右键 | 弹出对应上下文菜单 |

### 2.2 状态标记

| 标记 | 颜色 | 含义 |
|------|------|------|
| `+` | 绿 | 新建未保存 |
| `*` | 黄 | 已有文件被修改 |
| `-` | 红 | 标记删除，保存时生效 |
| `!` | 红 | 节点存在验证错误（详见 @5.4） |

组聚合子项：所有子项删除→`-`，有新建子项或自身新建→`+`，有修改子项→`*`。Project 根节点同样按聚合规则展示该 project 整体状态（聚合所有 group + 子节点）。

判断：
- 新建：`original` 为空
- 修改：序列化当前内容 ≠ `original`（"改回去"自动清除脏标记）
- 删除：`deleted = true`

### 2.3 功能区

TreeSection 标题栏下挂两条功能区：

#### 顶部功能区（项目级）

| 顺序 | 控件 | 用途 |
|------|------|------|
| 1 | 新建项目 | 弹「新建项目」对话框（@6.6），3 tab：空 / 从文件 / 从模板 |
| 2 | 排序下拉 | 项目顶层排序键：ID / 名称 / 已打开 / 创建时间 / 手动；会话内生效，未持久化 |

「已打开」排序：opened 在前、closed 在后；同态内回退到 ID 排序。「手动」预留拖拽排序入口（当前未实装）。

#### 过滤功能区（节点级）

| 顺序 | 控件 | 用途 |
|------|------|------|
| 1 | 搜索框 | 名称模糊匹配（实时过滤，placeholder「名称 / 拼音首字母」） |
| 2 | 过滤下拉 | 状态过滤：全部 / 改动 / 新增 / 修改 / 删除 |
| 3 | 完整组勾选 | 命中匹配组时显示该组所有未删子项（忽略 filter+search） |

closed project 不参与搜索 / 过滤匹配（@2.0），灰态展示在树里但不会被命中而隐藏。

#### 搜索匹配规则（`tablet_core::name_matches`）

query 与节点名都先 lowercase，任一命中即视作匹配；空 query 永远命中。

| 规则 | 例 | 命中 |
|------|------|------|
| 字面子串 | name = `HeroBase`，输 `hero` / `ero` / `Base` | ✓ |
| 拼音首字母子串 | name = `英雄表` → 派生 `yxb`，输 `yxb` / `YXB` / `xb` | ✓ |
| 中英文混合 | name = `HMM英雄表` → 派生 `hmmyxb`，输 `hmmyxb` / `mmyxb` / `yxb` | ✓ |
| 拼音全拼（不实现） | name = `英雄表`，输 `yingxiong` | ✗ |
| 字母不连续匹配 | name = `HeroBase`，输 `hb` | ✗ |

派生规则：每个汉字取该字 pinyin 首字符，非汉字（ASCII / emoji / 标点 / 空格）原样保留 + lowercase。两端前端共用同一份 `name_matches`。

#### 过滤下拉选项

| 选项 | 显示 |
|------|------|
| 全部 | 所有节点 |
| 改动 | 新增 + 修改 + 删除 |
| 新增 | 仅新建节点 |
| 修改 | 仅已修改节点 |
| 删除 | 仅标记删除节点 |

#### filter 与 search 的组合语义

filter 与 search 是**并行的 AND 条件**，不是先后管道——这点容易写错（只在原始集合做 OR 命中会丢子项）：

- 子项级显示 = `passes_filter(子项) ∧ name_matches(子项, search)`
- 组级显示 = `(组通过 filter ∧ name_matches(组名, search))` ∨ `(组内有任一子项级显示命中)`
- 组关闭时不展开子项；组展开时只列出"子项级显示"为真的子项
- 空 query 退化为纯 filter；filter = 全部 退化为纯 search

#### 完整组勾选

勾选后，**只要组本身被 filter+search 通道命中**，该组所有未删子项**忽略 filter 与 search 全部展开**——便于在过滤态下快速浏览整组上下文。仅过滤 `deleted`。

### 2.4 右键菜单

| 目标 | 菜单项 |
|------|--------|
| Project 根（opened） | 见 @2.0 「Project 根节点右键菜单」（11 项） |
| Project 根（closed） | 见 @2.0（4 项） |
| Group | 新建 Table、新建 Constant、新建 Enum、复制 Group(含全部内容)、粘贴节点(...)、粘贴 Group(...)、重命名、删除 |
| Table/Constant/Enum | 复制、粘贴节点(...)、重命名、删除 |
| 空白 | 新建 Group（落到选中节点所在 project；空选时落第一个 opened project） |

**粘贴菜单项 label 实时反映 clipboard**：复制了 `HeroBase` 节点后，其它节点的右键菜单显示「粘贴节点(HeroBase)」；clipboard 为空时整条菜单项灰禁。详见 @2.0 「node_clipboard」段。

**跨 project 复制粘贴**：在 project A 的节点上右键复制 → 在 project B 任意节点上右键粘贴。粘贴节点的 `@TableName` / `@EnumName` 字段不自动改写——若 project B 没有同名引用目标，按验证错误暴露给用户解决。

## 3. GridArea（表格本体）

GridArea 是 GridSection 的核心子区域，承载固定表头 + 可滚动数据。三种 mode（Table / Constant / Enum）共用同一组渲染规则，差异在表头结构。

### 3.1 单元格类型系统（CellKind）

所有单元格统一抽象为 `CellKind`，决定交互行为：

| 类型 | 交互 | 用途 |
|------|------|------|
| ReadOnly | 不可编辑、深灰底 + 半灰文字、无 hover 高亮 | Constant/Enum 固定表头、Table id 列的 export/type/field 三格 |
| Text | 双击编辑 | 普通数据、表头 desc/field |
| TypeEnum | 单击弹出类型选择器（默认；可配） | Table 表头 type 行 |
| ExportEnum | 单击下拉（默认；可配） | Table 表头 export 行 |
| TypeEnumCol | 双击弹出类型选择器（默认；可配） | Constant type 列 |
| ExportEnumCol | 双击下拉（默认；可配） | Constant export 列 |
| Ref | 双击弹出引用选择器（默认；可配） | 列类型为 `@Xxx` 的数据格 |

**呼出方式可配（@4.2）**：picker 类单元格的单击 / 双击行为由 `[ui] picker_trigger_header` / `picker_trigger_data` 控制，表头与数据区独立。默认 header=single、data=double，让数据区单击始终是无副作用的"瞄准"动作（Ctrl+C/V 批量复制粘贴 ref id / enum 值的前提）。

ReadOnly 表头单元格的具体分布详见 @01.5.5；只读列不可删除/重命名（右键菜单中相应项禁用）。

### 3.2 存储值 vs 展示值（重要约定）

单元格在 UI 模型层（`grid.data` / `HeaderCell.text`）**始终存「真实存储值」**——即写入 .tbl 文件的形式。渲染层在画的瞬间通过 `display_for_*` 转换为 UI 展示值。

| 列类型 | 存储值（grid.data） | 展示值（painter） |
|--------|----------------------|-------------------|
| ExportEnum / ExportEnumCol | `cs` / `c` / `s` / `-` | 前后端 / 客户端 / 服务器 / 不导出 |
| Ref（@EnumName + 开关开） | enum 条目 id（如 `1`） | 对应 entry.name（如 `WARRIOR`） |
| Ref（@TableName 或开关关） | 表/枚举 id | 同存储值 |
| 其它 | 原字符串 | 同存储值 |

由此自动得到的好处：
- **复制粘贴 round-trip**：剪贴板永远是 `cs` 而不是「前后端」，粘到别处直接落地
- **公式栏/编辑缓冲一致**：编辑态读 `grid.data` 直接拿到存储值
- **校验/序列化无歧义**：底层逻辑只看一种字符串

下拉编辑组件按同规则：`edit_buffer` 写存储值（点击「前后端」实际写 `cs`），渲染时再翻译。新增带「展示≠存储」的列类型时，**必须同时在 `display_for_cell` / `display_for_header` 增加分支**，不允许把展示值塞回 `grid.data`。

#### 展示与可编辑性是独立维度

ReadOnly 仅控制 **能否编辑、能否右键操作、是否显示下拉箭头**；它不影响 **展示规则**。最典型的例子是 Table 表头的 id 列 export 行：

| 维度 | 取值 |
|------|------|
| 存储值 | `cs` |
| kind | `ReadOnly`（id 列 export/type/field 三行不可改） |
| 展示值 | `前后端`（与其它 export 列一致） |

误区：曾经的实现里 `display_for_header` 仅匹配 `ExportEnum/ExportEnumCol` kind，导致 id 列虽然存的是 `cs` 但因为 kind 是 ReadOnly 被原样画出，与同行其它列「前后端」不一致。修法是按 **行位置**（Table 第二行就是 export 行）触发翻译，不依赖 kind。

#### 存储值边界

slint 是纯展示层，`HeaderCell.text` / `DataCell.text` 直接存展示值；存储真值由 `AppState.engine` 持有，Rust 的 `convert::build_grid` 在产出快照时翻译。复制 / 编辑 / 序列化等业务逻辑都从 `AppState.engine` 读写存储真值，不会从展示快照里取值。

### 3.3 Table 模式

```
┌────┬──────┬──────┬──────┬────────┐
│    │  A   │  B   │  C   │   D    │  ← 列字母行
├────┼──────┼──────┼──────┼────────┤
│    │英雄ID│ 名称 │ 血量 │ 技能组 │  ← desc (Text)
│    │前后端│前后端│服务器│ 前后端 │  ← export (ExportEnum)
│    │ int  │ str  │ int  │List<int>│ ← type (TypeEnum)
│    │ id   │ name │ hp   │ skills │  ← field (Text，id 列 ReadOnly)
╞════╪══════╪══════╪══════╪════════╡
│  1 │ 1001 │ 战士 │ 100  │ 1;2;3  │
│  2 │ 1002 │ 法师 │  80  │ 4;5    │
│  3 │      │      │      │        │  ← 扩展空行（自动追加 5 行）
└────┴──────┴──────┴──────┴────────┘
```

- 表头固定，不随数据滚动
- 数据行数 = 第一列（ID 列）非空的行数
- 扩展空行允许直接输入新增数据
- ID 列字段名固定 `id`，不可编辑/不可删除（见 @01.5.2）

### 3.4 Constant 模式

```
┌────┬──────────┬───────────┬───────┬──────┬──────────┐
│    │  A       │  B        │  C    │  D   │  E       │
├────┼──────────┼───────────┼───────┼──────┼──────────┤
│    │ name     │ type      │ value │export│ desc     │  ← 固定表头 (ReadOnly)
╞════╪══════════╪═══════════╪═══════╪══════╪══════════╡
│  1 │max_level │ int▾      │ 100   │前后端▾│最大等级 │
│  2 │start_pos │Tuple2…▾   │ 5,10  │前后端▾│出生坐标 │
└────┴──────────┴───────────┴───────┴──────┴──────────┘
```

列定义：name (Text) / type (TypeEnumCol) / value (Text) / export (ExportEnumCol) / desc (Text)。

### 3.5 Enum 模式

```
┌────┬──────┬──────────┬──────────┐
│    │  A   │  B       │  C       │
├────┼──────┼──────────┼──────────┤
│    │  id  │ name     │ desc     │  ← 固定表头 (ReadOnly)
╞════╪══════╪══════════╪══════════╡
│  1 │  1   │ WARRIOR  │ 战士     │
│  2 │  2   │ MAGE     │ 法师     │
│  3 │  3   │ ARCHER   │ 弓手     │
└────┴──────┴──────────┴──────────┘
```

列定义：id (Text) / name (Text) / desc (Text)。

## 4. 选择 + 编辑

### 4.1 选中

| 操作 | 结果 | 视觉 |
|------|------|------|
| 单击单元格 | 选中单格 | 浅蓝背景 + 蓝边框 |
| 单击行号 | 选中整行 | 整行浅蓝 |
| 单击列字母 | 选中整列 | 整列浅蓝（含表头） |
| 拖动单元格 | 选中矩形区 | 区域浅蓝 |
| 拖动行号 | 选中多行 | 多行浅蓝 |

### 4.2 编辑触发

picker 单元格（TypeEnum / ExportEnum / TypeEnumCol / ExportEnumCol / Ref）的呼出方式由 `[ui]` 两个独立旋钮控制（@03.4.10）：
- `picker_trigger_header` —— 表头 picker（Table type / export 行）：默认 `single`
- `picker_trigger_data` —— 数据区 picker（Ref 列 / Constant type / export 列）：默认 `double`

Text 单元格永远是双击进 LineEdit；ReadOnly 永远不可编辑。

| 操作 | 默认行为 | 说明 |
|------|---------|------|
| 单击 Text / picker 单元格（任意区域） | 选中 | 进入选区，可 Ctrl+C/V |
| 双击 Text 单元格 | 文本编辑框 | Enter 确认 / Esc 取消 |
| 单击表头 picker（默认 single） | 直接弹 | type 行弹类型选择器、export 行弹下拉 |
| 双击数据区 picker（默认 double） | 弹 picker | export 列弹下拉、type 列弹类型选择器、Ref 列弹引用选择器 |
| 公式栏输入 | Text 单元格选中后 | Enter 提交 |

**为什么数据区默认 double？** 早期版本数据区单击立即弹 picker，**没法选中 ref / enum cell**——选中之后才能 Ctrl+C/V 批量复制粘贴 ref id / enum 值。改 double 后单击稳定为"瞄准选中"。

**为什么表头默认 single？** 表头每列 type / export 各一格，几乎不需要批量改、也很少需要"先选中一片表头再操作"，single 直接弹少一次点击。

切到反向模式后体感会变：例如数据区设 `single` 后，单击 ref cell 直接弹 RefPicker，要批量复制就只能先 Esc 关弹窗再瞄准。两个旋钮独立可调，按口味来。

### 4.3 编辑保存策略

由 `[ui] auto_commit_on_blur` 控制（见 @03.4.10）：

| 配置 | Enter | 点击空白 / 其它单元格 |
|------|-------|------------------------|
| true（默认） | 保存 | 自动保存 |
| false | 保存 | 丢弃编辑 |

无论配置如何：Enter 始终保存，Esc 始终取消。

| 快捷键 | 功能 |

| Ctrl+C | 复制（TSV，兼容 Excel；按 @3.2 输出真实存储值） |
| Ctrl+X | 剪切（复制 + 删除内容，picker 列剪切只清值不改 schema） |
| Ctrl+V | 粘贴（TSV，支持多行多列） |
| Delete / Backspace | 清空选中单元格 |

### 4.5 右键菜单

| 目标 | 菜单项 |
|------|--------|
| 列字母行 | 左侧插入列、右侧插入列、删除列 |
| 行号 | 上方插入行、下方插入行、删除行 |
| 数据单元格（picker 类） | **首项："选择引用..." / "选择类型..." / "选择导出标记..."（按 cell kind 差异化）**、复制、粘贴、删除内容 |

picker 首项是"双击呼出"之外的辅助入口——发现性更好，对鼠标流也少一次精确点击。多选状态（CellRange）下首项不显示，避免误以为支持批量改（picker 一次只能改一个值；批量改靠选中后 Ctrl+C/V）。

## 5. 全局与表格区组件

界面有 5 处条形子区域。**Toolbar 与 LogPanel 是顶层全局**，**GridHeaderBar / GridRibbon / FormulaBar / StatusBar 是 GridSection 内部子区域**（与 GridArea 等宽，跟随表格大区）。

### 5.1 Toolbar（顶部全局工具栏）

```
[保存]  [重新加载]
```

按钮：[保存] [重新加载]。两个按钮服务"全局动作"——脏改一次落盘 / 全部 project 重读磁盘——不依赖具体选中节点。

| 按钮 | 行为 |
|------|------|
| 保存 | 全部脏 project 一键落盘（@7.2）；无脏改时禁用 |
| 重新加载 | 重扫 `projects/` 重读全部 .tbl，丢弃内存脏改前会先弹确认 |

旧版工具栏的其它入口已经按"作用域"下沉到对应位置：

| 旧入口 | 现位置 |
|--------|--------|
| 新建项目 | TreeSection 顶部功能区「新建项目」按钮（@2.3） |
| 用 Excel 打开 | GridRibbon「Excel 编辑」按钮（@5.2） |
| 导出 / 导出 Schema / 合并 Schema | Project 根右键菜单（@2.0） |
| 模板库 | 已合并入「新建项目」对话框 tab 2「从模板」（@6.6） |
| 生成测试数据 / 清空配置 | 计划中入口；现版本已隐藏 |

Toolbar 是单行结构，不放任何与「当前选中表」绑定的开关——表级开关全部下沉到 GridSection 的 GridRibbon。

### 5.2 GridRibbon（表级功能 bar）

GridSection 第二条子区域，类似 Excel 工具栏下面那条「字体/对齐/换行」选项条：放视图开关 + 表级动作按钮，仅影响渲染或当前节点。归属表格大区，宽度跟随 GridArea。

```
┌─────────────────────────────────────────────────────────┐
│ [Excel 编辑]   [☑] 枚举显示名字                         │
└─────────────────────────────────────────────────────────┘
```

#### 当前控件

| 控件 | 类型 | 作用 | 默认 | 启用条件 |
|------|------|------|------|----------|
| Excel 编辑 | 按钮 | 调起系统 Excel 打开当前选中节点的 .tbl 临时副本，文件回写后自动重新加载（详见 @06） | — | 选中节点 + .tbl 已存在（新建未保存节点禁用） |
| 枚举显示名字 | 勾选框 | Table 数据格中类型为 `@EnumName` 的引用列，只读渲染时显示对应 Enum 的 `entry.name` 而非存储的 id | 关 | 仅当选中 Table 时启用；Constant / Enum 选中时禁用 |

#### 引用类型分类

`@xxx` 是 type 系统的子类型，按被引用对象分两类：

| 类型 | 形如 | 当前是否支持"显示名字" |
|------|------|----------------------|
| 枚举引用 | `@HeroType`（指向 Enum 节点） | ✅ 由本开关控制 |
| 表引用 | `@HeroBase`（指向 Table 节点的主键 id） | ❌ 当前未实现"显示 Table.name 列"；始终显示 id |

> 开关名字明确写的就是"枚举显示名字"，只覆盖 @Enum；@Table 的"显示某列内容"属于将来再考虑的独立功能，不在本开关语义内。

#### 不影响范围（即便勾上也不变）

- 内置导出枚举（前后端 / 客户端 / 服务器 / 不导出）——这些走 ExportEnum 渲染规则，与本开关无关
- 表引用 `@TableName` 数据格——见上表，独立功能未实现
- 编辑场景（公式栏 / 双击编辑 / 引用选择器内）——始终是 id，避免"看到名字、改的是 id"的割裂
- Constant 的 `value` 列即使填 `@EnumName` 类型，当前不参与 id→name 渲染（只有 Table 的引用数据格走该路径）

> 状态全局保留一份（不绑定到节点），切回 Table 时自动恢复用户上次的勾选状态。Constant / Enum 选中时禁用是因为它们没有 Table 那种"@EnumName 引用数据列"，勾上也观察不到任何视觉变化。

### 5.3 FormulaBar（公式栏）

GridSection 第三条子区域，单元格内置编辑组件的「长内容辅助查看 + 编辑」延伸。**仅在选中单元格时显示**；未选中时整条收起为 0 高度。

- 左：当前选中单元格坐标（如 `B3`）
- 右：根据单元格类型决定行为

| 单元格类型 | 公式栏行为 |
|-----------|-----------|
| Text | 可编辑，缓冲 = 真实存储值；Enter / 失焦提交 |
| ExportEnum / ExportEnumCol | 只读 + 🔒 提示，展示底层 raw（`cs` / `c` / `s` / `-`，**不是**翻译后的"前后端"）。编辑走单元格下拉 |
| TypeEnum / TypeEnumCol | 只读 + 🔒，展示类型字符串。编辑走类型选择器弹窗 |
| Ref | 只读 + 🔒，展示底层 id（**不受**「枚举显示名字」开关影响）。编辑走引用选择弹窗 |
| 表头单元格（desc/export/type/field 行） | 公式栏不参与，编辑由表头自身的双击/下拉处理 |

picker / ReadOnly 列只读 + 显示底层 raw 是为了：
1. 对齐 Excel 心智模型 —— 单元格展示翻译值，公式栏永远是底层真值
2. 关掉 picker 校验旁路 —— 早期版本对 picker cell 公式栏可编辑，能直接打字塞入非法值（不存在的 ref id、非法 export 短码）；只读后只能走 picker 弹窗，校验保证写入合法
3. 视觉上用淡色文字 + 🔒 暗示 "不可改"，避免误以为 Text 但点不动

设计目的：解决 Text 单元格内容过长被截断（picker 列内容本身短，无此需求）。

### 5.4 验证错误展示

数据通过 cell→row→schema→table→project 五层验证（@01.8、@01 附录 A），UI 上的错误反馈分散在多个区域：

| 位置 | 表现 |
|------|------|
| GridArea 数据单元格 | 红色边框（1.5px） |
| GridArea 表头单元格 | 红色边框（1.5px），按 `ValidationError.header_row` 归到对应行（type 行 / field 行） |
| StatusBar | 选中单格且该格有错误时，坐标后追加 `⚠ 错误原因` |
| TreeSection 节点 | 状态标记后追加红色 `!` |
| TreeSection 组节点 | 子项有错误时同样追加 `!`（聚合） |
| LogPanel | 加载、保存失败时输出具体错误位置 + 错误信息（@01.附录A.5 格式） |

加载项目时即触发一次 `revalidate_all`，红框/`!` 在打开就可见，不依赖用户先编辑触发；reload / 生成测试 / 清空 后同样会重新跑全表验证。

实时验证开关 `[ui] realtime_validate` 见 @03.4.10.2。

GridSection 最末子区域，显示当前选中状态。归属表格大区，与 GridArea 等宽。

| 单行 | `第3行` |
| 多行 | `第2-5行 (共4行)` |
| 整列 | `第B列` |

### 5.6 LogPanel（底部全局日志）

顶层第三大区，独立于表格区。带「日志」标题栏 + 可滚动列表区，记录加载 / 保存 / 验证 / 导出等操作输出。

## 6. 弹窗组件

### 6.1 模态规则

所有弹窗（类型选择器、引用值选择器、导出对话框、Schema 导入导出、删除确认、命名输入等）遵循 Windows 常规模态规则：

- 弹窗显示时父级 UI 被半透明遮罩盖住，遮罩拦截所有鼠标点击（即父级不可点）
- 多层弹窗时只有最顶层可操作；子弹窗关闭后才能回到父级弹窗，以此类推
- 退出方式：点击「确定 / 取消 / 关闭」按钮，或点击窗口外的遮罩区域（等同取消）；按 Esc 等同取消

按钮排布统一约定（Windows 习惯）：

- 一律**右下角**对齐
- 顺序固定（视觉左→右）：**辅助按钮 → 主操作 → 取消**
  - 例：`[清空] [确定] [取消]`、`[导出] [取消]`、`[导入] [取消]`
- **取消始终在最右**，主操作（确定/导出/导入...）紧邻其左，对齐 Windows 系统对话框习惯
- 实现：通过 `modal::dialog_buttons` 封装 `right_to_left` 布局；行宽用 `ui.min_rect().width()` 撑满已布局的内容宽度（不能用 `available_width()`，在 `Window::resizable(false)` 下值不准确，会导致按钮贴左）

- field 行渲染英文字段名（id / name / hp / ...）

- Enum 引用没有 schema desc，desc 行硬编码 "ID / 名称 / 描述"

- **当前值**：顶部输入框，与列表选中双向同步；允许直接手输任意值（不要求命中列表），确认时优先以此为准

- 整行可点选中，hover 高亮；双击行 = 确定
- 列分隔与行底渲染网格线，便于对齐阅读
- [清空] 把单元格置空（视作未引用）
- 引用值为空时单元格视觉淡灰
- 引用目标不存在时弹窗顶部展示警告条；确定按钮仍允许提交（手动输入合法）

## 7. 保存机制

### 7.1 延迟写盘

所有创建/修改/删除操作只改内存，不立即落盘：
- 新建 Group/Table/Constant/Enum → 内存创建，标记 `is_new` / `dirty`
- 编辑数据 → 改内存，序列化对比自动计算 dirty
- 删除 → 标记 `deleted`，节点仍在树中显示（带 `-`）
- 复制 → 内存复制，标记新建

### 7.2 保存按钮

点击保存时统一处理：
1. 新建组 → `create_dir_all`
2. dirty 节点 → 序列化写 .tbl
3. deleted 节点 → 删除 .tbl 文件，从内存移除
4. 空组 → 删除目录

未保存关闭程序 = 丢弃所有修改。

### 7.3 进程锁

同目录下 `.tablet.lock` 防止多实例编辑同一项目。启动时检查 PID 是否存活。

## 8. 行颜色标记展示

数据行带 `#@c:RRGGBB` 标记时，UI 表格中该行显示对应背景色（详见 @01.9）：

- 仅展示，不提供标色入口（标色在 Excel 中完成）
- 行号列同步显示颜色，便于快速识别

## 9. 退出提示（规划中）

未保存修改时退出 → 弹出确认（保存 / 放弃 / 取消）。

## 10. 图标参考

工具使用 Unicode emoji/符号作为 UI 图标，slint 走系统字体 fallback 渲染，无需额外图标库。

### 10.1 已使用

| 符号 | 用途 |
|------|------|
| 📁 | Group 文件夹 |
| 📊 | Table |
| 📋 | Constant |
| 🔢 | Enum |
| ▶ ▼ | 树展开箭头 |
| ☑ ☐ ▣ | 复选框（含半选） |

**状态**：❌ ❗ ✔️ ⏳ 🔄 🚫

**操作**：➕ ➖ ✏️ 🔍 💾 📥 📤 🗑️ 📎

**标记**：🟢 🟡 🔴 ⬤ ○ ● ◆ ◇ ★ ☆

**结构**：📄 📂 🏷️ 🔗 📐 ⚙️

### 10.3 渲染说明

- slint 走系统字体 fallback 链，需要确保链中含 emoji 字体（Windows / macOS 默认即可，Linux 桌面通常需要 `fonts-noto-color-emoji` 之类）
- 组合符号（如 ⚠️ = U+26A0 + U+FE0F）在某些字体下可能显示为文本样式
- 单色符号（▶▼☑☐▣●○）渲染最稳定，不依赖彩色 emoji 表
- 彩色 emoji 在 Windows / macOS 表现一致
