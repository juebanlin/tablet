# 测试

## 测试架构

集成测试通过 CLI 程序驱动，基于 `.tblschema` 结构定义文件生成测试数据和验证代码，验证完整的导出链路：.tblschema → .tbl → JSON → Java 编译 → 加载运行。

### 核心流程

```
.tblschema（结构定义）
    ↓ generate-test
.tbl 数据文件 + TestMain.java
    ↓ export
JSON 数据 + Java Tpl 类
    ↓ javac + java
actual_output.txt
    ↓ diff
expected_output.txt → PASS / FAIL
```

### 内置 Schema 文件

位于 `crates/core/schemas/`，每个文件描述一种测试场景的表结构：

| 文件 | 覆盖内容 |
|------|---------|
| `basic.tblschema` | 基础类型（int/str/bool/float） |
| `collection.tblschema` | 集合类型（List/Set/Map） |
| `tuple.tblschema` | 元组类型（Tuple2/3/4） |
| `empty.tblschema` | 空值字段（验证 null/omit 策略） |
| `full.tblschema` | 完整项目结构（所有类型组合） |

Schema 文件格式详见 [01-tbl系列格式 · .tblschema](01-tbl系列格式.md#二tblschema-结构定义文件)。

## 目录结构

```
tbl-tool/tests/
├── run_all.sh              ← 自动发现并执行所有场景
├── java_json/
│   ├── run.sh              ← 场景测试脚本
│   └── expected_output.txt ← 预期输出
├── java_empty_omit/
│   ├── run.sh
│   └── expected_output.txt
└── ...
```

每个场景目录只需维护 `run.sh` + `expected_output.txt`，其余文件（.tbl、TestMain.java、gen/、out/）全部由 CLI 动态生成。

## 测试流程

`run_all.sh` 自动遍历子目录，发现 `run.sh` 即执行：

```bash
# run_all.sh 核心逻辑
for DIR in tests/*/; do
    [ -f "$DIR/run.sh" ] || continue
    cd "$DIR"
    rm -rf gen tbl-tool.toml out actual_output.txt config TestMain.java
    bash run.sh > actual_output.txt 2>&1
    diff expected_output.txt actual_output.txt && echo PASS || echo FAIL
done
```

每个场景的 `run.sh` 调用 CLI 完成数据生成和导出：

```bash
# 示例：java_json/run.sh
$CLI -w . generate-test              # 根据选项生成 .tbl + TestMain.java
$CLI -w . export                     # 导出 JSON + Java
javac ... TestMain.java              # 编译
java TestMain gen/server/data        # 运行验证
```

## CLI generate-test 命令

通过选项组合控制生成的测试数据特征：

```bash
tbl-cli generate-test [OPTIONS]

OPTIONS:
    --empty           包含空值字段
    --no-collection   不包含集合类型
    --no-tuple        不包含 Tuple 类型
    --no-constant     不包含 Constant 配置
    --rows <N>        数据行数（0=默认固定数据）
    --seed <N>        随机种子（0=固定数据，非0=可重复随机）
```

`generate-test` 同时生成：
- `config/` 下的 .tbl 数据文件（结构 + 动态填充的行数据）
- `TestMain.java`（根据结构知道加载哪些类、打印哪些字段）

## 测试场景说明

| 场景 | 验证内容 | CLI 参数 |
|------|---------|----------|
| java_json | 基础类型、集合、Tuple、Constant 的完整导出 | `generate-test` |
| java_empty_omit | 空值字段 omit 策略 | `generate-test --empty --no-collection --no-tuple --no-constant` |
