# 测试

## 测试架构

集成测试通过 CLI 程序驱动，验证完整的导出链路：.tbl → JSON → Java 编译 → 加载运行。

测试目录位于 `tbl-tool/tests/`，每个子目录是一个独立的测试场景。

## 目录结构

```
tbl-tool/tests/
├── run_all.sh                  ← 执行所有测试场景
├── java_json/                  ← Java + JSON 基础导出测试
│   ├── config/                 ← 测试用 .tbl 文件
│   ├── TestMain.java           ← Java 加载验证代码
│   └── expected_output.txt     ← 预期输出（用于 diff 对比）
├── java_empty_null/            ← JSON 空值策略 null 测试
│   ├── config/
│   ├── TestMain.java
│   └── expected_output.txt
├── java_empty_omit/            ← JSON 空值策略 omit 测试
│   ├── config/
│   ├── TestMain.java
│   └── expected_output.txt
├── validate/                   ← 验证规则测试
│   ├── config/                 ← 含错误数据的 .tbl
│   └── expected_errors.txt     ← 预期验证错误输出
└── xml_json/                   ← XML 数据文件测试（预留）
    └── ...
```

## 测试流程

每个场景的执行流程：

```bash
#!/bin/bash
SCENE=$1
CLI=../../target/release/tbl-cli

# 1. 清理上次生成
rm -rf $SCENE/gen $SCENE/tbl-tool.toml

# 2. 在场景目录执行导出（CLI 自动读取当前目录的 config/）
cd $SCENE
$CLI -w . export

# 3. 编译生成的 Java
javac gen/server/code/**/*.java TestMain.java -d out/

# 4. 运行验证，对比预期输出
java -cp out TestMain > actual_output.txt
diff expected_output.txt actual_output.txt && echo "PASS: $SCENE" || echo "FAIL: $SCENE"
```

## CLI 参数覆盖

测试中通过 `-s key=value` 覆盖 toml 配置，无需为每个场景维护不同的配置文件：

```bash
# 测试 omit 策略
$CLI -w . export -s export.json.empty_as=omit

# 测试不同包名
$CLI -w . export -s export.server.package=com.test.alt
```

## 测试场景说明

| 场景 | 验证内容 |
|------|---------|
| java_json | 基础类型、集合类型、Tuple 类型的 JSON 导出 + Java 加载 |
| java_empty_null | 空值字段输出为 null，Java 加载后为默认值 |
| java_empty_omit | 空值字段省略，Java 加载后为默认值 |
| validate | 验证规则：类型错误、Tuple 为空、ID 重复等 |
| xml_json | XML 数据文件导出（预留，待实现） |
