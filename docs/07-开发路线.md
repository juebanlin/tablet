# 开发路线

## 1. 开发阶段

整体分两大阶段：

1. **UI 工具** — 能创建/编辑数据并产生合法的 .tbl 文件
2. **验证导出** — 能校验 .tbl 并生成 server/client 产物

## 2. 阶段一：UI 工具（核心编辑链路）

```
S1. 基础框架
    ├─ slint 窗口 + 左右分栏布局
    ├─ tablet.toml 读取
    └─ 扫描 config/ 目录构建树形结构

S2. .tbl 格式解析/序列化
    ├─ 解析 #mode, #desc, #export, #type, #field, 数据行
    ├─ 序列化回 .tbl 文本
    └─ 内置基础类型（int, str, long, float, bool）

S3. 树形结构 + 浏览
    ├─ 左侧树展示 Group / Table(📊) / Constant(📋)
    ├─ 点击节点右侧展示表头 + 数据预览
    └─ 右键菜单（新建 Group / Table / Constant）

S4. 表头编辑
    ├─ 类型下拉选择（内置类型列表 + 示例展示）
    ├─ 导出下拉（前后端/客户端/服务器/不导出）

    ├─ UI 内表格编辑单元格

    ├─ 删除（标记待删除，保存后生效）

    ├─ 复制（延迟写盘）

     ├─ 冲突检测（✅新增 / ⚠️已存在将覆盖）
```

## 3. 阶段二：验证导出

```
S9. 验证系统 ✅
    ├─ 三层验证架构（cell→row→node）
    ├─ 数据验证（类型匹配、分隔符规则、主键重复）
    ├─ 中文标点 / 空元素检测
    ├─ 错误定位（红框 + 树节点! + 日志带示例）
    ├─ 表头验证（类型合法性、字段名重复、主键存在、主键值重复）
    ├─ 常量表验证（常量名重复、类型合法）
    └─ 命名规则（小写字母开头 + 小写字母/数字/下划线 + Java/Lua/Go 关键字检测）

S10. 导出 — 数据文件 ✅
     ├─ 导出前调用验证，不通过则中断并报错
     ├─ .tbl → JSON 转换（按 export 标记过滤字段）
     ├─ .tbl → XML 转换（JDK 7+ 原生 DOM 可解析）
     ├─ 按 Group 子目录输出（data/json/ 和 data/xml/）
     ├─ snake_case → camelCase 字段名转换
     ├─ 分隔符配置嵌入数据文件（JSON _sep / XML 根属性）
     └─ 空值策略可配置（json: null/omit, xml: empty/omit）

S11. 导出 — 后端模板类 ✅
     ├─ 生成 ITpl / IConstTpl 接口
     ├─ 生成 types 子包（Tuple2/3/4）
     ├─ 生成各 Group 下的 Tpl 类（@TblSource + @TblFieldType 注解）
     ├─ 生成 TplRegistry（独立注册表）+ TplHolder（两阶段加载）
     ├─ 生成 Paradigm 枚举 + SepConfig（类型解析框架）
     └─ 生成 SimpleJsonParser / SimpleXmlParser（零依赖解析）

S12. 导出 — 前端文件 ✅
     ├─ .tbl → Lua 转换（按 export 标记过滤字段）
     ├─ 复合类型展开为 Lua table 字面量（不降级为字符串）
     ├─ 按 Group 子目录输出
     └─ 数据内嵌，require 即用

S13. 导出产物同步 ✅
     ├─ 导出时自动对比生成目录，检测新增/修改/删除/不变
     ├─ CLI 默认删除残留文件，打印变化详情
     ├─ 只对本次执行的格式做清理（粒度控制）
     ├─ 路径统一正斜杠输出
     └─ 同步后自动清理空目录

S14. Excel 桥接
     ├─ tbl → xlsx 生成（整个 Group 一个文件）
     ├─ 行颜色标记：tbl 行尾 #@c:RRGGBB → xlsx 行背景色
     ├─ open::that() 调起 Excel
     ├─ 后台检测关闭 → xlsx → .tbl.tmp
     ├─ xlsx 回读行背景色 → 写入/移除 #@c: 标记
     ├─ UI 只读展示行颜色（不提供标色入口）
     └─ 容错（超时、崩溃恢复、残留检测）
```

## 5. 推荐开发顺序的理由

- S1-S3 先跑通「能看到数据」的最小闭环
- S4-S5 让策划能实际编辑，产生合法 .tbl
- S6 是编辑的安全网
- S8 复合类型可以延后，基础类型足够跑通全流程
- S8b 导入/导出 schema 依赖 tblschema 解析器（已在 core 实现），UI 对话框独立
- S9 验证系统独立于导出，可以先做——保存时就需要验证
- S10-S12 三个导出互相独立，可并行开发
- S14 Excel 桥接放最后——没有也能正常业务使用，属于体验优化
- S15 → S16 → S17 阶段三按"短闭环"顺序：S15 能立刻给用户带来"快速起项目"价值；S16 依赖 S15 的项目内容做层级展示；S17 标签是横切系统，最后铺开影响所有视图与导出
- S15 内部 A → B → C → D → E → F → G → H 必须按序：A 加 metadata 字段 → B core 模板模块（schema 数据通路就绪）→ C generate-test 重构走 B（CLI 层闭环验证）→ D Project 概念落地（ProjectEngine 解绑全局 config_dir，重构而非 feature）→ E 模板库 UI（依赖 D 的多 Project 能力）→ F 新建项目 + 多 Project 树（Vec<Project> 同时加载，跨 project 复制粘贴）→ G 导出为模板（复用 D 的 Project 模型）→ H 网络拉取（独立实现，最后接入）
- S17 内部 S17-A → S17-B → S17-C → S17-D 必须按序：存储模型 → 编辑器 → 展示与过滤 → 导出
- S18 与 S15-S17 不冲突，可独立排期；优先级：等 S15 GUI（E2/F2/G2）落地后做 S18，避免重构 expected 文件期间 schema 还在频繁变动
- S19 在 S15-S18 任意时点都可插入，纯结构调整不动业务；优先做能让"GUI 复用 CLI 业务编排"的 §A 拆包，再做 §B GUI 分流
- S20 完全可选，只在确认有"Unity / 第三方 IDE 插件需要直接读取项目并导出"的需求落地时再做

## 6. 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 中间格式 | 自定义 .tbl v2 文本 | Git 友好，行级 diff |
| 分片 | 暂不实现 | 大多数表不超过几千行，Git merge 能力足够 |
| 类型系统 | 工具内置，配置仅控制分隔符 | 简单可控，升级发新版本 |
| ctype/stype | 不拆分，统一 type + export 标记 | Lua 无静态类型，差异在导出而非类型 |
| 数据模式 | Table + Constant + Enum | 覆盖三类配置场景 |
| Group 映射 | 文件夹 = Group = Excel | 直观，文件管理器可读 |
| 树形命名 | Group → Table / Constant / Enum | 不使用 Sheet 术语，模式即类型 |
| 数据编辑 | UI 内编辑 + Excel 编辑并存 | 小改动用 UI，大批量用 Excel |
| 导出选项 | 中文（前后端/客户端/服务器/不导出） | 策划友好，零理解成本 |
| 写回安全 | 延迟写盘 + 保存按钮统一处理 | 简单可靠，未保存关闭=丢弃 |
| 并发控制 | 进程锁(.tablet.lock) + Git | 防多实例，文本格式冲突易解决 |
| 常量导出 | 默认双端，可选限制 | 常量通常全局使用 |
| 生成类命名 | .tbl 文件名 + Tpl 后缀，大写驼峰 | 与源文件对应，清晰可追溯 |
