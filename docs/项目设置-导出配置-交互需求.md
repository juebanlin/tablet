# 项目设置 - 导出配置 - 交互需求文档

## 前置重构任务

本需求需要三个大步骤的重构，前两步是数据模型重构，第三步是基于重构后的模型实现 UI 交互。

---

## 步骤 1：重命名和对齐配置结构 🔴🔴🔴

### 1.1 目标

区分**全局配置**和**项目配置**的类名，使代码语义清晰。

### 1.2 问题分析

**现状命名混乱**：
- `WorkspaceConfig` 既用于全局配置（tablet.toml），又用于项目合并后的配置
- `ProjectConfig` 实际是仓库管理配置（last_project, opened_projects），不是项目配置
- 类型混用导致理解困难

### 1.3 重构方案

#### 新的命名规范

```rust
// ============= 全局配置（tablet.toml）=============
/// 对应 tablet.toml 文件结构（原 WorkspaceConfig）
#[derive(Debug, Clone, serde::Deserialize)]
pub struct GlobalConfig {
    /// 仓库级配置段 [project]：多项目管理状态
    #[serde(default = "default_project_management", rename = "project")]
    pub project_management: ProjectManagementConfig,
    
    /// 项目默认配置，可被项目级 project.toml [export] 覆盖
    #[serde(default)]
    pub export: Option<ExportConfig>,
    
    /// 工作区级 UI 偏好，不支持项目级覆盖
    #[serde(default)]
    pub ui: Option<UiConfig>,
    
    /// 新建空项目时的分隔符初值
    /// 仅在「新建空项目」时拷贝到 project.tblschema 的 # @sep 行作为初值
    /// 已有项目的分隔符以各自 .tblschema 的 # @sep 行为准（通过 GUI 编辑）
    /// 从模板/文件新建的项目继承源 schema 的 separators
    #[serde(default)]
    pub separators: SeparatorsSection,
}

/// 仓库级管理配置（原 ProjectConfig，重命名避免混淆）
/// 保存多项目管理状态：上次打开的项目、已打开列表、排序方式等
#[derive(Debug, Clone, serde::Deserialize)]
pub struct ProjectManagementConfig {
    pub last_project: String,          // 启动时进入的项目 id
    pub opened_projects: Vec<String>,  // 启动时自动打开的项目列表
    pub project_sort: String,          // 项目排序方式
    pub project_order: Vec<String>,    // manual 排序时的顺序
    pub config_dir: PathBuf,           // 历史字段（老布局兼容）
    pub cache_dir: PathBuf,            // 历史字段（老布局兼容）
}

// ============= 项目配置 =============
/// 项目配置（统一类型，在内存中作为两个实例存储）
/// - Project.config：合并后的生效配置（用于程序逻辑）
/// - Project.raw_config：原始配置（从 project.toml 加载，用于 UI 编辑）
/// 
/// 注意：不包含 project_management，因为那是仓库级的，不属于单个项目
#[derive(Debug, Clone, Default, serde::Deserialize)]
pub struct ProjectConfig {
    #[serde(default)]
    pub export: Option<ExportConfig>,      // 可被项目覆盖的字段
    
    // 以下字段仅在生效配置（config）中有值，原始配置（raw_config）中为空：
    // - ui 来自全局（项目级不允许覆盖，project.toml 的 [ui] 会被 strip）
    // - separators 来自 schema.separators（项目级不允许覆盖，project.toml 的 [separators] 会被 strip）
    //   
    //   分隔符继承策略：
    //   1. 新建空项目时：从 tablet.toml [separators] 拷贝初值到 project.tblschema 的 # @sep 行
    //   2. 已有项目：分隔符以 project.tblschema 的 # @sep 行为唯一来源（通过 GUI「项目设置→分隔符」编辑）
    //   3. 从模板新建：继承源模板 schema 的 separators
    //   4. 运行时：schema.separators 覆盖任何 toml 文件中的 [separators] 段
    #[serde(default)]
    pub ui: Option<UiConfig>,
    #[serde(default)]
    pub separators: SeparatorsSection,
}

// ============= 子配置（可复用）=============
#[derive(Debug, Clone, serde::Deserialize)]
pub struct ExportConfig {
    pub encoding: Option<String>,
    pub line_ending: Option<String>,
    pub json: Option<JsonExport>,
    pub xml: Option<XmlExport>,
    pub server: Option<ServerExport>,
    pub client: Option<ClientConfig>,
}
// ... 其他子配置
```

## 步骤 2：项目配置分离为"原始"和"生效"两份 🔴🔴

### 2.1 目标

项目级别的配置在内存中保存两份：
- **原始配置**（`raw_config`）：对应 `project.toml` 文件内容，用于 UI 编辑和保存
- **生效配置**（`config`）：合并后的最终值，用于程序逻辑（导出操作等）

### 2.2 问题分析

在完成步骤 1 后，`Project.config` 是合并后的配置，但存在问题：
- ❌ 无法区分"项目显式设置"和"继承全局"
- ❌ UI 无法判断哪些字段应该显示"项目覆盖"勾选框
- ❌ 保存时无法知道哪些字段应该写入 project.toml

### 2.3 解决方案

**核心思路**：`Project` 同时保存两份 `ProjectConfig` 实例

```rust
pub struct Project {
    pub config: ProjectConfig,           // 生效配置（合并后）
    pub raw_config: ProjectConfig,       // 原始配置（project.toml）
    // ...
}
```

**用途区分**（同一类型，不同实例）：
- `config`：用于程序逻辑（导出操作、数据处理）
  - `export`：合并后的最终值（项目 override 全局）
  - `ui`：来自全局配置
  - `separators`：来自 schema
- `raw_config`：用于 UI 编辑和保存
  - `export`：项目显式设置的值（可能为空或部分字段为空）
  - `ui`：为空（项目级不允许设置）
  - `separators`：为空（项目级不允许设置）

### 2.4 加载逻辑

```rust
fn load_project(workdir: &Path) -> Result<Project> {
    // 1. 加载全局配置
    let global_text = std::fs::read_to_string(&config_path)?;
    let global_config: GlobalConfig = toml::from_str(&global_text)?;
    
    // 2. 加载项目原始配置（project.toml）
    let project_text = std::fs::read_to_string(root.join(PROJECT_TOML_FILE)).ok();
    let raw_config = if let Some(pt) = &project_text {
        parse_project_config(pt)?
    } else {
        ProjectConfig::default()
    };
    
    // 3. 合并生成生效配置
    let config = merge_to_project_config(
        &global_config,
        &raw_config,
        &schema.separators,
    );
    
    Ok(Project {
        workdir: workdir.to_path_buf(),
        project_root,
        config,           // 生效配置
        raw_config,       // 原始配置
        schema,
        groups,
        schema_dirty: false,
        root_pending_create: false,
    })
}

fn parse_project_config(project_text: &str) -> Result<ProjectConfig> {
    // 解析 project.toml，仅 [export] 段有值
    // [ui]/[separators]/[project] 段会被 serde 的 #[serde(default)] 忽略或在后续被 strip
    toml::from_str(project_text)
}
```

### 2.5 合并逻辑（手动实现，清晰可控）

```rust
fn merge_to_project_config(
    global: &GlobalConfig,
    raw: &ProjectConfig,
    schema_separators: &SeparatorsSection,
) -> ProjectConfig {
    ProjectConfig {
        // 导出配置：项目覆盖全局（字段级深度合并）
        export: merge_export_config(
            global.export.as_ref(),
            raw.export.as_ref(),
        ),
        
        // UI 配置：直接使用全局（不允许项目覆盖）
        ui: global.ui.clone(),
        
        // 分隔符：使用 schema 的值作为唯一来源
        // schema.separators 从 project.tblschema 的 # @sep 行解析而来，
        // 覆盖任何 toml 文件（tablet.toml / project.toml）中的 [separators] 段
        separators: schema_separators.clone(),
    }
    // 注意：不包含 project_management，因为那是仓库级的，
    // 保存在 ProjectEngine.global_config.project_management 里
}

fn merge_export_config(
    global: Option<&ExportConfig>,
    project: Option<&ExportConfig>,
) -> Option<ExportConfig> {
    match (global, project) {
        (None, None) => None,
        (Some(g), None) => Some(g.clone()),
        (None, Some(p)) => Some(p.clone()),
        (Some(g), Some(p)) => {
            // 字段级合并：项目有值用项目，否则用全局
            Some(ExportConfig {
                encoding: p.encoding.clone().or_else(|| g.encoding.clone()),
                line_ending: p.line_ending.clone().or_else(|| g.line_ending.clone()),
                json: merge_json_export(g.json.as_ref(), p.json.as_ref()),
                xml: merge_xml_export(g.xml.as_ref(), p.xml.as_ref()),
                server: merge_server_export(g.server.as_ref(), p.server.as_ref()),
                client: merge_client_config(g.client.as_ref(), p.client.as_ref()),
            })
        }
    }
}
```

## 步骤 3：实现 UI 交互（基于重构后的模型）🔴

### 3.1 目标

在项目设置对话框中实现导出配置的编辑，支持三种属性状态场景：
1. **继承模式**：未勾选覆盖，显示全局配置值（灰色）
2. **编辑已有值**：已勾选覆盖，显示项目配置值（可编辑）
3. **输入新值**：勾选覆盖，用户输入新值

### 3.2 数据结构（ExportConfigBuffer）

每个字段需要 3 个属性来支持三种状态：

### 3.3 UI 加载逻辑

```rust
fn load_export_buffer(
    raw_export: &Option<ExportConfig>,
    global_export: &Option<ExportConfig>,
) -> ExportConfigBuffer {
    let mut buf = ExportConfigBuffer::default();
    
    // 对每个字段（以 encoding 为例）：
    let project_value = raw_export.as_ref().and_then(|e| e.encoding.clone());
    let global_value = global_export.as_ref().and_then(|e| e.encoding.clone());
    let default_value = "utf-8";
    
    // 生效值 = 项目值 or 全局值 or 默认值
    let effective = project_value
        .clone()
        .or(global_value.clone())
        .unwrap_or_else(|| default_value.to_string());
    
    // override = 项目有显式设置
    let has_override = project_value.is_some() && !project_value.as_ref().unwrap().is_empty();
    
    buf.encoding = effective.clone();
    buf.encoding_original = effective;
    buf.encoding_override = has_override;
    
    // ... 其他 26 个字段类似
    
    buf
}
```

### 3.4 UI 交互逻辑

### 3.5 保存逻辑

```rust
fn save_export_config(buf: &ExportConfigBuffer, project_root: &Path) -> Result<()> {
    let mut raw = ProjectConfig::default();
    let mut export = ExportConfig::default();
    
    // 只保存勾选了 override 的字段
    if buf.encoding_override {
        export.encoding = Some(buf.encoding.clone());
    }
    
    if buf.line_ending_override {
        export.line_ending = Some(buf.line_ending.clone());
    }
    
    // ... 其他字段
    
    raw.export = Some(export);
    // raw.ui 和 raw.separators 保持为空（项目级不允许设置）
    
    // 1. 写入 project.toml
    write_to_project_toml(project_root, &raw)?;
    
    // 2. 更新内存中的 raw_config
    project.raw_config = raw;
    
    // 3. 重新合并生成新的生效配置
    project.config = merge_to_project_config(
        &engine.global_config,
        &project.raw_config,
        &project.schema.separators,
    );
    
    Ok(())
}
```

### 3.6 数据流总结

**启动时**：
```
tablet.toml → GlobalConfig → engine.global_config
project.toml → ProjectConfig → project.raw_config（仅 export 有值）
project.tblschema 的 # @sep 行 → schema.separators
merge(global, raw, schema.separators) → project.config（生效配置）
  - export: 合并后的最终值
  - ui: 来自 global
  - separators: 来自 schema（覆盖 toml 中的任何 [separators] 段）
```

**打开对话框**：
```
对比 raw_config 和 global_config
→ 判断每个字段是否项目覆盖
→ 设置 override 标记和显示值
→ 推送到 UI（81 个属性）
```

**用户编辑**：
```
勾选 override → 允许编辑当前值
取消勾选 → 恢复 original 值（删除覆盖）
清空输入 → 恢复 original 值
```

**保存**：
```
只保存 override=true 的字段到 project.toml
→ 更新 raw_config
→ 重新 merge 生成新的 config（生效配置）
```

**程序逻辑（导出操作）**：
```
直接使用 project.config（生效配置）
→ 已经是合并后的最终值，不需要再判断
```

## 注意事项

1. **字段验证**：路径字段需要验证是否合法
2. **默认值**：每个字段需要定义合理的默认值
3. **UI 性能**：81 个属性的绑定可能影响性能，需测试
4. **错误处理**：保存失败需要回滚内存状态
5. **合并顺序**：保存后必须先更新 `raw_config`，再重新 merge
