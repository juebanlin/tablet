## 2. Group 与 Excel 的对应关系

- 一个**文件夹** = 一个 **Group** = 一个 **Excel 文件**
- 文件夹内每个 `.tbl` 文件 = 一个 **Table / Constant / Enum** = Excel 中的一个 tab
- 用 Excel 编辑时整个 Group 生成一个 xlsx，每个配置项对应一个 tab（详见 @05）

Group 名仅在工具内部使用，不进生成代码路径，因此允许中文（@01.8.1、@04.1）。

## 4. tbl-tool.toml 配置

工具配置文件，定义项目目录、导出目标、UI 行为、类型分隔符。所有字段都有默认值，新建项目可只写少量字段。

### 4.1 完整示例

```toml
[project]
name = "game-config"
config_dir = "config"
cache_dir = ".tbl-cache"

[export]
encoding = "utf-8"
line_ending = "lf"

[export.json]
empty_as = "null"     # null / omit

[export.xml]
empty_as = "empty"    # empty / omit

[export.server]
data_output = "gen/server/data"

[export.server.java]
package = "com.game.config"
code_output = "gen/server/java"

[export.server.go]
package = "config"
code_output = "gen/server/go"

[export.client.lua]
output = "gen/client"

[ui]
auto_commit_on_blur = true
realtime_validate = false
log_level = "debug"

[separators]
Tuple2 = ","
Tuple3 = ","
Tuple4 = ","
List = ";"
Set = ";"

[separators.Map]
kv = ":"
entry = ";"

[separators.List_Tuple2]
tuple = ","
list = ";"

[separators.Map_Tuple2]
kv = ":"
tuple = ","
entry = ";"

[separators.Map_List]
kv = ":"
item = ","
entry = ";"
```

### 4.2 [project]

| 字段 | 说明 | 默认值 |
|------|------|--------|
| name | 项目名称 | — |
| config_dir | .tbl 文件所在目录（相对项目根） | — |
| cache_dir | 临时 xlsx 缓存目录 | `.tbl-cache` |

### 4.3 [export]（全局）

| 字段 | 说明 | 默认值 |
|------|------|--------|
| encoding | 生成文件编码 | utf-8 |
| line_ending | 换行符（lf / crlf） | lf |

子段（json/xml/server/client）可分别覆盖 `encoding` `line_ending`。

### 4.4 [export.json] / [export.xml]

| 字段 | 说明 | 默认值 |
|------|------|--------|
| empty_as | json: `null` / `omit`； xml: `empty` / `omit` | json=null； xml=empty |

空值策略详见 @01.8.4。

### 4.5 [export.server]

| 字段 | 说明 | 默认值 |
|------|------|--------|
| data_output | 后端数据文件目录（JSON/XML 共用） | — |

### 4.6 [export.server.java]

| 字段 | 说明 | 默认值 |
|------|------|--------|
| package | Java 包名 | — |
| code_output | Java 模板类输出目录 | — |

### 4.7 [export.server.go]

| 字段 | 说明 | 默认值 |
|------|------|--------|
| package | Go package | — |
| code_output | Go 代码输出目录 | — |

### 4.8 [export.client.lua]

| 字段 | 说明 | 默认值 |
|------|------|--------|
| output | Lua 文件输出目录 | — |

### 4.9 [separators]

按范式配置类型分隔符，详见 @01.7.4。

默认值覆盖绝大多数场景，仅当项目有历史数据使用不同分隔符时才需要修改。

`[separators]` 共 25 项 leaf（list / set / tuple2/3/4 / map.kv / map.entry / list_tuple{2,3,4}.{tuple,list} / map_tuple{2,3,4}.{kv,tuple,entry} / map_list.{kv,item,entry}）— 这套清单是**唯一真值源**，定义在 `crates/core/src/export/sep_meta.rs::sep_kv_pairs`，JSON `_sep` / XML `sep_*` attr / Go `SepConfig` / Java `SepConfig` 全部由此派生：

- 数据文件（JSON `_sep` / XML `sep_*` attr）：**按需输出** —— `paradigm_sep_keys` 列出每个范式用到的 leaf，扫表/常量字段 union 得到该文件需要的 key 集合，集合外的 leaf 不出。全 base 表 / 全 base + Ref 表（如纯 int/str/bool）`_sep` 整个省略。
- 生成代码（Go `templates/go/sep.go` / Java `templates/java/SepConfig.java`）：**保持 25 字段全量** —— 项目级共享一份 SepConfig 类，不同表用不同范式，按字段范式查 `SepConfig.listTuple2List` 等成员，不能裁剪。
- 消费端 `SepConfig.fillDefaults()`（Go）/ `getAny(..., default)`（Java）给缺失 key 兜底，所以数据文件省略 leaf 安全。

加新分隔符时，需要同步：(1) `SeparatorsSection` + serde rename；(2) `sep_kv_pairs` 顺序数组；(3) `paradigm_sep_keys` 映射表；(4) Go / Java 模板里的 SepConfig 字段及对应 fromMap / fromXMLAttrs 加载。`sep_meta.rs` 的 4 个 unit test 锁死前三处一致性 —— 漏改会立刻失败。

### 4.10 [ui]

| 字段 | 说明 | 默认值 |
|------|------|--------|
| auto_commit_on_blur | 点击空白区域时自动保存当前编辑 | true |
| realtime_validate | 编辑单元格时实时验证（关闭时仅保存前验证） | false |
| log_level | 日志级别（debug / info / warn / error） | debug |

#### 4.10.1 [ui.ref_picker]

| 字段 | 说明 | 默认值 |
|------|------|--------|
| default_strategy | Table 引用列展示默认策略：`auto`（id + 最多 2 辅助列） / `full`（除 export=- 外全部字段） | `"auto"` |

弹窗内可临时切换策略；每次重新打开都会回退到配置默认。Enum 引用永远固定 id/name/desc 三列，不受此配置影响。详见 @02.6.3。

#### 4.10.2 realtime_validate 行为

| 取值 | 单元格编辑时 | 保存时 |
|------|--------|--------|
| `false`（默认） | 不验证；红框只在保存校验失败后才出现 | 强制全量验证 |
| `true` | 每次单元格提交都立刻 revalidate 当前节点 | 同上 |

打开实时验证可以更早发现错误，但项目大时（>10 万条记录）每次按键提交都会触发 cell+row+schema 三层调用，可能感知到卡顿。校验逻辑详见 @01.8 与 @01 附录 A。

**与项目结构操作的关系**：新建 / 重命名 / 拷贝 / 删除节点 / 删除组等操作属于"项目结构变化"，**无论 `realtime_validate` 开关如何，都必然触发 `validation_errors` 索引的同步**（删除→清除残留 entries；重命名→平移 key；新建/拷贝→建立新索引）。这是为了保证 TreeSection 的 `!` 聚合标记不会因为索引滞留而错算。`realtime_validate` 只控制**单元格内容编辑**这条路径上的复算行为。

UI 上的视觉反馈（红框/树节点 `!` /日志框）见 @02.5.4。

## 6. 内部数据模型

工具运行时的内存结构，定义在 `crates/core/src/model.rs`。

```rust
pub struct Project {
    pub workdir: PathBuf,
    pub config: ProjectConfig,
    pub groups: Vec<Group>,
}

/// 一个 Group = config/ 下一个子目录 = 一个 Excel 文件
pub struct Group {
    pub name: String,
    pub dir: PathBuf,
    pub tables: Vec<Table>,
    pub constants: Vec<Constant>,
    pub enums: Vec<Enum>,
}

/// Table = 行列数据配置（@01.4.1）
pub struct Table {
    pub name: String,
    pub path: PathBuf,
    pub schema: TableSchema,
    pub record_count: usize,
}

pub struct TableSchema {
    pub fields: Vec<FieldDef>,  // 第一列固定为 id (主键)
}

pub struct FieldDef {
    pub name: String,
    pub desc: String,
    pub tbl_type: String,   // TblFieldType 字符串，详见 @01.7
    pub export: Export,
}

/// Constant = 离散常量配置（@01.4.2）
pub struct Constant {
    pub name: String,
    pub path: PathBuf,
    pub entries: Vec<ConstEntry>,
}

pub struct ConstEntry {
    pub name: String,
    pub tbl_type: String,
    pub value: String,
    pub export: Export,
    pub desc: String,
}

/// Enum = 枚举配置（@01.4.3）
pub struct Enum {
    pub name: String,
    pub path: PathBuf,
    pub entries: Vec<EnumEntry>,
}

pub struct EnumEntry {
    pub id: i64,
    pub name: String,
    pub desc: String,
}

pub enum Export {
    ClientServer,  // 前后端 → cs
    ClientOnly,    // 客户端 → c
    ServerOnly,    // 服务器 → s
    None,          // 不导出 → -
}
```

`FieldDef.tbl_type` / `ConstEntry.tbl_type` 字符串都是 [TblFieldType](01-tbl系统.md#7-tblfieldtype-类型系统)，工具内部解析为 `tbl_core::types::TblType` AST，详见 @01.7。

## 7. 节点状态与脏标记

每个节点（Group/Table/Constant/Enum）额外维护：

```rust
pub struct NodeState {
    pub original: Option<String>,  // 文件原始内容；None = 新建
    pub deleted: bool,             // 标记删除
    pub errors: Vec<NodeError>,    // 上次验证累积的错误
}
```

判定规则：

- `original = None` → 新建未保存
- 当前序列化 ≠ original → 脏（modified）
- `deleted = true` → 标记删除
- 改回 original 自动清除脏标记

UI 上的展示见 @02.2.2。

## 9. slint 实现细节坑点

slint 的声明式布局有几处与命令式 UI（egui / 原生 Win32）行为不同的地方，踩过的坑统一记在这里。

### 9.1 表头水平同步 / 行号垂直同步

**需求**：表头水平随数据 ScrollView 同步、垂直固定；行号列垂直随数据同步、水平固定。

**坑点**：slint 的 `ScrollView` 只能整体滚动，无法把"某列"或"某行"独立钉住。同时 `ScrollView` 嵌套互相同步 `viewport-x/y` 在 1.16 版本下不工作（事件不会冒泡）。

**做法**：单一数据 ScrollView 持有真值，header / 行号用 `clip: true` + 内层手动平移：

```slint
in-out property <length> scroll-x;   // root 持有真值
in-out property <length> scroll-y;

// 表头：clip 容器 + 内层 x: scroll-x
Rectangle {
    clip: true;
    Rectangle {
        x: root.scroll-x;            // 直接绑定（不要再取负）
        width: total-col-w;
        ...                          // header rows
    }
}

// 行号列：同样模式但绑 y
Rectangle {
    clip: true;
    Rectangle {
        y: root.scroll-y;
        height: total-rows-h;
        ...                          // row numbers
    }
}

// 数据 ScrollView：viewport-x/y 与 root 双向绑定
ScrollView {
    viewport-x <=> root.scroll-x;
    viewport-y <=> root.scroll-y;
    ...
}
```

`viewport-x` 在向右滚时本身就是负值，内层 `x` 直接绑 `scroll-x` 即可同方向，**不要再取一次负**。

### 9.2 layout 子元素禁止设置 x/y

`HorizontalLayout` / `VerticalLayout` 的直接子元素如果显式设置 `x:` 或 `y:`，编译报：

```
The property 'x' cannot be set for elements placed in this layout, because the layout is already setting it
```

所以"行号列固定不水平滚动"不能在数据 ScrollView 内的 row HorizontalLayout 里给 row-num 元素加 `x: -scroll-x` 抵消，必须把行号拆出 layout（如 §9.1 的独立 clip 容器）。

### 9.3 input property 不能在 callback 内赋值

```slint
in property <int> rp-strategy-index;
// set-strategy(i) => { root.rp-strategy-index = i; }   ← 编译报错
```

编译报 `Assignment on a input property`。需要把声明改成 `in-out property`，或用单独的 callback 让 Rust 端回写。

### 9.4 RefPicker 数据通道

弹窗的 search / manual / strategy 三个 in-out 属性都需要"slint 端写 + Rust 端立刻重 push"才能让筛选 / 列表跟着刷新。仅靠 in-out 双向绑定，slint 写完不会触发 Rust 重新计算 `rows`，列表就不动。所以三处都额外加了 callback：

```slint
edited(s) => { root.set-search(s); }   // 写值 + 通知 Rust
```

```rust
ui.on_rp_search_edited(move |q| {
    s.borrow_mut().ref_picker.search = q.to_string();
    if let Some(ui) = weak.upgrade() { push_ref_picker(&ui, &s); }
});
```

参考实现 `crates/app-slint/src/main.rs::wire_ref_picker`。
