# 二进制导出（C# / Unity）

> 状态：**已实现 v1**。源格式仍是 `.tbl` / `.tblschema`；二进制只是派生数据，不进 Git。

## 1. 目标

Unity（APK / 微信小程序 / 抖音小程序，IL2CPP / WebGL）在启动时解析 JSON 慢、分配大。
本功能把配置导出成按列组织的二进制，读取端按 schema 直接访问，避免 JSON 文本解析与大量临时字符串。

当前支持：

- 数据：**Table + Constant**；Enum 没有数据文件，不参与；
- 代码读取器：**C#（dotnet / Unity）**；其它语言暂不提供二进制 reader；
- 复合类型（Tuple / List / Set / Map / 嵌套）v1 仍按原文本编码，读取端用生成代码里的
  `TblParse` 解析；标量列已经是定长数组，可零拷贝扫描。

## 2. 导出命令

```bash
# 整个项目一个包：<data_output>/bin/config.bytes
tablet-cli --project P export data --bin

# 每节点一个文件：<data_output>/bin/parts/<Node>.bytes
tablet-cli --project P export data --bin-split

# 两种同时生成（互不覆盖）
tablet-cli --project P export data --bin --bin-split
```

- 二进制与 JSON/XML 可以同一次导出并存；
- `--bin` 只生成 bundle，`--bin-split` 只生成分部；都不指定 `--json/--xml` 时默认仍是 JSON；
- 文件扩展名使用 `.bytes`：Unity 的 `Resources` 会把它导入成 `TextAsset`；
- 目录同步会清理不再生成的 `.bytes`，但 bundle 与 `parts/` 分开存放，互不删除。

GUI（Tauri）导出对话框同样支持：勾选「BIN 数据（整包）」/「BIN 数据（按节点拆分）」；
「全部」「数据」预设包含整包，新增「二进制」预设只选整包。输出根仍是「项目设置 → 导出 → 服务端数据输出目录」。

## 3. 磁盘布局

```text
<data_output>/bin/
├── config.bytes              # 整项目 bundle（节点名 → payload）
└── parts/
    ├── Item100k.bytes        # 单节点 payload（与 bundle 里的内容格式一致）
    └── AllTypes.bytes
```

两种布局的节点 payload **完全同构**，读取器用同一个 `TblBinTable`。

## 4. 格式 v1（little-endian）

### 4.1 单节点 payload

```text
magic "TBLB" | version u16=1 | kind u16 (0=table, 1=constant)
col_count u16 | row_count u32 | schema_hash u64
sep_count u16 | [key str, value str]...
每列: name str | type str | tag u8 | offset u64 | len u64
数据区（列式）:
  int32 / int64 / float32 / float64: 定长数组
  bool: 每行 1 字节
  string / raw: (row_count+1) 个 u32 偏移 + UTF-8 blob
```

- `str` = `u16 长度 + UTF-8`；
- `schema_hash` = FNV-1a 64（节点名 + kind + 列名 + 列类型 + tag），读取端校验；
- 列 offset 是绝对文件偏移；bundle 里的 payload 由读取器按 `(offset,len)` 切片，不复制；
- Constant 固定 5 列字符串：`name / type / value / export / desc`。

### 4.2 bundle

```text
magic "TBLB" | version u16=1 | kind u16=2
node_count u16 | [name str, offset u64, len u64]...
payload...
```

`offset` 指向整个 bundle 内的 payload 起点；多个 bundle/单文件可以任意组合加载。

## 5. C# 读取器

生成的 `TblBin.cs` 提供：

```csharp
var bundle = TblBinBundle.Load("config.bytes");          // 或 LoadFromBytes(byte[])
bundle.TryGetTable("Item100k", out var t);

int row = t.RowCount;
var ids = t.Int32Span(0);                                 // 零拷贝
string name = t.GetString(1, 10);
int hp = t.GetInt32(2, 10);
```

生成的 `Loader.cs`：

```csharp
Loader.LoadAllBin("ConfigData");                    // Unity: Resources 子目录
Loader.LoadAllBin("config.bytes");                  // dotnet: 文件
Loader.LoadAllBin("parts");                         // 目录：无 bundle 时逐个 .bytes
Loader.LoadAllBin("config.bytes", "extra.bytes");   // 多来源聚合
// Loader.LoadBin(...) 是同一入口的别名
```

聚合语义：

- 多个来源按参数顺序加载；
- 同一张表：后读到的行覆盖同 id，新 id 追加（不清空已有数据）；
- 常量：后读到的整体覆盖先读到的；
- 目录里同时有 `config.bytes` 和 `parts/` 时，目录入口优先 bundle；需要合并时显式传文件。

## 6. Unity 示例

生成的 `BinExample.cs`（仅 `--csharp-unity`）：

```csharp
// 整包
Loader.LoadAllBin("ConfigData");   // Assets/Resources/ConfigData/config.bytes

// 单个表（分包 / Addressables）
var ta = Resources.Load<TextAsset>("ConfigData/parts/Item100k");
Loader.LoadAllBin(ta);

// 零拷贝扫列
var bundle = TblBinBundle.LoadFromBytes(ta.bytes);
bundle.TryGetTable("Item100k", out var t);
foreach (var id in t.Int32Span(0)) { ... }
```

- APK / 小程序：`Resources` 或 Addressables 均可；小程序建议按表拆包，启动只加载基础包；
- `Resources.Load<TextAsset>` 的路径不带扩展名（`Item100k` 对应 `Item100k.bytes`）。

## 7. 老 Unity / 不支持 Span

默认读取器使用 `BinaryPrimitives` + `MemoryMarshal`（Unity 2021.2+ / .NET Standard 2.1）。

老版本或转译环境在 **Player Settings → Scripting Define Symbols** 加：

```text
TBLBIN_NO_SPAN
```

- 读取改为 `BitConverter` 手工读取（Unity 全平台小端，语义一致）；
- `Int32Span` 等零拷贝 API 不参与编译，改用 `GetInt32(col,row)` 循环；
- 格式与 `Loader` API 不变。

## 8. 实测（桌面 .NET 10，仅作相对参考）

数据：10 万行 × 20 列道具表 + 271 项覆盖全部类型的全局常量。

| 模式 | 耗时 | 分配 | 加载后堆 |
|---|---:|---:|---:|
| JSON | 1877.8 ms | 915 MB | 678 MB |
| BIN bundle（物化对象） | 516.8 ms | 242 MB | 129 MB |
| BIN 多文件（物化） | 524.6 ms | 242 MB | 114 MB |
| BIN 多来源聚合（bundle + 单文件） | 510.1 ms | 257 MB | 127 MB |
| BIN 零拷贝扫列 | 15.9 ms | 21 MB | — |
| BIN bundle（`TBLBIN_NO_SPAN`） | 486.9 ms | 242 MB | 129 MB |

体积：Item100k JSON 45.6 MB → `.bytes` 13.9 MB；整包 JSON 72.9 MB → `config.bytes` 22.1 MB。

WASM/IL2CPP 真机数值会不同，但“少文本解析、少分配”的相对收益保留；上线前需在
微信/抖音小程序真机测端到端（分包下载 + 解压 + TextAsset 加载 + 首次访问）。

## 9. 限制 / 后续

- v1 复合类型仍是原文本；后续可把 List/Tuple/Map 结构化编码，进一步减少解析；
- 只提供 C# reader；TS/Java/Go 需要时再按同一格式生成；
- 二进制产物不进 Git，由 `export` 生成；schema 变化后必须重新导出（hash 不匹配会直接抛错）。
