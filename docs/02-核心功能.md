# 核心功能

本文档描述**核心层**（数据子系统）能力：在 .tbl 数据模型之上、**不依赖 UI** 即可完整运行的所有功能。CLI 模式（`tbl-cli`）是这些核心功能的薄入口，与 GUI 共享同一份 `tbl-core`。

涵盖范围：

| 类别 | 子项 |
|------|------|
| 项目与模板 | Project 目录结构 / .tblschema 模板（内置 + 本地 + 网络）/ 模板实例化 |
| 导出（核心 → 外部） | JSON / XML / xlsx / Java / Go / Lua |
| 导入（外部 → 核心） | xlsx → 内存模型（待开发，对应 UI 的 Excel 桥接 @06） |
| 验证 | 全项目离线校验，CI 友好 |
| 测试数据生成 | 内置 / 外部 schema 灌随机或空数据，便于压测和 review |

UI 端（@04-UI 设计 / @05-UI 平台）只是核心层的展示前端之一；CLI 是另一个等价前端。

## Project（项目）

一个 Project = 一份独立的配置数据集。同一仓库可并存多个 Project（如 `slg-test` / `slg-prod` / `mini-game`），各自隔离的 schema + 数据 + 元数据。UI 一次性加载所有 Project 同时展示在 TreeSection 顶层（@04.2.0），跨 Project 直接通过右键复制/粘贴迁移节点。

### 目录结构

```
<repo-root>/
├── tbl-tool.toml                       ← 仓库全局配置（所有 Project 共享）
└── projects/
    ├── slg-test/                       ← Project ID（[a-z0-9_-]{1,32}）
    │   ├── project.toml                ← Project 元数据（[project]）+ 可选配置覆盖（[export]/[ui]/[separators]）
    │   ├── project.tblschema           ← 该 Project 的结构定义（多表合并）
    │   ├── config/                     ← 数据文件（.tbl）—— 当前 Project 范围内的源
    │   │   ├── hero/HeroBase.tbl
    │   │   ├── hero/HeroType.tbl
    │   │   └── global/GlobalConst.tbl
    │   └── .tbl-cache/                 ← Excel 桥接缓存（.gitignore，详见 @06）
    │       └── hero.xlsx
    ├── slg-prod/
    │   └── ...
    └── mini-game/
        └── ...
```

`project.toml` 字段：

```toml
[project]                           # 必有：Project 元数据
id = "slg-test"
name = "SLG 测试配置"
created_at = "2026-05-31T10:00:00Z"
source_template = "full"             # 来源模板 id（手动新建可省）
source_template_version = "1.0.0"

# 以下为可选段：覆盖仓库级 tbl-tool.toml 同名段（field-level deep merge）
# [export.server.java]
# package = "com.slg.test"
# code_output = "gen/slg-test/java"
# [ui]
# log_level = "info"
```

加载顺序：项目 toml > 全局 toml > 内置默认；缺失字段回退到上一级。

### 全局配置 vs Project 元数据

| 文件 | 范围 | 内容 |
|------|------|------|
| `<repo-root>/tbl-tool.toml` | 仓库全局 | 类型分隔符、导出路径、UI 偏好、`[app] last_project` 记录上次进入的 Project |
| `projects/<id>/project.toml` | 单个 Project | 该 Project 的 id / name / 来源模板信息 + 可选 `[export]` / `[ui]` / `[separators]` 覆盖段 |

`projects/` 下的 Project 列表由启动时扫描得出，**不需要**在 `tbl-tool.toml` 里枚举。详见 @07.4。

### 多 Project 同时管理

UI 一次性加载 `<repo-root>/projects/` 下**全部** project，TreeSection 顶层节点 = 每个 project 根（@04.2.0）；CLI 用 `--project <id>` 限定操作范围（list / export / new-project）。**不存在"切换 project"概念**——所有 project 始终在内存里，跨 project 复制/粘贴节点直接通过右键即可。

| 维度 | 行为 |
|------|------|
| 节点定位键 | `(project_id, group, name)` 三元组，`ProjectEngine.find_table` / `validation_errors` 等都按该键索引 |
| 引用范围 | `@TableName` / `@EnumName` 仅在同 project 的 `groups` 内解析；跨 project 引用产生验证错误 |
| 跨 project 节点迁移 | 右键复制 → 切到目标 project 的节点上右键粘贴；`@ref` 字段保持原值，未在目标 project 解析时按验证错误暴露 |
| 启动展开策略 | 仅 `tbl-tool.toml [app].last_project` 指向的 project 默认展开，其它 project 折叠；展开状态会话内有效（不持久化） |
| 新建 group / table 落点 | 默认落到选中节点所在 project；空选时落第一个 project；project 根节点右键「新建 Group」可显式选 project |

`ProjectEngine` 持有 `Vec<Project>`，每个 `Project` 自带独立的 `project_root` / `config` / `instance_meta` / `groups`。`[app].last_project` 字段语义降级为"启动展开偏好"——仍写入但不再控制"切到哪个 project"。

### Project 保存 / 导出

| 入口 | 范围 |
|------|------|
| 工具栏 [保存] | 一键落盘所有脏 project |
| 工具栏 [导出] | 全部 project 各走自己的 `export_root`（多 project 模式下每个 project 各自隔离 `gen/`） |
| Project 根节点右键「保存此 project」 | 仅落盘该 project 的脏改 |
| Project 根节点右键「导出此 project」 | 仅导出该 project |

### ProjectEngine 路径解析

每个 `Project` 持有 `project_root: PathBuf`（指向 `projects/<id>/`），不再绑定仓库级 `config_dir`。所有路径基于该 root：

| 资源 | 路径 |
|------|------|
| schema | `<root>/project.tblschema` |
| 数据目录 | `<root>/config/` |
| 元数据 | `<root>/project.toml` |
| Excel 缓存 | `<root>/.tbl-cache/` |

### 老结构迁移

老仓库的根目录 `config/` 在新版本启动时**自动迁移**到 `projects/default/`：

- 移动 `config/` → `projects/default/config/`
- 把仓库内已有的 `*.tblschema`（如有）合并为 `projects/default/project.tblschema`
- 生成 `projects/default/project.toml`（id=`default`，name=`默认项目`）
- 在 `tbl-tool.toml` 写入 `[app] last_project = "default"`

迁移一次性完成，不保留双结构；废弃根 `config/` 路径。

## 项目模板（Schema Template）

**项目模板** = `.tblschema` 文件，描述一份 Project 的结构（不含数据）。新建 Project 时从模板库选一个模板，工具按 schema **实例化**空的 `.tbl` 文件集合。

### 模板格式

`.tblschema` 文件的完整规则在 @01.10。要点：

- 头部 `# @meta key: value` 注释行提供模板元数据：`id`（路径标识 `[a-z0-9_-]{1,32}`）/ `name`（显示文本，含中文）/ `category`（分类筛选，如 test / slg / rpg）/ `version`（semver）
- 主体：多个 `[group/Name] mode` 段，每段下接字段定义行
- **模板不含数据**——只描述结构（Enum 段直接含枚举条目，因为枚举值就是 schema 的一部分）

### 模板来源

工具支持三种模板源，统一通过 `TemplateSource` trait 访问：

| 来源 | 实现 | 路径 / 取得方式 | 加载时机 |
|------|------|---------------|---------|
| 内置（Builtin） | `BuiltinTemplates` | 编译时 `include_str!("../schemas/*.tblschema")` | 永远存在 |
| 本地（Local） | `LocalTemplates` | 程序根目录 `<binary-dir>/tblschema/` 下的任意 `.tblschema` | 启动扫描 |
| 网络（Remote） | `RemoteTemplates` | GitHub registry index.json + 各 .tblschema 拉到本地缓存 | 按需下载（@08 S15-H 后置）|

接口：

```rust
trait TemplateSource {
    fn list(&self) -> Vec<TemplateMeta>;          // 列出该源的全部模板（不读 body）
    fn load_by_id(&self, id: &str) -> Option<TemplateContent>;
}
```

### 内置模板

`crates/core/schemas/{full,empty}.tblschema` 通过 `include_str!` 嵌入二进制，`build.rs` 把 `schemas/` 加进 rerun-if-changed。两套内置模板：

| id | 用途 |
|----|------|
| `full` | 完整结构演示（所有类型 / 所有 mode），generate-test 默认源、回归测试驱动 |
| `empty` | 极简空骨架（一两张表 + 一个常量集），供"空 Project"起步 |

后续可扩展（如 `slg-base` / `rpg-base`）：文件直接放进 `crates/core/schemas/`，build.rs 自动重编。

### 本地模板

`<binary-dir>/tblschema/` 目录下任意 `.tblschema` 文件——启动时扫描列表，metadata 不全的按文件名兜底（@01.10.1）。用户拷贝文件即可扩展模板库，不依赖工具版本，社区分享友好。

### 模板实例化

`instantiate_template(schema, target_dir)` 把 schema 翻译为空 `.tbl` 文件集合，写入 target_dir：

| schema 段 | 输出 |
|-----------|------|
| `[group/Name] table` | `<target>/config/<group>/<Name>.tbl`：写好 `#!tbl v2` / `#mode table` / `#desc` / `#export` / `#type` / `#field` / `---`，**数据行为空** |
| `[group/Name] constant` | `<target>/config/<group>/<Name>.tbl`：写好 `#!tbl v2` / `#mode constant` / `---`，每条常量行 `name | type | <empty value> | export | desc` |
| `[group/Name] enum` | `<target>/config/<group>/<Name>.tbl`：写好 `#!tbl v2` / `#mode enum` / `---`，**枚举条目直接写入**（来自 schema） |

同时把 schema 自身（去掉 `# @meta` 头）拷贝为 `<target>/project.tblschema`，作为该 Project 的结构定义。

实例化失败（schema 解析错误 / 目标目录非空）就报错回滚，不写半成品。

### 导出当前 Project 为模板

工具栏「导出为模板」入口（@04.6.7）：

1. 弹窗勾选要导出的 group / 节点
2. 编辑模板 metadata（id / name / category / version，预填项目 meta）
3. 选输出位置（默认 `<binary-dir>/tblschema/<id>.tblschema`）
4. 写出 `.tblschema`：合并所选段为一份 schema，加 `# @meta` 头

输出后自动出现在「本地」模板 tab，下次新建 Project 即可选用。

### CLI 入口

```bash
tbl-cli list-templates                                       # 列出内置 + 本地模板
tbl-cli list-projects                                        # 扫描 projects/ 列出全部 Project
tbl-cli new-project --template full --id slg-test            # 用模板新建 Project
                    --name "SLG 测试配置"
tbl-cli migrate-legacy                                       # 把根目录 config/ 迁移到 projects/default/
tbl-cli --project slg-test export                            # 用 --project 显式选要导出的 Project（不传 = 全部）
```

> CLI 端没有"切换"概念；`--switch-after` 标志已废弃。`new-project` 会更新 `[app].last_project` 到新 project（仅作为下次启动的展开偏好），但不影响其它 project 的存在。

GUI 端弹窗（@04.6.6 / @04.6.7）共享同一套底层逻辑。

## 目录扁平化

**Group 仅工具内部使用**（树形导航 + `projects/<id>/config/<group>/` 子目录）。**生成产物不保留 group 层级**，所有配置项扁平输出。

| 产物类型 | 路径 | 说明 |
|---------|------|------|
| JSON 数据 | `gen/server/data/json/HeroBase.json` | 不分 group 子目录 |
| XML 数据 | `gen/server/data/xml/HeroBase.xml` | 同上 |
| Java Tpl | `gen/server/java/com/game/config/tpl/HeroBaseTpl.java` | 集中到 `tpl/` 子包 |
| Java 框架 | `gen/server/java/com/game/config/{ITpl,TplHolder,...}.java` | 框架与 Tpl 物理隔离 |
| Go | `gen/server/go/config/hero_base_tpl.go` | flat package（已有） |
| Lua | `gen/client/HeroBase.lua` | 不分 group 子目录 |

理由：
- 生成代码是给程序员消费的，他们只关心 `import HeroBaseTpl`，不关心配置工具里这个表归在哪个 group
- 配置项跨组唯一（验证规则保证），扁平后无命名冲突
- Group 不进入生成路径 → group 名允许包含中文（不会破坏 Go package / Java import）

registry key 同步简化：从 `"hero/HeroBase"` → `"HeroBase"`（与文件名一致）。

## 导出选项

导出分为六个独立操作，可自由组合执行：

| 选项 | 说明 | 默认输出目录 | 状态 |
|------|------|-------------|------|
| JSON | 将 .tbl 数据导出为 JSON | gen/server/data/json/ | ✅ |
| XML | 将 .tbl 数据导出为 XML（JDK 7+ 原生解析） | gen/server/data/xml/ | ✅ |
| xlsx | 每 Group 一个 xlsx，用 Excel 编辑 / 审阅 / 配色 | gen/excel/ | ⚠️ 待开发 |
| Java | 生成 Java 接口 + Tpl 类 + TplHolder | gen/server/java/ | ✅ |
| Go | 生成 Go 结构体 + 加载框架 | gen/server/go/ | ✅ |
| Lua | 生成 Lua 文件，数据内嵌，require 即用 | gen/client/ | ✅ |

枚举（mode=enum）**不参与数据文件导出**——枚举内容固定写死在 Java/Go/Lua 生成代码里，不需要数据文件。

以上目录为默认值，可在 tbl-tool.toml 中修改：

```toml
[export]
encoding = "utf-8"       # 全局默认编码
line_ending = "lf"       # 全局默认换行符

[export.json]
empty_as = "null"
# line_ending = "lf"     # 可选，覆盖全局
# encoding = "utf-8"     # 可选，覆盖全局

[export.xml]
empty_as = "empty"
# line_ending = "lf"
# encoding = "utf-8"

[export.server]
data_output = "gen/server/data"
# line_ending = "lf"     # server 层级默认值
# encoding = "utf-8"

[export.server.java]
package = "com.game.config"
code_output = "gen/server/java"
# line_ending = "lf"     # 可选，覆盖 server → export
# encoding = "utf-8"

[export.server.go]
package = "config"
code_output = "gen/server/go"
# line_ending = "lf"
# encoding = "utf-8"

[export.client.lua]
output = "gen/client"
# line_ending = "lf"
# encoding = "utf-8"
```

编码和换行符的 fallback 链：各部分独立配置 > 上级节点（如 `[export.server]` / `[export.client]`）> `[export]` > 默认值（lf + utf-8）。

UI 上提供：
- "全部导出"按钮 — 一键执行三项
- 菜单中可单独选择某一项执行

## JSON 导出策略

JSON 数据文件包装为 `{"_sep": {...}, "data": [...]}` 结构，`_sep` 嵌入项目的分隔符配置供 Java 端解析复合类型。

**按需输出**：`_sep` 只包含该表/常量**实际用到**的分隔符 key（按字段范式聚合），跟字段无关的 leaf 不输出。全 base 表（无 List/Set/Map/Tuple/复合）直接**省略 `_sep` key**，文件就是 `{"data": ...}`。消费端模板的 `SepConfig.fillDefaults()` 给缺失的 key 兜底默认值，省略安全。

基础类型（int/long/float/double/bool）输出为 JSON 原生类型，复合类型（List/Set/Map/Tuple）保持原始分隔符字符串形式。

空值策略通过 `[export.json] empty_as` 配置：

| 策略 | 行为 | 示例 |
|------|------|------|
| `null`（默认） | 空值字段输出为 JSON null | `{"id":1, "hp":null}` |
| `omit` | 空值字段不写入 JSON | `{"id":1}` |

## XML 导出策略

XML 数据文件使用原生 JDK DOM API 可解析的格式（JDK 7+ 零依赖）。分隔符配置嵌入根元素属性，attr 名 = `"sep_" + json_key`。

**按需输出**：与 JSON 同语义——根元素只挂该表/常量**实际用到**的 `sep_*` attr，全 base 表根元素**完全不带 sep_ attr**。

空值策略通过 `[export.xml] empty_as` 配置：

| 策略 | 行为 | 示例 |
|------|------|------|
| `empty`（默认） | 空值字段输出为空元素 | `<hp></hp>` |
| `omit` | 空值字段不输出 | 无该元素 |

## 代码模板加载策略

生成的 Java/Go 代码加载 JSON 时，对空值（null 或字段缺失）统一按**默认值策略**处理：

| 类型分类 | 空值处理 | Java | Go |
|---------|---------|------|----|
| 基础类型 | 零值 | int=0, boolean=false, String="" | int32=0, bool=false, string="" |
| 集合类型 | 空集合 | new ArrayList<>() | []T{} |
| 元组类型 | 不会出现 | — | — |

- 不使用包装类型（Integer/*int），字段永远有值，业务代码无需判空
- 元组类型由验证层保证非空，加载时不需要处理空值情况
- 详见 [@01.8.4 空值规则](01-tbl系统.md#84-空值规则)

## 命名规则

生成的类名/文件名与 .tbl 文件名一致，使用**大写驼峰**（Tpl 后缀仅 Table/Constant；Enum 用 Enum 后缀）：

| .tbl 文件名 | Java 类名 | Go 文件名 | Lua 文件名 | JSON | XML |
|-------------|-----------|-----------|------------|------|-----|
| HeroBase.tbl (table) | HeroBaseTpl | hero_base_tpl.go | HeroBase.lua | HeroBase.json | HeroBase.xml |
| GlobalConst.tbl (constant) | GlobalConstTpl | global_const_tpl.go | GlobalConst.lua | GlobalConst.json | GlobalConst.xml |
| HeroType.tbl (enum) | HeroTypeEnum | hero_type_enum.go | HeroType.lua | — | — |

## 导出规则

JSON 数据文件和后端模板类是给 server 用的，仅包含"前后端"和"服务器"标记的字段。Lua 前端文件直接从 .tbl 读取生成，仅包含"前后端"和"客户端"标记的字段。

| export 标记 | 数据文件 (JSON/XML) | 后端模板类 (Java/Go) | 前端文件 (Lua) |
|-------------|---------------------|---------------------|----------------|
| 前后端 | 生成 | 生成 | 生成 |
| 服务器 | 生成 | 生成 | 跳过 |
| 客户端 | 跳过 | 跳过 | 生成 |
| 不导出 | 跳过 | 跳过 | 跳过 |

枚举（mode=enum）的所有条目对所有目标语言生成（条目无 export 标记）。

## 导出粒度控制

CLI 支持按格式独立导出，可任意组合：

```bash
tbl-cli export                    # 全部导出（JSON + XML + Java + Go + Lua；xlsx 待开发后并入）
tbl-cli export --json --lua       # 只导出 JSON + Lua
tbl-cli export --java             # 只导出 Java 模板类
tbl-cli export --go               # 只导出 Go 模板代码
tbl-cli export --lua              # 只导出 Lua 前端文件
tbl-cli export --xlsx             # 只导出 xlsx（每 Group 一个文件，待开发）
```

无 flag = 全部导出。指定 flag = 只导出对应部分。

`-w <workdir>` 默认当前目录；`-s key=value` 覆盖 `tbl-tool.toml` 任意配置项（@07.4），可重复指定。覆盖键名与 toml 路径一一对应（如 `export.server.java.package`、`export.client.lua.output`）。

## 导出产物同步

每次导出时，工具对比生成目录中已有文件和本次应生成的文件，自动同步：

| 状态 | 含义 | 操作 |
|------|------|------|
| 新增 | 之前不存在的文件 | 写入 |
| 修改 | 内容有变化 | 覆盖 |
| 不变 | 内容相同 | 跳过 |
| 删除 | 目录中存在但本次不再生成（.tbl 已删除/重命名） | 删除文件 |

### CLI 行为

默认删除多余文件，打印变化日志：

```
[JSON] 2 新增, 1 修改, 1 删除, 3 不变
  [新增] gen/server/data/json/hero/HeroSkill.json
  [修改] gen/server/data/json/hero/HeroBase.json
  [删除] gen/server/data/json/hero/OldTable.json
```

不变的文件不打印。

### UI 行为

弹窗展示变化列表（新增/修改/删除），确认后执行。操作日志窗口记录导出详情。

### 清理范围

- 只对**本次实际执行的导出格式**做残留检测
- 例如只导出 `--lua`，不会清理 JSON/XML/Java 目录
- 所有文件参与检测（包括框架文件如 ITpl.java、TplHolder.java）
- 同步后自动清理空目录

### 接口定义

接口放在 package 根目录：

**ITpl.java：**

```java
package com.game.config;

public interface ITpl {
```

**IConstTpl.java：**

```java
package com.game.config;

public interface IConstTpl {
}
```

### types 子包 — 自定义类型实现

**IntPair.java：**

```java
package com.game.config.types;

public class IntPair {

        this.first = first;
        this.second = second;
```

### Table 模式 → Tpl 实体类

放在 `tpl/` 子包，实现 `ITpl`，类级 `@TblSource` 标识来源（含 group 元信息），字段级 `@TblFieldType` 描述 [@01.7 TblFieldType](01-tbl系统.md#7-tblfieldtype-类型系统)：

**HeroBaseTpl.java：**

```java
package com.game.config.tpl;

import com.game.config.ITpl;
import com.game.config.TblFieldType;
import com.game.config.TblSource;

@TblSource(group = "hero", name = "HeroBase", mode = "table")
public class HeroBaseTpl implements ITpl {
    @TblFieldType("int")
    private int id;
    @TblFieldType("str")
    private String name;
    @TblFieldType("int")
    private int hp;
    @TblFieldType("List<int>")
    private List<Integer> skills;

    @Override
    public int getId() { return id; }
    public String getName() { return name; }
    public int getHp() { return hp; }
    public List<Integer> getSkills() { return skills; }
}
```

`@TblSource` 的 `group` 字段保留 group 元信息（业务/工具可反射查询来源），但**不影响**类的 package 路径。

### Constant 模式 → Tpl 常量类

同样放在 `tpl/` 子包，实现 `IConstTpl`。

**Table 行 vs Constant 项 → Tpl 类的统一视角**

两种模式最终都生成一个 Tpl 实体类，区别只是「类的属性怎么来」：

| 模式 | 类的来源 | 属性的来源 |
|------|---------|------------|
| Table | 一张 `.tbl` 表 → 一个 `XxxTpl` 类 | 表的每一**列**（`FieldDef`）→ 一个 Java 字段 |
| Constant | 一个 `.tbl` 常量集 → 一个 `XxxTpl` 类 | 常量集的每一**行**（`ConstEntry`）→ 一个 Java 字段 |

字段级注解都用 `@TblFieldType("...")`，值就是 [@01.7 TblFieldType](01-tbl系统.md#7-tblfieldtype-类型系统) 字符串。运行时 `TplHolder` 反射拿这个注解 + `TplUtil.parseField()` 把字符串值解析为目标 Java 类型。

**GlobalConstTpl.java：**

```java
package com.game.config.tpl;

import com.game.config.IConstTpl;
import com.game.config.TblFieldType;
import com.game.config.TblSource;

@TblSource(group = "global", name = "GlobalConst", mode = "constant")
public class GlobalConstTpl implements IConstTpl {
    @TblFieldType("int")
    private int maxLevel;
    @TblFieldType("Tuple2<int,int>")
    private Tuple2<Integer, Integer> startPos;

    public int getMaxLevel() { return maxLevel; }
    public Tuple2<Integer, Integer> getStartPos() { return startPos; }
}
```

字段名转换规则：.tbl 中的 snake_case（`max_level`）→ Java 中的 camelCase（`maxLevel`）。

### TplHolder — 统一查询入口

放在 package 根目录。TplHolder 通过静态 registry 注册所有 Tpl 类（由工具生成时写入），启动时扫描 dataDir 下的数据文件按需加载。

- `init(dataDir)` — 加载 XML 数据文件（默认）
- `initJson(dataDir)` — 加载 JSON 数据文件

字段值统一以字符串形式从数据文件读取，通过 `@TblFieldType` 注解 + `TplUtil.parseField()` 解析为目标类型。

**TplHolder.java：**

```java
package com.game.config;

import com.game.config.tpl.*;
import java.util.Map;
import java.util.HashMap;

public class TplHolder {
    private static final Map<String, Class<?>> registry = new HashMap<>();

    static {
        registry.put("HeroBase", HeroBaseTpl.class);
        registry.put("GlobalConst", GlobalConstTpl.class);
    }

    public static void init(String dataDir) { /* 扫描 .xml 文件 */ }
    public static void initJson(String dataDir) { /* 扫描 .json 文件 */ }

    public static <T extends ITpl> T get(Class<T> clazz, int id) { ... }
    public static <T extends ITpl> Map<Integer, T> getAll(Class<T> clazz) { ... }
    public static <T extends IConstTpl> T getConst(Class<T> clazz) { ... }
}
```

registry key 是配置项名（与数据文件名一致），不含 group 前缀。

**业务使用示例：**

```java
import com.game.config.TplHolder;
import com.game.config.tpl.HeroBaseTpl;
import com.game.config.tpl.GlobalConstTpl;
// 或一次性 import com.game.config.tpl.*;

// XML 数据（默认）
TplHolder.init("config/server/data");

// 或 JSON 数据
TplHolder.initJson("config/server/data");

HeroBaseTpl hero = TplHolder.get(HeroBaseTpl.class, 1001);
GlobalConstTpl consts = TplHolder.getConst(GlobalConstTpl.class);
```

## 生成后端模板代码（Go）

Go 后端生成 **flat package**：所有文件平铺在 `[export.server.go] code_output` 指向的目录下，包名取自 `[export.server.go] package`。零反射，每张表/常量生成专用 `Get` 函数。

### Java vs Go：范式绑定的两条路线

两边都需要把 [@01.7 TblFieldType](01-tbl系统.md#7-tblfieldtype-类型系统) 字符串变成针对每个字段的解析逻辑，但绑定时机完全不同：

| 维度 | Java（运行时反射 + 注解驱动） | Go（编译期展开，无注解） |
|------|------------------------------|--------------------------|
| 范式信息载体 | `@TblFieldType("Tuple2<int,int>")` 字段注解 | Rust 生成器把范式直接翻成 Go 语句 |
| 解析时机 | 运行时反射读注解 → `TplUtil.parseField(raw, ann.value(), sep)` 通用解析 | 生成时已展开为定型表达式（`parseInt32` / `parseListInt32(raw, sep.List)` …） |
| 字段级范式标记 | 注解（参与运行时） | 行尾 `// int` 注释（仅给人看，运行时无意义） |
| 反射依赖 | 是 | 否 |
| 装箱 | 是（`List<Integer>`） | 否（`[]int32`） |
| 加新范式时改的位置 | `TplUtil.parseField` 一处 | Rust `parse_expr_for` + 生成的所有 .go 文件重新生成 |

两边产物在业务逻辑上**等价**，只是范式 → 解析代码的转换发生在不同阶段。

**Java：注解 = 数据**

```java
public class HeroBaseTpl implements ITpl {
    @TblFieldType("List<int>")
    private List<Integer> skills;
}

// 运行时：
TblFieldType ann = field.getAnnotation(TblFieldType.class);
field.set(obj, TplUtil.parseField(raw, ann.value(), sep));
```

**Go：范式 = 生成时已固化的语句**

```go
type HeroBaseTpl struct {
    Skills []int32 // List<int>   ← 注释，运行时无作用
}

func parseHeroBase(row map[string]string, sep SepConfig) *HeroBaseTpl {
    obj := &HeroBaseTpl{}
    if raw, ok := row["skills"]; ok && raw != "" {
        obj.Skills = parseListInt32(raw, sep.List)   // ← 范式编译期就定了
    }
    return obj
}
```

引用类型同理：Java 用 `@TblFieldType("@HeroType")` 反射判断 `field.getType().isEnum()` 调 `fromId`；Go 直接生成 `obj.Type = HeroTypeEnum(parseInt32(raw))`。

### Table 模式 → Tpl 结构体

**hero_base_tpl.go：**

```go
package config

type HeroBaseTpl struct {
    Id     int32   // int
    Name   string  // str
    Hp     int32   // int
    Skills []int32 // List<int>
}

var HeroBase_data = map[int32]*HeroBaseTpl{}

func parseHeroBase(row map[string]string, sep SepConfig) *HeroBaseTpl {
    obj := &HeroBaseTpl{}
    if raw, ok := row["id"]; ok && raw != "" {
        obj.Id = parseInt32(raw)
    }
    if raw, ok := row["name"]; ok && raw != "" {
        obj.Name = parseStr(raw)
    }
    if raw, ok := row["hp"]; ok && raw != "" {
        obj.Hp = parseInt32(raw)
    }
    if raw, ok := row["skills"]; ok && raw != "" {
        obj.Skills = parseListInt32(raw, sep.List)
    }
    return obj
}

func init() {
    registerTable("hero/HeroBase", func(rows []map[string]string, sep SepConfig) {
        m := map[int32]*HeroBaseTpl{}
        for _, row := range rows {
            obj := parseHeroBase(row, sep)
            m[obj.Id] = obj
        }
        HeroBase_data = m
    })
}

func GetHeroBase(id int32) *HeroBaseTpl       { return HeroBase_data[id] }
func GetAllHeroBase() map[int32]*HeroBaseTpl  { return HeroBase_data }
```

字段名规则：.tbl 中 snake_case（`max_level`）→ Go 中 PascalCase 导出（`MaxLevel`），数据文件 key 与 Java 保持一致（camelCase `maxLevel`）。

### Constant 模式 → Tpl 结构体

**global_const_tpl.go：**

```go
package config

type GlobalConstTpl struct {
    MaxLevel   int32             // int
    StartPos   Tuple2[int32,int32] // Tuple2<int,int>
    ServerName string            // str
}

var GlobalConst_data = &GlobalConstTpl{}

func init() { /* registerConstant ... */ }

func GetGlobalConst() *GlobalConstTpl { return GlobalConst_data }
```

### 类型映射

| TblFieldType | Go 类型 |
|---------|---------|
| int / long / float / double / bool / str | int32 / int64 / float32 / float64 / bool / string |
| List\<T\> | []T |
| Set\<T\> | map[T]struct{} |
| Map\<K,V\> | map[K]V |
| Tuple2\<A,B\> | Tuple2[A,B]（泛型结构体，字段 F0/F1） |
| Tuple3 / Tuple4 | Tuple3[A,B,C] / Tuple4[A,B,C,D] |
| List\<Tuple2\<...\>\> | []Tuple2[...]，等等 |
| Map\<K,Tuple_\<...\>\> | map[K]Tuple_[...]，等等 |
| Map\<K,List\<V\>\> | map[K][]V |

### 加载入口

`loader.go` 暴露：

```go
config.Init(dataDir string) error      // 加载 XML 数据文件（默认）
config.InitJSON(dataDir string) error  // 加载 JSON 数据文件
```

实现细节：每个 `*_tpl.go` 在 `init()` 时把 `<group>/<name>` 注册到 loader registry。`Init` 扫描 dataDir 下所有匹配后缀的文件，按相对路径解析为 key，调用对应注册函数完成加载。

## 生成枚举（mode=enum）

枚举固定范式（id|name|desc），无 export 标记，对所有目标语言全量生成。**枚举不参与数据文件导出**——内容固定写死在生成代码里。

### Java —— 真正的 enum + Javadoc desc + @TblSource

**HeroTypeEnum.java：**

```java
package com.game.config.tpl;

import com.game.config.TblSource;

@TblSource(group = "hero", name = "HeroType", mode = "enum")
public enum HeroTypeEnum {
    /** 战士 */
    WARRIOR(1, "战士"),
    /** 法师 */
    MAGE(2, "法师"),
    /** 弓手 */
    ARCHER(3, "弓手");

    public final int id;
    public final String desc;

    HeroTypeEnum(int id, String desc) {
        this.id = id;
        this.desc = desc;
    }

    public static HeroTypeEnum fromId(int id) {
        for (HeroTypeEnum e : values()) if (e.id == id) return e;
        return null;
    }
}
```

- 类级 `@TblSource(group, name, mode = "enum")` —— 复用 Table/Constant 的注解，业务/工具可反射查询来源
- 每个常量上 Javadoc `/** desc */` —— IDE 悬停 `HeroTypeEnum.WARRIOR` 显示 `战士`
- 业务用法：`HeroTypeEnum.WARRIOR.id` / `.desc` / `valueOf("WARRIOR")` / `fromId(1)`

### Go —— typed int + 常量 + 行注释 + 反查函数

**hero_type_enum.go：**

```go
package config

type HeroTypeEnum int32

const (
    HeroTypeEnum_WARRIOR HeroTypeEnum = 1 // 战士
    HeroTypeEnum_MAGE    HeroTypeEnum = 2 // 法师
    HeroTypeEnum_ARCHER  HeroTypeEnum = 3 // 弓手
)

var heroTypeEnumDesc = map[HeroTypeEnum]string{
    HeroTypeEnum_WARRIOR: "战士",
    HeroTypeEnum_MAGE:    "法师",
    HeroTypeEnum_ARCHER:  "弓手",
}

var heroTypeEnumByName = map[string]HeroTypeEnum{
    "WARRIOR": HeroTypeEnum_WARRIOR,
    "MAGE":    HeroTypeEnum_MAGE,
    "ARCHER":  HeroTypeEnum_ARCHER,
}

func (h HeroTypeEnum) Desc() string { return heroTypeEnumDesc[h] }

func (h HeroTypeEnum) String() string {
    for name, val := range heroTypeEnumByName {
        if val == h {
            return name
        }
    }
    return ""
}

func ParseHeroTypeEnum(name string) (HeroTypeEnum, bool) {
    v, ok := heroTypeEnumByName[name]
    return v, ok
}
```

### Lua —— name→id + desc 倒查表

**HeroType.lua：**


## 引用类型字段生成（@TableName / @EnumName）

引用类型字段在数据文件层面**永远存 id**，加载阶段三语言按各自风格转换。

### 字段定义对照

`#type` 行声明：

```
boss   | @HeroBase   | cs | Boss 配置
type   | @HeroType   | cs | 英雄类型
```

### Java

```java
@TblFieldType("@HeroBase")
private int boss;            // table ref → int

@TblFieldType("@HeroType")
private HeroTypeEnum type;   // enum ref → 枚举类型，加载时 fromId(int) 转换
```

加载逻辑：`@HeroBase` 读为 int 直接赋值；`@HeroType` 读 int 后调 `HeroTypeEnum.fromId(int)`。

### Go

```go
type HeroBaseTpl struct {
    Boss int32         // @HeroBase
    Type HeroTypeEnum  // @HeroType — 加载时 HeroTypeEnum(parseInt32(raw))
}
```

加载逻辑：table ref 用 `parseInt32`；enum ref 用 `HeroTypeEnum(parseInt32(raw))`（typed int 直接 cast）。

### Lua

```lua
{
    boss = 1001,      -- table ref，业务用 HeroBase[1001]
    type = 1,         -- enum ref，业务用 HeroType.WARRIOR == 1 比较
}
```

Lua 不做类型转换，业务自行用引用 enum 的 name 字段反查 id 比较。

## 生成数据文件（JSON）

数据文件供 Java 端 TplHolder 加载。**扁平存放**（不分 group 子目录），仅包含"前后端"和"服务器"标记的字段。

### Table 模式

**HeroBase.json：**

```json
{
  "_sep": {"list": ";"},
  "data": [
    {"id": 1001, "name": "战士", "hp": 100, "skills": "1;2;3", "type": 1},
    {"id": 1002, "name": "法师", "hp": 80, "skills": "4;5", "type": 2}
  ]
}
```

`_sep` 只包含表中实际范式用到的 leaf：HeroBase 仅 `skills: List<int>` 是复合范式，所以只写 `list`。其余 `id` `name` `hp` `type` 都是 base / Ref，不需要分隔符。如果整张表全 base / Ref（比如纯 int/str 的简单表），`_sep` 会**整个被省略**，文件直接是 `{"data": [...]}`。

引用类型字段（`type` / `boss`）在 JSON 中存储为 int 原生类型。

### Constant 模式

**GlobalConst.json：**

```json
{
  "_sep": {"tuple2": ","},
  "data": {
    "maxLevel": 100,
    "startPos": "5,10"
  }
}
```

JSON 中字段名使用 camelCase，与 Java Tpl 类字段一致。基础类型输出为 JSON 原生类型，复合类型保持分隔符字符串。`_sep` 按需输出 —— 这里只有 `startPos: Tuple2<int,int>` 一个复合范式，所以仅写 `tuple2`；消费端 `SepConfig.fillDefaults()` 给缺失 key 兜底。

## 生成 Excel 文件（xlsx）

> ⚠️ 待开发。下文是规约 / 设计目标。

每个 **Group** 生成一个 xlsx 文件（`gen/excel/<group>.xlsx` 或 `projects/<id>/.tbl-cache/<group>.xlsx`）；Group 内每个 Table / Constant / Enum 对应一个 sheet（tab）。这是**核心层能力**——CLI 也能跑，输出的 xlsx 可直接给策划用 Excel 打开审阅 / 配色。UI 层在此之上叠加"调起 Excel + 监控关闭 + 回写"工作流（见 @06 Excel 桥接）。

### sheet 布局

| 模式 | 行结构 |
|------|--------|
| Table | 第 1 行：desc<br>第 2 行：type（合并 export，如 `cs int`，参考 @01.5 字段语法）<br>第 3 行：field<br>第 4 行起：数据，第 1 列固定为 id |
| Constant | 第 1 行：固定表头 `name / type / value / export / desc`<br>第 2 行起：数据 |
| Enum | 第 1 行：固定表头 `id / name / desc`<br>第 2 行起：数据 |

每个 sheet 顶部冻结表头行（freeze pane），便于策划滚动数据时仍能看到 field / type。

### 行颜色映射

.tbl 行颜色标记（@01.9）通过 Excel 行背景色双向映射：导出时按颜色枚举写背景色；导入时读取背景色反查回 `RowColor`。具体颜色值（RGB）由 `crates/core/src/excel.rs` 中常量定义，UI 与 xlsx 共用一套——保证视觉一致。

### 命名 / 文件

| .tbl 路径 | xlsx 文件 | sheet 名 |
|-----------|----------|---------|
| `projects/<id>/config/hero/HeroBase.tbl` | `gen/excel/hero.xlsx` | `HeroBase` |
| `projects/<id>/config/hero/HeroSkill.tbl` | `gen/excel/hero.xlsx` | `HeroSkill` |
| `projects/<id>/config/global/GlobalConst.tbl` | `gen/excel/global.xlsx` | `GlobalConst` |

sheet 名直接用 .tbl 文件名（不带扩展名），Excel sheet 名最长 31 字符，工具在生成前校验。

### 配置

```toml
[export.excel]
output = "gen/excel"          # xlsx 输出目录
# encoding / line_ending 不适用 — xlsx 是二进制
```

### 入口函数

`crates/core/src/export/xlsx.rs::export_all_xlsx(project) -> ExportResult`，与 `export_all_json` / `export_all_xml` / `export_all_java` 等平级。

## 导入 Excel 文件（xlsx → 内存模型）

> ⚠️ 待开发。

xlsx 解析回 `Project` 内存模型是**导出 xlsx 的反函数**，与导出共用 sheet 布局和颜色映射规则。CLI 暂无直接入口（业务上没强需求），主要供 UI 端的 Excel 桥接（@06）调用。

### 解析规则

| 来源 | 目标 |
|------|------|
| sheet 名 | `Table.name` / `Constant.name` / `Enum.name`（按对应 .tbl 的 mode 推断） |
| 第 1-3 行（Table） | desc / type / field 表头比对：与现有 schema 不一致时报错（不允许通过 Excel 改 schema 字段顺序） |
| 第 4 行起（Table） | 数据行；空行跳过，单元格按 type 解析 |
| 单元格颜色 | RowColor（取每行第 1 个非空单元格背景色） |

### 错误回报

xlsx 解析失败不直接抛 panic，按 .tbl 的 `validate` 规则把错误聚到 `ProjectErrors`，UI / CLI 决定如何展示。

### 入口函数

`crates/core/src/excel.rs::import_xlsx(path) -> Result<GroupData>`（待实现）。

## 验证（CLI validate）

`tbl-cli validate` 触发**全项目离线校验**，是 @01.8 验证规则的 CLI 入口。GUI 端的"实时验证 / 保存校验"走同一份 core 逻辑（@07.4.10.2）。

### 命令

```bash
tbl-cli [-w <workdir>] [-s key=value]... validate
```

### 退出码

| 码 | 含义 |
|----|------|
| 0 | 全部 .tbl 通过四层验证（cell / row / schema / project，@01 附录 A） |
| 1 | 任一节点验证失败 / .tblschema 解析失败 / 文件读取失败 |

### 输出

stderr 打印每个失败 entry 的位置 + 错误码 + 示例值，按 `<group>/<name>:<row>:<col>` 形式聚集；stdout 不打印（保持安静，便于 CI 解析）。

CI 推荐用法：

```bash
tbl-cli validate || exit 1
tbl-cli export        # 验证通过才导出
```

## 测试数据生成（CLI generate-test）

`tbl-cli generate-test` 依据内置或外部 `.tblschema` 模板，生成 .tbl 数据 + 配套配置文件，供：

- 工具开发期对照测试（不需要真实策划数据）
- 新接入项目的脚手架（一键起一个空项目）
- 性能压测（生成 N 万行随机数据）

### 命令

```bash
tbl-cli generate-test \
  [--empty | --schema <path>] \
  [--rows N] [--seed N] \
  [--format json|xml] \
  [--lang java|go|none]
```

| 参数 | 说明 | 默认 |
|------|------|------|
| `--empty` | 生成空骨架（仅 schema，无数据行） | — |
| `--schema <path>` | 用指定 .tblschema 文件；缺省走内置 `full.tblschema` | 内置 |
| `--rows N` | 每张 Table 生成 N 行随机数据（与 `--empty` 互斥） | 5 |
| `--seed N` | 随机种子，方便复现 | 当前时间戳 |
| `--format` | 顺手把生成的项目导出一份数据文件 | json |
| `--lang` | 顺手把生成的项目导出一份代码 | none |

### 实现：复用模板模块

`generate-test` 内部分两步：

1. `BuiltinTemplates::load_by_id(<id>) → schema` —— 从模板模块拿 schema
2. `instantiate_template(schema, tempdir)` —— 实例化空 .tbl 文件集合
3. **填充随机数据**（generate-test 独有）—— 按 `--rows N` 在每张 Table 灌随机行，Constant 灌随机 value，Enum 已由 instantiate 写完不再处理

这样模板加载 / 实例化的逻辑在内置模板库（@项目模板）和测试数据生成之间复用。`--schema <path>` 模式直接读外部 .tblschema 文件并用同一个 instantiate 通路。

### 内置 schema

`crates/core/schemas/{full,empty}.tblschema` 通过 `include_str!` 嵌入二进制（`build.rs` 把 schemas/ 加进 rerun-if-changed，避免改 schema 不重编）。改 schema 必须保证通过 @01.8 验证（如字段名不能用语言关键字，详见 [@07.9](07-程序实现.md)）。

### 目录与 package 对应关系

**Java:**

| 目录 | Java package | 内容 |
|------|-------------|------|
| 根 | com.game.config | ITpl, IConstTpl, TplHolder, TplRegistry, TblMeta, TblFieldType, TblSource, TplUtil, 解析器 |
| types/ | com.game.config.types | Tuple2, Tuple3, Tuple4 |
| tpl/ | com.game.config.tpl | 所有 Tpl 类 + Enum 类（跨 group 扁平集中） |

业务代码统一 `import com.game.config.tpl.*;` 或按需 import 单个类。

**Go:**

Go 输出采用 **flat package**：所有生成文件都在同一个 package 目录下，文件名使用 snake_case，不分 group 子包。原因是 Go 的初始化顺序按 import 图保证，flat 结构避免循环依赖、调用更直观。

| 文件 | 内容 |
|------|------|
| loader.go | `Init(dir)` / `InitJSON(dir)` 入口，扫描数据目录调用 registry |
| parser.go | 基础类型/List/Set 解析函数 |
| sep.go | `SepConfig` 结构 + JSON/XML 元数据反序列化 |
| tuples.go | `Tuple2/3/4` 泛型结构 + `ParseTuple_/ParseListItems/ParseMap` |
| {name}_tpl.go | 每张表/常量一个文件，包含结构体定义、`Get{Name}`/`GetAll{Name}` 函数、`init()` 注册解析器 |
| {name}_enum.go | 每个枚举一个文件，包含 typed int + 常量 + `Desc()` / `String()` / `FromId` |

**Lua:**

所有 .lua 直接放 `gen/client/` 下，业务 `require("config.HeroBase")`（路径中无 group 层）。

## Java / Go / Lua 导出对比

| 维度 | Java（后端） | Go（后端） | Lua（前端） |
|------|-------------|-----------|-------------|
| 数据来源 | JSON 或 XML 数据文件 | JSON 或 XML 数据文件 | 直接从 .tbl 生成 |
| 字段过滤 | 仅服务器+前后端 | 仅服务器+前后端 | 仅客户端+前后端 |
| 数据格式 | XML（默认）或 JSON | XML（默认）或 JSON | Lua table 内嵌 |
| 模板类 | Tpl 类 + 注解（反射加载） | 结构体 + 生成的 parse 函数（零反射） | 不需要 |
| 加载方式 | TplHolder.init(目录) / TplHolder.initJson(目录) | config.Init(目录) / config.InitJSON(目录) | require("Name") |
| 查询方式 | TplHolder.get(Class, id) | config.GetXxx(id) / config.GetAllXxx() | table[id] |
| 目录结构 | tpl/ 子包扁平 | flat package | 扁平 |
