# 测试

## 1. 测试架构

集成测试通过 CLI 程序驱动，基于 `.tblschema` 结构定义文件生成测试数据和验证代码，验证完整的导出链路：.tblschema → .tbl → JSON/XML → Java 编译 → 加载运行。

### 1.1 核心流程

```
.tblschema（结构定义）
    ↓ generate-test --format json|xml
.tbl 数据文件 + TestMain.java
    ↓ export --json/--xml --java
JSON/XML 数据 + Java Tpl 类
    ↓ javac + java
actual_output.txt
    ↓ diff
expected_output.txt → PASS / FAIL
```

### 1.2 内置 Schema 文件

位于 `crates/core/schemas/`，每个文件描述一种测试场景的表结构：

| 文件 | 覆盖内容 |
|------|---------|
| `basic.tblschema` | 基础类型（int/str/bool/float） |
| `collection.tblschema` | 集合类型（List/Set/Map） |
| `tuple.tblschema` | 元组类型（Tuple2/3/4） |
| `empty.tblschema` | 空值字段（验证 null/omit 策略） |
| `full.tblschema` | 完整项目结构（所有类型组合） |

Schema 文件格式详见 [@01.10 .tblschema 详解](01-tbl系统.md#10-tblschema-详解)。

## 2. 目录结构

```
tbl-tool/tests/
├── run_all.sh              ← 自动发现并执行所有场景
├── java_json/
│   ├── run.sh              ← 场景测试脚本
│   └── expected_output.txt ← 预期输出
├── java_json_omit/
│   ├── run.sh
│   └── expected_output.txt
├── java_xml/
│   ├── run.sh
│   └── expected_output.txt
├── java_xml_omit/
│   ├── run.sh
│   └── expected_output.txt
└── ...
```

每个场景目录只需维护 `run.sh` + `expected_output.txt`，其余文件（.tbl、TestMain.java、gen/、out/）全部由 CLI 动态生成。

> 测试目录是**独立 CLI fixture**，与 `projects/<id>/` 没有关系——`tests/<scenario>/` 各自是一个临时工作区，`generate-test` 在场景目录内创建 `config/` 平铺出 .tbl 文件供测试使用。这些 `config/` 是脚本临时产物（diff 后清理），不是 Project 概念（@04 Project）的一部分。

## 3. 测试流程

`run_all.sh` 自动遍历子目录，发现 `run.sh` 即执行：

```bash
# run_all.sh 核心逻辑
for DIR in tests/*/; do
    [ -f "$DIR/run.sh" ] || continue
    cd "$DIR"
    rm -rf gen tbl-tool.toml out actual_output.txt config TestMain.java
    bash run.sh > actual_output.txt 2>&1
    diff expected_output.txt actual_output.txt && echo PASS || echo FAIL
done
```

每个场景的 `run.sh` 调用 CLI 完成数据生成和导出：

```bash
# 示例：java_json/run.sh
$CLI -w . generate-test --format json   # 生成 .tbl + TestMain.java
$CLI -w . export --json --java          # 导出 JSON + Java
javac ... TestMain.java                 # 编译
java TestMain gen/server/data/json      # 运行验证
```

## 4. CLI generate-test 命令

通过选项组合控制生成的测试数据特征：

```bash
tbl-cli generate-test [OPTIONS]

OPTIONS:
    --empty           包含空值字段
    --schema <PATH>   指定外部 .tblschema 文件
    --rows <N>        数据行数（0=默认固定数据）
    --seed <N>        随机种子（0=固定数据，非0=可重复随机）
    --format <FMT>    数据格式：json（默认）或 xml，影响 TestMain.java 初始化方式
    --lang <LANG>     生成验证程序的目标语言（java / lua）
```

`generate-test` 同时生成：
- `config/` 下的 .tbl 数据文件（结构 + 动态填充的行数据）
- 验证主程序：`--lang java` 时为 `TestMain.java`（按 --format 选择 `TplHolder.initJson()` 或 `TplHolder.init()`）；`--lang lua` 时仅生成 .tbl，不产出 TestMain.java

## 5. 测试场景说明

| 场景 | 验证内容 | CLI 参数 |
|------|---------|----------|
| java_json | 完整类型的 JSON 导出+加载 | `generate-test --format json` + `export --json --java` |
| java_json_omit | JSON 空值 omit 策略 | `generate-test --empty --format json` + `-s export.json.empty_as=omit export --json --java` |
| java_xml | 完整类型的 XML 导出+加载 | `generate-test --format xml` + `export --xml --java` |
| java_xml_omit | XML 空值 omit 策略 | `generate-test --empty --format xml` + `-s export.xml.empty_as=omit export --xml --java` |
