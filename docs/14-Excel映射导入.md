# Excel 映射导入（计划）

> 状态：已纳入开发计划，Phase A 未排期。目标是把**完全不符合 tablet 表头规范**的任意 Excel
> 映射成 tablet 结构；与「原生 xlsx 组导入」是两条独立的入口。

## 1. 目标与非目标

### 1.1 目标

- 源 Excel 可以是任意布局：id 不在第一列、只有一行列名、列名大小写/空格/中文不统一。
- 用户选择表头行、数据起始行、id 列，并把源列映射到 tablet 字段。
- 自动规范化字段名（snake_case）、推断类型、补 `desc / export / type / field` 四行表头。
- 预览映射结果，校验通过后导入。
- 源 Excel **不被修改**。

### 1.2 非目标

- 不把源 Excel 的样式、合并单元格、公式、批注带进 tablet。
- 不自动理解任意业务语义；列映射必须可见、可改。
- 不在本阶段支持多 sheet 批量映射（Phase B）。
- 不替代「原生 xlsx 组导入」：4 行表头合规的工作簿仍原样复制、保留样式。

## 2. 入口与判定

Project 根右键：

```text
导入 Excel Group...          ← 原生：4 行表头合规，原样复制
导入任意 Excel（映射）...    ← 本功能
```

选择文件后先做一次检测：

| 检测结果 | 行为 |
|---|---|
| 所有 sheet 都是 4 行规则表头 | 提示可直接走「导入 Excel Group」，也可继续映射 |
| 任一 sheet 不合规 | 打开映射窗口 |

映射窗口不修改源文件；输出默认写入当前 Project 的 `config/<group>/`（Tbl 组）。

## 3. UI 设计

### 3.1 窗口结构

目标尺寸约 `1100 × 720`，左右分栏，底部固定操作区。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 导入任意 Excel：foreign.xlsx                                        │
│ Sheet: [HeroBase ▾]   表头行: [3]   数据起始行: [4]   [自动识别]   │
├──────────────────────────────┬──────────────────────────────────────┤
│ 源表预览                     │ 目标结构                             │
│                              │ 组名: [hero       ]                  │
│  A    B        C       D     │ 节点: [HeroBase   ]  类型: Table     │
│ ───────────────────────────  │                                      │
│  ID   Name     HP      描述  │ 目标字段          源列   类型  export│
│  1    亚瑟     100     战士  │ [id      ] ← [ID  ▾] [int ▾] [cs ▾]  │
│  2    兰斯     90      法师  │ [name    ] ← [Name▾] [str ▾] [cs ▾]  │
│                              │ [hp      ] ← [HP  ▾] [int ▾] [cs ▾]  │
│  选中行/列会在预览中高亮     │ [desc    ] ← [描述▾] [txt ▾] [cs ▾]  │
│                              │ [+ 添加字段]  [自动匹配] [规范化]   │
├──────────────────────────────┴──────────────────────────────────────┤
│ 预览：生成的 tablet 表头                                             │
│ desc   | 名称  | 血量 | 描述                                        │
│ export | cs    | cs   | cs                                          │
│ type   | str   | int  | txt                                         │
│ field  | name  | hp   | desc                                        │
│ 警告：源列 "备注" 未映射；id 必须是第一列（将自动重排）             │
├─────────────────────────────────────────────────────────────────────┤
│                                      [取消]  [预览全部]  [导入]     │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.2 左侧：源表预览

- 显示前 ~20 行、所有列；列用 Excel 字母，行用真实行号。
- 表头行高亮；id 列高亮。
- 点击某一列 → 右侧自动选中对应源列；点击某一行可改「表头行」。
- 「自动识别」：
  - 表头行 = 文本非空最多的一行；
  - 数据起始行 = 表头行 + 1；
  - id 列 = 规范化后等于 `id` 的列；没有则留空要求用户选；
  - 其它列按规范化名字与目标字段自动匹配。

### 3.3 右侧：目标结构

- 组名、节点名可编辑；节点名默认取 sheet 名并转 PascalCase。
- Phase A 只支持 Table；Constant / Enum 在 Phase B。
- 字段表每行：目标字段名、源列、类型、export、desc、删除。
- 源列使用 ComboBox，包含「（忽略）」。
- 目标字段名自动规范化为 snake_case；冲突时该行标红，阻止导入。
- 「+ 添加字段」把未映射的源列加为目标字段。
- 自动匹配只做建议，不覆盖用户已经手改的映射。

### 3.4 底部：结果预览与校验

预览生成的四行表头 + 前几行数据：

```text
desc   | 名称 | 血量
export | cs   | cs
type   | str  | int
field  | name | hp
```

校验项：

- id 存在，且输出时固定第一列；
- 字段名合法且不重复；
- 类型可解析；
- 节点名 / 组名合法；
- 目标项目内节点名不冲突；
- 目标文件不存在；
- 源表没有重复映射同一列（允许，但给出警告）；
- 空 id 行会被跳过并提示行号。

错误在对话框内展示，不落任何数据；「导入」按钮只在无阻断错误时可用。

## 4. 规范化规则

### 4.1 字段名

```text
ID / Id / id              → id
Hero Name / heroName      → hero_name
HP / Hp / hp              → hp
描述                       → 保留中文？→ 拒绝，要求用户改成英文 snake_case
```

- 只保留 ASCII 字母、数字、下划线；
- 大写转小写；空格、连字符、点、括号转下划线；
- 连续下划线合并；首尾下划线去掉；
- 首字符必须是字母；数字开头前加 `f_`（或直接要求用户改）；
- 与 tablet 关键字冲突时提示用户改；
- 最终必须匹配 `[a-z][a-z0-9_]*`。

### 4.2 节点名

- sheet 名默认转 PascalCase：去分隔符、首字母大写；
- 必须匹配 `[A-Z][A-Za-z0-9_]*`；
- 项目内唯一（忽略大小写）；冲突直接报错，不自动 `_copy`。

### 4.3 类型

- 采样前 ~200 行非空值：
  - 全部整数 → `int`
  - 全部数字（含小数）→ `float`
  - 全部 `true/false` → `bool`
  - 其它 → `str`
- 用户必须能覆盖；复合类型、`txt`、`@Ref` 由用户显式选择。
- 推断结果只是建议，不静默决定最终类型。

### 4.4 export / desc

- export 默认 `cs`，可逐列改；
- desc 优先取「描述 / desc / 说明」列；没有则用源列名或留空；
- id 的 desc 默认 `ID`。

## 5. 输出语义

### 5.1 默认：生成 Tbl 组

- 在 `config/<group>/<Node>.tbl` 写出 tablet v3 表头 + 数据；
- 写入 manifest 的 section 索引；
- 源 Excel 不动；
- 与 `project import-tbl` 共用同一套名字校验 / 冲突规则。

### 5.2 可选：生成 xlsx 组（Phase B）

- 生成新的 `config/<group>.xlsx`，写入 4 行表头；
- **不保留源表样式、合并、公式**；必须显式勾选并提示；
- 如果用户想要样式，应保留原工作簿并用原生 xlsx 导入，而不是映射。

## 6. Phase A 实现拆分

1. **core：映射计划与预览**
   - `SheetPreview { columns, rows, max_row, ... }`；
   - `MappingPlan { sheet, header_row, data_start, id_col, fields }`；
   - `normalize_field_name` / `infer_type` / `build_table` 纯函数 + 单测。
2. **core：导入**
   - `apply_mapping_to_project(project_id, group, plan)`；
   - 全量校验后写 `.tbl` + manifest；
   - 失败不落数据。
3. **GUI**
   - 新对话框 `dialogs/excel_mapping_dialog.slint`；
   - 状态 `AppState.excel_mapping`；
   - Project 根右键入口；
   - 预览 / 校验 / 导入接线。
4. **测试**
   - 单 header 行、id 不在第一列、大小写混乱、缺 id、字段名冲突；
   - 源文件字节不变；
   - 导入后 manifest / `.tbl` 正确。

## 7. 验收标准

1. 任意单 sheet Excel（只有一行表头、id 不在第一列）能完成映射并生成正确 `.tbl`。
2. 预览中能看到最终四行表头和数据前几行。
3. 字段名自动规范化；冲突、缺 id、非法类型会阻止导入。
4. 源 Excel 字节不变。
5. 导入后项目树、manifest、保存/导出行为正常。
6. 合规的 xlsx 仍走原生导入，样式保留。
