# Excel 映射导入（计划）

> 状态：Phase A / 多 Sheet / 表·常量·枚举映射 / 多行表头语义行已实现（Tauri）。
> Constant/Enum 的映射方案复用、可选 xlsx 输出仍待做。

## 1. 目标与非目标

### 1.1 目标

- 源 Excel 可以是任意布局：id 不在第一列、只有一行列名、列名大小写/空格/中文不统一。
- 用户选择表头行、数据起始行、id 列，并把源列映射到 tablet 字段。
- 自动规范化字段名（snake_case）、推断类型、补 `desc / export / type / field` 四行表头。
- 预览映射结果，校验通过后导入。
- 源 Excel **不被修改**。

### 1.2 非目标

- 不把源 Excel 的样式、合并单元格、公式、批注带进 tablet。
- 不自动理解任意业务语义；列映射必须可见、可改。
- 不在本阶段支持多 sheet 批量映射（Phase B）。
- 不替代「原生 xlsx 组导入」：4 行表头合规的工作簿仍原样复制、保留样式。

## 2. 入口与判定

Project 根右键：

```text
导入 Excel Group...          ← 原生：4 行表头合规，原样复制
导入任意 Excel（映射）...    ← 本功能
```

选择文件后先做一次检测：

| 检测结果 | 行为 |
|---|---|
| 所有 sheet 都是 4 行规则表头 | 提示可直接走「导入 Excel Group」，也可继续映射 |
| 任一 sheet 不合规 | 打开映射窗口 |

映射窗口不修改源文件；输出默认写入当前 Project 的 `config/<group>/`（Tbl 组）。

## 3. UI 设计（Tauri）

### 3.1 窗口结构

左侧 Sheet 轨道 + 右侧目标设置 / 列映射 / 预览页签 + 底部导入栏。

```text
┌──────────────────────────────────────────────────────────────────┐
│ 导入任意 Excel（映射）                                  [关闭]   │
│ 文件：foreign.xlsx                                  [选择文件…] │
├────────────────┬─────────────────────────────────────────────────┤
│ 工作表 3       │ 节点类型[表/常量/枚举] 分组[hero] 节点[Item]    │
│ 道具表   ●     │ 字段行[4] 数据起始行[5]                         │
│ 技能表   !     │ 表头辅助行：说明[1] 类型[3] 导出[2]  [重新识别] │
│ 掉落表   –     ├─────────────────────────────────────────────────┤
│                │ 列映射 3/4 列已启用  [搜索][自动映射][全部启用] │
│                │ ☑ A ID   → id    int   前后端  ID               │
│                │ ☑ B Name → name  str   前后端  名字             │
│                ├─────────────────────────────────────────────────┤
│                │ 源表预览 | 导入结果 | 检查                      │
│                │ 1 说明行 / 2 导出行 / 3 类型行 / 4 字段行 ...    │
├────────────────┴─────────────────────────────────────────────────┤
│ 将导入 4 列 × 2 行 → hero / Item   [取消][导入全部][导入当前]    │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 Sheet 轨道

- 列出所有 sheet 的名称、列数 / 行数、状态：
  待配置、已就绪、待确认、N 个问题、已跳过、已导入、读取失败。
- 每个 sheet 独立保存映射状态；切换 sheet 不丢改动。

### 3.3 目标设置

- **节点类型**：表 / 常量 / 枚举，可手动改；默认按标准表头自动识别。
- **目标分组**：所有 sheet 共用；**节点名**：每个 sheet 独立，默认 PascalCase。
- **字段行**：字段名 / 属性名所在行；**数据起始行**：第一条数据所在行。
- **表头辅助行**（仅表）：说明行 / 类型行 / 导出行，`0` = 不使用。
  - 自动识别会填上，识别不到保持 0；全部可手动改。
  - 设置后按这些行覆盖每列的 desc / 类型 / 导出，并在源表预览中高亮。
- 常量 / 枚举使用单行表头，辅助行固定 0 并隐藏。

### 3.4 列映射

- **表**：源列 → 目标字段（自由命名）/ 类型 / 导出 / 说明；id 行锁定；
  未启用的列不写入。
- **常量**：源列 → `name / type / value / export / desc` 固定目标列。
- **枚举**：源列 → `id / name / desc` 固定目标列。
- 常量 / 枚举按表头自动匹配，未匹配的列为「不导入」，可在目标列下拉里手动改。
- 每行实时校验（字段名、关键字、重复、缺列、源列冲突），错误直接标在行上；
  校验规则来自 core（`field_issues` / `entry_field_issues`），界面只展示结果。

### 3.5 预览与检查

- **源表预览**：字段行、数据起始线、说明 / 类型 / 导出行分别高亮。
- **导入结果**：表显示 4 行表头 + 数据；常量 / 枚举显示目标列 + 数据行。
- **检查**：逐条问题，点击定位到映射行。
- 底部实时显示「将导入 N 列 × M 行」或「约 N 条常量 / 枚举」，以及错误 / 提示数。

### 3.6 底部操作

- **导入当前工作表**：当前 Sheet 无错误时可用。
- **导入全部就绪**：只导入已配置、未跳过、无错误的 Sheet；失败的逐条列出。
- **取消**：不落任何数据。

## 4. 规范化规则

### 4.1 字段名

```text
ID / Id / id                         → id
Hero Name / heroName / HeroName      → hero_name
AABb / URLPath / IDCard              → aa_bb / url_path / id_card
HP / Hp / hp                         → hp
道具ID / 攻击力 / 备注               → dao_ju_id / gong_ji_li / bei_zhu
2D                                   → f_2d
```

- 只保留 ASCII 字母、数字、下划线；其它字符作为分隔符；
- 驼峰、连续大写（缩写）都转 snake_case：`URLPath → url_path`；
- 汉字逐字转全拼：`道具ID → dao_ju_id`（识别不到才需要用户手填）；
- 连续下划线合并；首尾下划线去掉；
- 首字符必须是字母；数字开头前加 `f_`；
- 与 tablet 关键字冲突时提示用户改；
- 最终必须匹配 `[a-z][a-z0-9_]*`。

### 4.5 节点类型识别

- 标准 4 行表头（说明 / 导出 / 类型 / 字段）→ **表**，并识别三个辅助行；
- 单行表头恰好是 `name / type / value`（可带 `export / desc`）→ **常量**；
- 单行表头恰好是 `id / name`（可带 `desc`）→ **枚举**；
- 字段行上方还有说明 / 类型 / 导出行 → **表**（即使字段恰好叫 id/name/desc）；
- 其余（含普通单行表头的表）→ **表**。
- 自动识别结果都可在界面上手动改；识别不到的辅助行值为 0。

### 4.2 节点名

- sheet 名默认转 PascalCase：去分隔符、首字母大写；
- 必须匹配 `[A-Z][A-Za-z0-9_]*`；
- 项目内唯一（忽略大小写）；冲突直接报错，不自动 `_copy`。

### 4.3 类型

- 采样前 ~200 行非空值：
  - 全部整数 → `int`
  - 全部数字（含小数）→ `float`
  - 全部 `true/false` → `bool`
  - 其它 → `str`
- 用户必须能覆盖；Phase A 固定提供 `int / long / date / float / bool / str / txt`，复合类型 / `@Ref` 在 Phase B 再做。
- 推断结果只是建议，不静默决定最终类型。

### 4.4 export / desc

- export 默认 `cs`，可逐列改；
- desc 优先取「描述 / desc / 说明」列；没有则用源列名或留空；
- id 的 desc 默认 `ID`。

## 5. 输出语义

### 5.1 默认：生成 Tbl 组

- 在 `config/<group>/<Node>.tbl` 写出 tablet v3 表头 + 数据；
- 写入 manifest 的 section 索引；
- 源 Excel 不动；
- 与 `project import-tbl` 共用同一套名字校验 / 冲突规则。

### 5.2 可选：生成 xlsx 组（Phase B）

- 生成新的 `config/<group>.xlsx`，写入 4 行表头；
- **不保留源表样式、合并、公式**；必须显式勾选并提示；
- 如果用户想要样式，应保留原工作簿并用原生 xlsx 导入，而不是映射。

## 6. Phase A 实现拆分

1. **core：映射计划与预览**
   - `SheetPreview { columns, rows, max_row, ... }`；
   - `MappingPlan { sheet, header_row, data_start, id_col, fields }`；
   - `normalize_field_name` / `infer_type` / `build_table` 纯函数 + 单测。
2. **core：导入**
   - `apply_mapping_to_project(project_id, group, plan)`；
   - 全量校验后写 `.tbl` + manifest；
   - 失败不落数据。
3. **GUI**
   - Tauri 对话框 `#excel-map`（`ui/index.html` / `ui/main.js`）；
   - 后端命令 `excel_preview` / `excel_detect_layout` / `excel_check_mapping` / `excel_import_mapped`；
   - Project 根右键入口；
   - 预览 / 实时校验 / 表·常量·枚举导入接线。
   - 3.0 起只有 Tauri 版；旧 Slint 对话框已随 app-slint 删除。
4. **测试**
   - 单 header 行、id 不在第一列、大小写混乱、缺 id、字段名冲突；
   - 源文件字节不变；
   - 导入后 manifest / `.tbl` 正确。

## 7. 验收标准

1. 任意单 sheet Excel（只有一行表头、id 不在第一列）能完成映射并生成正确 `.tbl`。
2. 预览中能看到最终四行表头和数据前几行。
3. 字段名自动规范化；冲突、缺 id、非法类型会阻止导入。
   标准五列常量、id/name/desc 枚举能自动识别并各生成一个节点；
   说明 / 类型 / 导出辅助行可手动改，识别不到为 0。
4. 源 Excel 字节不变。
5. 导入后项目树、manifest、保存/导出行为正常。
6. 合规的 xlsx 仍走原生导入，样式保留。
