# UI 平台选型

## 架构

项目采用 core + 多前端架构：

```
tbl-tool/
├── crates/
│   ├── core/         ← tbl-core：零 UI 依赖的核心库
│   ├── app-egui/     ← egui 桌面实现（当前主力）
│   ├── app-slint/    ← Slint 实现（待开发）
│   ├── app-fltk/     ← FLTK 实现（待开发）
│   └── app-cli/      ← 命令行工具（jenkins 打包用，待开发）
```

所有 UI 实现共享 `tbl-core`（模型、类型系统、验证、数据操作、文件 I/O）。
UI 设计和布局见 [07-UI设计](07-UI设计.md)，与具体实现平台无关。

## 框架对比总览

| | egui | FLTK | Slint |
|--|------|------|-------|
| **渲染模式** | Immediate-mode 自绘 | Retained-mode 自绘 | 声明式自绘 |
| **编程模型** | 每帧重建 UI | OOP 回调式 | .slint 描述文件 + Rust 逻辑 |
| **跨平台** | Win/Mac/Linux | Win/Mac/Linux | Win/Mac/Linux/嵌入式 |
| **原生感** | 差（游戏引擎风） | 一般（经典控件风） | 好（多套精细主题） |
| **主题切换** | 仅 light/dark | fltk-theme 运行时换皮 | 编译时选主题，按平台自动适配 |
| **内置主题** | — | Aqua/Metro/Dark/Greybird 等 | fluent(Win11)/cupertino(macOS)/material/cosmic |
| **中文字体** | 需代码加载系统字体 | 零配置，走系统文本渲染 | 需嵌入或开启系统字体 feature |
| **Release 体积** | ~4 MB | ~2-3 MB | ~5-8 MB |
| **表格控件** | 无内置，手动绘制 | 内置 Table 控件 | 无内置，ListView + delegate |
| **树形控件** | 无内置，手动绘制 | 内置 Tree 控件 | 需自己组合 |
| **弹窗/菜单** | egui::Window/Area | Window/MenuButton | PopupWindow 组件 |
| **可视化设计器** | 无 | FLUID (fl2rust) | Live Preview + VS Code 插件 |
| **许可证** | MIT | LGPL (FLTK 本体) | GPL 或商业许可 |

## 各平台原生感

| 平台 | egui | FLTK | Slint |
|------|------|------|-------|
| Windows | 差 | 尚可（经典 Win 风） | 好（fluent 主题接近 Win11） |
| macOS | 差 | 一般（不像 Cocoa） | 较好（cupertino 主题） |
| Linux | 差 | 一般 | 较好（cosmic 或走 Qt） |

注：三者都不是真正的系统原生控件，但 Slint 的主题系统视觉完成度最高。

## 选型建议

| 场景 | 推荐 |
|------|------|
| 快速迭代、功能优先 | egui（当前已实现） |
| 追求原生感、视觉质量 | Slint |
| 追求体积小、表格开箱即用 | FLTK |
| CI/CD 自动化打包 | app-cli |

## egui 实现

当前主力实现，功能已完成。

### 优势
- 开发速度快，immediate-mode 适合快速原型
- MIT 许可，无商业限制
- 社区活跃，egui 生态丰富

### 难点与解决
- **中文字体**：运行时通过 font-kit 加载系统字体（微软雅黑/PingFang 等）
- **表格控件**：完全手动绘制（列宽、行高、选区、滚动、表头固定）
- **原生感差**：通过自定义 Visuals 尽量贴近，但本质是游戏引擎风格
- **类型选择器**：egui::Window 弹窗实现，需处理帧延迟提交问题

### 产物
- 二进制：~4 MB（release + LTO + strip）
- 无运行时依赖

## FLTK 实现（待开发）

### 优势
- 内置 Table/Tree 控件，表格工具开箱即用
- 中文零配置，直接走系统文本渲染
- 产物最小（~2-3 MB）
- 静态链接，无运行时依赖

### 难点预估
- **拖拽选区**：Table 控件的选区模型有限，复杂选区需自定义事件处理
- **单元格验证红框**：需覆盖 Table 的 draw_cell 回调自定义绘制
- **主题**：fltk-theme 换皮是改颜色/边框，控件形态不会真正变化
- **公式栏联动**：需手动同步 Table 选中状态与外部 Input 控件

### 适配策略
- Tree 控件直接映射左侧树
- Table 控件映射表格区，通过 draw_cell 回调实现自定义渲染
- 弹窗用 Window 控件
- 右键菜单用 MenuButton

## Slint 实现（待开发）

### 优势
- 视觉质量最高，多套精细主题按平台自动适配
- 声明式 UI 开发效率高，支持 Live Preview
- 条件样式天然适合验证红框等动态视觉反馈
- 支持动画和响应式布局

### 难点预估
- **表格控件**：无内置，需用 ListView + 自定义 delegate 实现整个表格
- **树形控件**：需自己组合 TreeView（递归组件）
- **中文字体**：需开启 `backend-winit-fontconfig` feature 或嵌入字体文件
- **产物体积**：含渲染器 + 字体较大（~5-8 MB）
- **许可证**：GPL 或商业许可，需评估合规性
- **拖拽选区**：需在 delegate 层手动处理鼠标事件和状态

### 适配策略
- .slint 文件描述布局，Rust 侧通过 model 绑定数据
- 表格用 ListView + GridLayout delegate
- 验证错误通过 model 属性驱动条件样式
- 类型选择器用 PopupWindow 组件

## CLI 模式（待开发）

用于无 GUI 环境（CI/CD、jenkins）：

### 功能
- `tbl-cli validate` — 验证所有 .tbl 文件，输出错误列表
- `tbl-cli export` — 导出数据文件（JSON/Lua）+ 代码模板（Java/Go）
- 返回退出码：0 成功，非 0 有错误

### 依赖
- 仅依赖 `tbl-core` + `clap`
- 不涉及 UI 渲染
- 产物极小（< 1 MB）
