# TBL 配置管理系统 — 概述

## 1. 系统定位

游戏配置数据管理工具链，解决策划用 Excel 编辑配置表时的协作冲突、版本管理和代码生成问题。

**核心思路：** Excel 只作为编辑器，数据以文本中间格式（.tbl）存储在 Git 中，通过工具实现 Excel ↔ .tbl 双向转换。

**技术栈：** 服务端 Java / Go，客户端 Unity/Cocos 的 Lua。

## 2. 工作流

```
策划日常流程：

打开 tbl-tool → 左侧树选择配置表 → 在 UI 内直接编辑 / 点击"用 Excel 打开"
    → 编辑完成 → 验证通过 → 点击保存 → .tbl 文件更新
    → git commit / push

程序日常流程：

git pull → tbl-tool export → 生成 server/data + server/code + client
    → 编译运行
```

**冲突策略**：不做本地并发锁，完全依赖 Git 解决冲突。一行一记录的文本格式保证大多数情况下 Git 可自动 merge。

## 3. 核心概念

| 概念 | 说明 |
|------|------|
| Group | `config/` 下的一个文件夹，对应一个 Excel 文件 |
| Table | 行列数据配置（`.tbl`，`#mode table`） |
| Constant | 离散常量配置（`.tbl`，`#mode constant`） |
| Enum | 枚举配置（`.tbl`，`#mode enum`） |
| Export | 导出标记：前后端 / 客户端 / 服务器 / 不导出 |

## 5. 文档章节标号约定

为了方便跨文档定位与引用追踪，所有文档统一遵守以下规则。

### 5.1 章节按层级编号

```
## 5. 一级标题       ← 数字编号
### 5.1 二级标题
#### 5.1.2 三级标题
```

每个文档的一级编号从 1 开始，独立递增。文档前的「00/01/...」不进入章节编号本身，是文件级排序。

### 5.2 跨文档引用：`@<文档号>.<章节号>`

写法 | 含义
---- | ----
`@01.7.5` | 01 号文档第 7.5 节
`@05.4` | 05 号文档第 4 节
`@5.4` | 同文档（省略文档号）的 5.4 节
`@01` | 整个 01 号文档（罕见）

### 5.3 为什么要用 `@编号` 而不是直接写文字标题

- **稳定**：标题文字会改，编号也可能调，但二者都比「随手描述」抗腐朽
- **唯一**：同一概念再多处描述也无歧义
- **可统计**：`grep -rn '@01\.' docs/` 一秒看出 01 被引用多少次、被谁引用
- **避免重复描述**：用 `@01.7.5` 替代「详见类型系统的引用类型章节那段说明」

### 5.4 写引用时的最小义务

- 写 `@x.y` 即可，不必把目标章节标题再抄一遍
- 如果想给读者一句话提示，写「（@01.7.5 引用类型）」或「[引用类型](@01.7.5)」均可
- 引用本身就是文档系统的索引，**不允许在引用处复制粘贴目标内容**

### 5.5 标号到锚点的对应

每个章节标题已经含数字编号，markdown 渲染器会生成对应锚点（如 `## 7. TblFieldType 类型系统` → `#7-tblfieldtype-类型系统`）。点击 `@01.7` 跳转时，浏览器/IDE 按文档号定位文件，再按章节号在文件内滚动到对应标题。
