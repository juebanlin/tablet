# UI 设计

桌面工具的界面布局、交互、编辑保存机制、验证反馈、规划中功能。所有 tbl 系统的硬性约束都在 @01；这里只讲面向用户的呈现与操作。

## 1. 整体布局

### 1.1 区域划分

界面采用「大区→子区域」两级分区。顶层只有 **3 个大区**（自上而下），中部由左右 **2 个子大区**横向并列；每个大区内部再切分若干子区域，子区域宽度始终跟随所在大区。

#### 顶层 3 个大区

| 大区 | 位置 | 尺寸 | 责任 |
|------|------|------|------|
| **Toolbar** | 顶部 | 32px | 全局命令按钮（生成测试 / 保存 / 导出 / Schema 等） |
| **TreeSection + GridSection** | 中部填充 | 自适应高度 | 配置树 / 表格 二选一聚焦 |
| **LogPanel** | 底部 | 默认 120px，可拖拽 | 操作日志（独立于表格区） |

#### 中部两个子大区

| 大区 | 位置 | 尺寸 | 责任 |
|------|------|------|------|
| **TreeSection** | 左 | 默认 200px，可拖拽，最小 80px、无最大限制 | 配置树（标题 + 功能区 + 节点列表） |
| **GridSection** | 右 | 自适应宽度 | 当前选中节点的表格详情（5 段子区域） |

调节线、滚动条等具体行为见 @1.5。

### 1.2 区域归属原则

每个 UI 元素都明确归属一个大区，不跨级悬浮：

- **属于「当前选中表」的所有控件归属 GridSection**：表名标题、表级开关、公式栏、状态栏，宽度都跟随表格区。
- **属于「项目浏览」的控件归属 TreeSection**：搜索 / 过滤 / 完整组 / 节点列表。
- **全局命令归属 Toolbar**；**与具体节点无关的产出归属 LogPanel**。

这样读者一眼就能从位置反推归属：选中 cell 时看到的「B3 │ 战士」公式栏，本质是 `GridSection` 的子组件，它窄于 `Toolbar`、宽于 `TreeSection`，自然不会让人误以为是全局栏。

### 1.3 GridSection 子区域

`GridSection` 是表格大区，从上到下 5 段子区域，全部与 `GridArea` 等宽：

| 子区域 | 高度 | 内容 |
|--------|------|------|
| **GridHeaderBar** | 24px | 表名（含图标 + 路径，如 `📊 hero / HeroBase`） + 副标题（行列数 / 模式） |
| **GridRibbon** | 24px | 表级视图开关（仅渲染影响），见 @5.2 |
| **FormulaBar** | 22px（动态） | 选中单元格时显示坐标 + 公式栏；未选中时 0 高度收起 |
| **GridArea** | 自适应 | 固定表头 + 可滚动数据区 |
| **StatusBar** | 20px | 当前选区 + 光标位置 |

未选中任何节点时，`GridSection` 显示居中占位文本「选择左侧节点查看详情」，子区域条仍可见但内容为空。

### 1.4 TreeSection 子区域

`TreeSection` 是配置树大区，3 段子区域，宽度跟随大区：

| 子区域 | 高度 | 内容 |
|--------|------|------|
| **标题栏** | 24px | 「配置树」固定标签 |
| **功能区** | 自适应 | 搜索框 → 过滤下拉 → 完整组勾选（顺序固定） |
| **节点列表** | 自适应填充 | 树形导航，可滚动 |

### 1.5 拉伸调节与滚动条

#### 大区拉伸调节

| 调节线 | 位置 | 行为 |
|--------|------|------|
| **左右调节线** | TreeSection 与 GridSection 之间（垂直走向） | 鼠标悬停光标变 ↔，左右拖动改变两者宽度 |
| **上下调节线** | 中部（树+表格）与 LogPanel 之间（水平走向） | 鼠标悬停光标变 ↕，上下拖动改变 LogPanel 高度 |

约束：

- TreeSection：默认 200px，最小 80px（拖拽到 80px 后再拖不缩小），无最大限制
- LogPanel：默认 120px，可拖拽至 0（完全收起）；上限由窗口高度决定
- Toolbar / GridHeaderBar / GridRibbon / FormulaBar / StatusBar 不可拖拽，固定高度
- 用户拖拽后的尺寸保留在会话内（不持久化到配置）

#### 滚动条

滚动只发生在「内容超出可视区」的局部，不在整窗口级别：

| 区域 | 滚动方向 | 行为 |
|------|----------|------|
| **TreeSection 节点列表** | 双向（H + V） | 节点超出 → 右侧出垂直条；名字过长被窄面板截断 → 底部出水平条 |
| **GridArea 数据区** | 双向（H + V） | **表头固定不滚动**，仅数据行滚动；列数多于可视宽度 → 底部水平条；行数多于可视高度 → 右侧垂直条 |
| **LogPanel 列表** | 垂直 | 内容超出可视区 → 右侧出垂直条；自动「粘底」（新日志追加时自动滚到末尾），用户手动上滑后停止粘底，回到底部后恢复 |

#### 滚动条样式

- 滚动条只在区域有 hover / 滚动时显示，离开后淡出（egui 默认 fade 行为）
- 内容不足时不显示滚动条（不留空白槽）
- TreeSection 与 GridArea 的水平 / 垂直滚动条独立，互不影响

## 2. TreeSection（配置树大区）

左侧主区域，三段式：标题栏 / 功能区 / 节点列表。所有控件宽度跟随大区。

### 2.1 交互

| 操作 | 效果 |
|------|------|
| 点击三角形 ▶/▼ | 展开/收拢组 |
| 双击组名 | 展开/收拢组 |
| 单击配置项 | 选中，右侧 GridSection 显示详情 |
| 右键 | 弹出对应上下文菜单 |

### 2.2 状态标记

| 标记 | 颜色 | 含义 |
|------|------|------|
| `+` | 绿 | 新建未保存 |
| `*` | 黄 | 已有文件被修改 |
| `-` | 红 | 标记删除，保存时生效 |
| `!` | 红 | 节点存在验证错误（详见 @5.4） |

组的状态聚合子项：所有子项删除→`-`，有新建子项或自身新建→`+`，有修改子项→`*`。

判断：
- 新建：`original` 为空
- 修改：序列化当前内容 ≠ `original`（"改回去"自动清除脏标记）
- 删除：`deleted = true`

### 2.3 功能区

功能区位于标题栏与节点列表之间，三个控件按固定顺序排布：

| 顺序 | 控件 | 用途 |
|------|------|------|
| 1 | 搜索框 | 名称关键字模糊匹配（实时过滤） |
| 2 | 过滤下拉 | 状态过滤：全部 / 改动 / 新增 / 修改 / 删除 |
| 3 | 完整组勾选 | 命中匹配组时显示该组所有子项 |

#### 过滤下拉选项

| 选项 | 显示 |
|------|------|
| 全部 | 所有节点 |
| 改动 | 新增 + 修改 + 删除 |
| 新增 | 仅新建节点 |
| 修改 | 仅已修改节点 |
| 删除 | 仅标记删除节点 |

非"全部"模式下空组自动隐藏。"完整组"勾选与搜索/过滤结果叠加生效。

### 2.4 右键菜单

| 目标 | 菜单项 |
|------|--------|
| Group | 新建 Table、新建 Constant、新建 Enum、重命名、删除 |
| Table/Constant/Enum | 复制、重命名、删除 |
| 空白 | 新建 Group |

## 3. GridArea（表格本体）

GridArea 是 GridSection 的核心子区域，承载固定表头 + 可滚动数据。三种 mode（Table / Constant / Enum）共用同一组渲染规则，差异在表头结构。

### 3.1 单元格类型系统（CellKind）

所有单元格统一抽象为 `CellKind`，决定交互行为：

| 类型 | 交互 | 用途 |
|------|------|------|
| ReadOnly | 不可编辑、深灰底 + 半灰文字、无 hover 高亮 | Constant/Enum 固定表头、Table id 列的 type/export/field 三格 |
| Text | 双击编辑 | 普通数据、表头 desc/field |
| TypeEnum | 单击弹出类型选择器 | Table 表头 type 行 |
| ExportEnum | 单击下拉 | Table 表头 export 行 |
| TypeEnumCol | 单击弹出类型选择器 | Constant type 列 |
| ExportEnumCol | 单击下拉 | Constant export 列 |
| Ref | 单击弹出引用选择器 | 列类型为 `@Xxx` 的数据格 |

ReadOnly 表头单元格的具体分布详见 @01.5.5；只读列不可删除/重命名（右键菜单中相应项禁用）。

### 3.2 存储值 vs 展示值（重要约定）

单元格在 UI 模型层（`grid.data` / `HeaderCell.text`）**始终存「真实存储值」**——即写入 .tbl 文件的形式。渲染层在画的瞬间通过 `display_for_*` 转换为 UI 展示值。

| 列类型 | 存储值（grid.data） | 展示值（painter） |
|--------|----------------------|-------------------|
| ExportEnum / ExportEnumCol | `cs` / `c` / `s` / `-` | 前后端 / 客户端 / 服务器 / 不导出 |
| Ref（@EnumName + 开关开） | enum 条目 id（如 `1`） | 对应 entry.name（如 `WARRIOR`） |
| Ref（@TableName 或开关关） | 表/枚举 id | 同存储值 |
| 其它 | 原字符串 | 同存储值 |

由此自动得到的好处：
- **复制粘贴 round-trip**：剪贴板永远是 `cs` 而不是「前后端」，粘到别处直接落地
- **公式栏/编辑缓冲一致**：编辑态读 `grid.data` 直接拿到存储值
- **校验/序列化无歧义**：底层逻辑只看一种字符串

下拉编辑组件按同规则：`edit_buffer` 写存储值（点击「前后端」实际写 `cs`），渲染时再翻译。新增带「展示≠存储」的列类型时，**必须同时在 `display_for_cell` / `display_for_header` 增加分支**，不允许把展示值塞回 `grid.data`。

#### 展示与可编辑性是独立维度

ReadOnly 仅控制 **能否编辑、能否右键操作、是否显示下拉箭头**；它不影响 **展示规则**。最典型的例子是 Table 表头的 id 列 export 行：

| 维度 | 取值 |
|------|------|
| 存储值 | `cs` |
| kind | `ReadOnly`（id 列 export/type/field 三行不可改） |
| 展示值 | `前后端`（与其它 export 列一致） |

误区：曾经的实现里 `display_for_header` 仅匹配 `ExportEnum/ExportEnumCol` kind，导致 id 列虽然存的是 `cs` 但因为 kind 是 ReadOnly 被原样画出，与同行其它列「前后端」不一致。修法是按 **行位置**（Table 第二行就是 export 行）触发翻译，不依赖 kind。

#### 双前端的存储值边界

各前端对"存储值层"的位置约定不同，但对外可见的规则一致：

| 前端 | 存储值层 | 展示翻译位置 |
|------|----------|--------------|
| egui | `GridData.header_rows[].text` / `data[][]` 都存 code | `display_for_header` / `display_for_cell` 在画的瞬间翻译 |
| slint | slint 的 `HeaderCell.text` / `DataCell.text` 直接存展示值（slint 是纯展示层） | Rust 的 `convert::build_grid` 在产出快照时翻译；存储真值由 `AppState.engine` 持有 |

复制/编辑/序列化等业务逻辑在所有前端 **都从存储真值读写**（egui 走 GridData，slint 走 AppState），不会从展示快照里取值。

### 3.3 Table 模式

```
┌────┬──────┬──────┬──────┬────────┐
│    │  A   │  B   │  C   │   D    │  ← 列字母行
├────┼──────┼──────┼──────┼────────┤
│    │英雄ID│ 名称 │ 血量 │ 技能组 │  ← desc (Text)
│    │前后端│前后端│服务器│ 前后端 │  ← export (ExportEnum)
│    │ int  │ str  │ int  │List<int>│ ← type (TypeEnum)
│    │ id   │ name │ hp   │ skills │  ← field (Text，id 列 ReadOnly)
╞════╪══════╪══════╪══════╪════════╡
│  1 │ 1001 │ 战士 │ 100  │ 1;2;3  │
│  2 │ 1002 │ 法师 │  80  │ 4;5    │
│  3 │      │      │      │        │  ← 扩展空行（自动追加 5 行）
└────┴──────┴──────┴──────┴────────┘
```

- 表头固定，不随数据滚动
- 数据行数 = 第一列（ID 列）非空的行数
- 扩展空行允许直接输入新增数据
- ID 列字段名固定 `id`，不可编辑/不可删除（见 @01.5.2）

### 3.4 Constant 模式

```
┌────┬──────────┬───────────┬───────┬──────┬──────────┐
│    │  A       │  B        │  C    │  D   │  E       │
├────┼──────────┼───────────┼───────┼──────┼──────────┤
│    │ name     │ type      │ value │export│ desc     │  ← 固定表头 (ReadOnly)
╞════╪══════════╪═══════════╪═══════╪══════╪══════════╡
│  1 │max_level │ int▾      │ 100   │前后端▾│最大等级 │
│  2 │start_pos │Tuple2…▾   │ 5,10  │前后端▾│出生坐标 │
└────┴──────────┴───────────┴───────┴──────┴──────────┘
```

列定义：name (Text) / type (TypeEnumCol) / value (Text) / export (ExportEnumCol) / desc (Text)。

## 5. 全局与表格区组件

界面有 5 处条形子区域。**Toolbar 与 LogPanel 是顶层全局**，**GridHeaderBar / GridRibbon / FormulaBar / StatusBar 是 GridSection 内部子区域**（与 GridArea 等宽，跟随表格大区）。

### 5.1 Toolbar（顶部全局工具栏）

按钮：[生成测试数据] [清空配置] | [用Excel打开] [保存] [重新加载] | [导出] [导出Schema] [导入Schema]。详见 @6.3 / @6.4。

Toolbar 是单行结构，不放任何与「当前选中表」绑定的开关——表级开关全部下沉到 GridSection 的 GridRibbon。

### 5.2 GridRibbon（表级功能 bar）

GridSection 第二条子区域，类似 Excel 工具栏下面那条「字体/对齐/换行」选项条：放视图开关，仅影响渲染，不改数据、不改公式栏行为。归属表格大区，宽度跟随 GridArea。

```
┌─────────────────────────────────────────────────────────┐
│ [☑] 枚举显示名字   ...                                  │
└─────────────────────────────────────────────────────────┘
```

#### 当前开关

| 开关 | 作用 | 默认 |
|------|------|------|
| 枚举显示名字 | `@EnumName` 单元格只读渲染时显示 entry.name 而非 id | 关 |

#### 不参与切换

- 表引用 `@TableName` 始终显示 id（被引用表可能没有 `name` 字段）
- 编辑场景（公式栏 / 双击编辑）始终是 id（避免「看到名字、改的是 id」的割裂）

### 5.3 FormulaBar（公式栏）

GridSection 第三条子区域，单元格内置编辑组件的「长内容辅助查看 + 编辑」延伸。**仅在选中单元格时显示**；未选中时整条收起为 0 高度。

- 左：当前选中单元格坐标（如 `B3`）
- 右：根据单元格类型决定行为

| 单元格类型 | 公式栏行为 |
|-----------|-----------|
| Text | 可编辑，缓冲 = 真实存储值；Enter / 失焦提交 |
| ExportEnum / ExportEnumCol | 只读展示（与单元格内一致：前后端/客户端/...）。编辑走单元格自身下拉框 |
| TypeEnum / TypeEnumCol | 只读展示类型字符串。编辑走类型选择器弹窗 |
| Ref | 只读展示 id（开关开时显示 enum name）。编辑走引用选择弹窗 |
| 表头单元格（desc/export/type/field 行） | 公式栏不参与，编辑由表头自身的双击/下拉处理 |

设计目的：解决 Text 单元格内容过长被截断（特色单元格内容本身就短，无此需求）。

### 5.4 验证错误展示

数据通过 cell→row→schema→table→project 五层验证（@01.8、@01 附录 A），UI 上的错误反馈分散在多个区域：

| 位置 | 表现 |
|------|------|
| GridArea 数据单元格 | 红色边框（1.5px） |
| GridArea 表头单元格 | 红色边框（1.5px），按错误类型归到对应行：类型/引用错误 → type 行；字段名/关键字/重复 → field 行 |
| StatusBar | 选中单格且该格有错误时，坐标后追加 `⚠ 错误原因` |
| TreeSection 节点 | 状态标记后追加红色 `!` |
| TreeSection 组节点 | 子项有错误时同样追加 `!`（聚合） |
| LogPanel | 加载、保存失败时输出具体错误位置 + 错误信息（@01.附录A.4 格式） |

加载项目时即触发一次 `revalidate_all`，红框/`!` 在打开就可见，不依赖用户先编辑触发；reload / 生成测试 / 清空 后同样会重新跑全表验证。

实时验证开关 `[ui] realtime_validate` 见 @07.4.10.1。

### 5.5 StatusBar（表格状态栏）

GridSection 最末子区域，显示当前选中状态。归属表格大区，与 GridArea 等宽。

| 选中类型 | 显示 |
|---------|------|
| 单格 | `B3` |
| 矩形区 | `B2:D5 (4行×3列，共12格)` |
| 单行 | `第3行` |
| 多行 | `第2-5行 (共4行)` |
| 整列 | `第B列` |
| 鼠标悬停 | 追加 `光标: C4` |

### 5.6 LogPanel（底部全局日志）

顶层第三大区，独立于表格区。带「日志」标题栏 + 可滚动列表区，记录加载 / 保存 / 验证 / 导出等操作输出。

错误级别用颜色区分：info（灰）/ warn（黄）/ error（红）。日志面板高度可拖拽。

## 6. 弹窗组件

### 6.1 模态规则

所有弹窗（类型选择器、引用值选择器、导出对话框、Schema 导入导出、删除确认、命名输入等）遵循 Windows 常规模态规则：

- 弹窗显示时父级 UI 被半透明遮罩盖住，遮罩拦截所有鼠标点击（即父级不可点）
- 多层弹窗时只有最顶层可操作；子弹窗关闭后才能回到父级弹窗，以此类推
- 退出方式：点击「确定 / 取消 / 关闭」按钮，或点击窗口外的遮罩区域（等同取消）；按 Esc 等同取消

按钮排布统一约定（Windows 习惯）：

- 一律**右下角**对齐
- 顺序固定（视觉左→右）：**辅助按钮 → 主操作 → 取消**
  - 例：`[清空] [确定] [取消]`、`[导出] [取消]`、`[导入] [取消]`
- **取消始终在最右**，主操作（确定/导出/导入...）紧邻其左，对齐 Windows 系统对话框习惯
- 实现：通过 `modal::dialog_buttons` 封装 `right_to_left` 布局；行宽用 `ui.min_rect().width()` 撑满已布局的内容宽度（不能用 `available_width()`，在 `Window::resizable(false)` 下值不准确，会导致按钮贴左）

## 7. 保存机制

### 7.1 延迟写盘

所有创建/修改/删除操作只改内存，不立即落盘：
- 新建 Group/Table/Constant/Enum → 内存创建，标记 `is_new` / `dirty`
- 编辑数据 → 改内存，序列化对比自动计算 dirty
- 删除 → 标记 `deleted`，节点仍在树中显示（带 `-`）
- 复制 → 内存复制，标记新建

### 7.2 保存按钮

点击保存时统一处理：
1. 新建组 → `create_dir_all`
2. dirty 节点 → 序列化写 .tbl
3. deleted 节点 → 删除 .tbl 文件，从内存移除
4. 空组 → 删除目录

未保存关闭程序 = 丢弃所有修改。

### 7.3 进程锁

同目录下 `.tbl-tool.lock` 防止多实例编辑同一项目。启动时检查 PID 是否存活。

## 8. 行颜色标记展示

数据行带 `#@c:RRGGBB` 标记时，UI 表格中该行显示对应背景色（详见 @01.9）：

- 仅展示，不提供标色入口（标色在 Excel 中完成）
- 行号列同步显示颜色，便于快速识别

## 9. 退出提示（规划中）

未保存修改时退出 → 弹出确认（保存 / 放弃 / 取消）。

工具使用 Unicode emoji/符号作为 UI 图标，egui 原生渲染无需额外图标库。

### 10.1 已使用

| 符号 | 用途 |
|------|------|
| 📁 | Group 文件夹 |
| 📊 | Table |
| 📋 | Constant |
| 🔢 | Enum |
| ▶ ▼ | 树展开箭头 |
| ☑ ☐ ▣ | 复选框（含半选） |

**状态**：❌ ❗ ✔️ ⏳ 🔄 🚫

**操作**：➕ ➖ ✏️ 🔍 💾 📥 📤 🗑️ 📎

**标记**：🟢 🟡 🔴 ⬤ ○ ● ◆ ◇ ★ ☆

**结构**：📄 📂 🏷️ 🔗 📐 ⚙️

### 10.3 框架兼容性

| 框架 | 彩色 emoji | 单色符号 | 备注 |
|------|-----------|---------|------|
| egui | ✅ | ✅ | 走系统字体 fallback，开箱即用 |
| Slint | ✅ | ✅ | 需确保字体 fallback 链含 emoji 字体 |
| fltk | ❌ | ✅ | 字体引擎不解析 color emoji 表（COLR/CBDT/sbix） |

fltk 兼容替代见 @03.

### 10.4 使用建议

- egui 默认字体支持大部分 emoji 渲染
- 组合符号（如 ⚠️ = U+26A0 + U+FE0F）在某些字体下可能显示为文本样式
- 单色符号（▶▼☑☐▣●○）渲染最稳定
- 彩色 emoji 依赖系统字体，Windows/macOS 表现一致
