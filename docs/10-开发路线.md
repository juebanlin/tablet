# 开发路线

## 开发阶段

整体分两大阶段：

1. **UI 工具** — 能创建/编辑数据并产生合法的 .tbl 文件
2. **验证导出** — 能校验 .tbl 并生成 server/client 产物

## 开发顺序

```
阶段一：UI 工具（核心编辑链路）

S1. 基础框架
    ├─ egui 窗口 + 左右分栏布局
    ├─ tbl-tool.toml 读取
    └─ 扫描 config/ 目录构建树形结构

S2. .tbl 格式解析/序列化
    ├─ 解析 #mode, #index, #desc, #type, #export, #field, 数据行
    ├─ 序列化回 .tbl 文本
    └─ 内置基础类型（int, str, long, float, bool）

S3. 树形结构 + 浏览
    ├─ 左侧树展示 Group / Table(📊) / Constant(📋)
    ├─ 点击节点右侧展示表头 + 数据预览
    └─ 右键菜单（新建 Group / Table / Constant）

S4. 表头编辑
    ├─ 类型下拉选择（内置类型列表 + 示例展示）
    ├─ 导出下拉（前后端/客户端/服务器/不导出）
    ├─ 字段名、描述编辑
    └─ 新建时初始化表头模板

S5. 数据编辑
    ├─ UI 内表格编辑单元格
    ├─ 新增行 / 删除行
    └─ 编辑产生临时文件（.tbl.tmp）

S6. 保存机制 ✅
    ├─ 延迟写盘（新建/编辑/删除仅修改内存）
    ├─ 脏标记（序列化对比 original 快照）
    ├─ 状态标记（绿+ 黄* 红-）+ 组状态聚合
    ├─ 保存按钮统一写入/删除 .tbl 文件
    ├─ 进程锁（.tbl-tool.lock + PID 检查）
    └─ 树过滤器（全部/改动/新增/修改/删除 + 完整组）

S7. 节点操作 ✅
    ├─ 删除（标记待删除，保存后生效）
    ├─ 重命名
    ├─ 复制（延迟写盘）
    └─ 树面板重写（手动展开状态 + 统一右键菜单）

S8. Excel 桥接
    ├─ tbl → xlsx 生成（整个 Group 一个文件）
    ├─ 行颜色标记：tbl 行尾 #@c:RRGGBB → xlsx 行背景色
    ├─ open::that() 调起 Excel
    ├─ 后台检测关闭 → xlsx → .tbl.tmp
    ├─ xlsx 回读行背景色 → 写入/移除 #@c: 标记
    ├─ UI 只读展示行颜色（不提供标色入口）
    └─ 容错（超时、崩溃恢复、残留检测）

S9. 复合类型扩展
    ├─ IntPair, StrPair, IntTriple, Array<T>, Map<K,V>
    └─ types.toml 分隔符配置读取
```

```
阶段二：验证导出

S10. 验证系统
     ├─ 致命错误检测（表头结构）
     ├─ 表头验证（类型合法性、字段名重复、主键存在）
     ├─ 数据验证（类型匹配、分隔符规则、主键重复）
     └─ 错误定位（标红 + 提示信息）

S11. 导出 — 数据文件
     ├─ .tbl → JSON 转换（按 export 标记过滤字段）
     ├─ 按 Group 子目录输出
     └─ snake_case → camelCase 字段名转换

S12. 导出 — 后端模板类
     ├─ 生成 ITpl / IConstTpl 接口
     ├─ 生成 types 子包（IntPair 等）
     ├─ 生成各 Group 下的 Tpl 类
     └─ 生成 TplHolder（含注册列表）

S13. 导出 — 前端文件
     ├─ .tbl → Lua 转换（按 export 标记过滤字段）
     ├─ 按 Group 子目录输出
     └─ 数据内嵌格式

S14. 导出前验证
     ├─ 对比已有生成产物与当前 .tbl
     ├─ 列举已删除/重命名的配置
     └─ 确认后清理旧文件 + 执行生成
```

## 推荐开发顺序的理由

- S1-S3 先跑通"能看到数据"的最小闭环
- S4-S5 让策划能实际编辑，产生合法 .tbl
- S6 是编辑的安全网，必须在 Excel 桥接之前完成
- S8 依赖 S2（序列化）+ S6（保存机制），放在 UI 编辑稳定后
- S10 验证系统独立于导出，可以先做——保存时就需要验证
- S11-S13 三个导出互相独立，可并行开发
- S9 复合类型可以延后，基础类型足够跑通全流程

| 决策 | 选择 | 理由 |
|------|------|------|
| 中间格式 | 自定义 .tbl v2 文本 | Git 友好，行级 diff |
| 分片 | 暂不实现 | 大多数表不超过几千行，Git merge 能力足够 |
| 类型系统 | 工具内置，配置仅控制分隔符 | 简单可控，升级发新版本 |
| ctype/stype | 不拆分，统一 type + export 标记 | Lua 无静态类型，差异在导出而非类型 |
| 数据模式 | Table + Constant 两种 | 覆盖行列数据和离散常量两种场景 |
| Group 映射 | 文件夹 = Group = Excel | 直观，文件管理器可读 |
| 树形命名 | Group → Table / Constant | 不使用 Sheet 术语，模式即类型 |
| 数据编辑 | UI 内编辑 + Excel 编辑并存 | 小改动用 UI，大批量用 Excel |
| 导出选项 | 中文（前后端/客户端/服务器/不导出） | 策划友好，零理解成本 |
| 写回安全 | 延迟写盘 + 保存按钮统一处理 | 简单可靠，未保存关闭=丢弃 |
| 并发控制 | 进程锁(.tbl-tool.lock) + Git | 防多实例，文本格式冲突易解决 |
| 常量导出 | 默认双端，可选限制 | 常量通常全局使用 |
| 生成类命名 | .tbl文件名 + Tpl 后缀，大写驼峰 | 与源文件对应，清晰可追溯 |
