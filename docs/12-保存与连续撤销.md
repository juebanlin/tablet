# 保存与连续撤销

> 状态：实现中，待 GUI 验收（P0–P3 已落地；本文档同时作为设计与验收清单）。
> 已同步 @04.5.1（Toolbar）、@02.26.4（还原）与 @07.S28。

## 1. 目标与结论

把「保存」从「全部项目一起落盘」改成「保存当前项目」，并在保存前提供类似 Excel 的连续撤销/重做：

1. **Project = 一个 Excel 工作簿**，Group / 节点 = 工作簿里的 sheet。
2. **撤销/重做是内存事务**，每个 Project 一份历史栈；切换项目不清栈，Ctrl+Z 只作用于 active project。
3. **保存 = 当前项目的提交点**。保存成功后清空该项目的撤销和重做；其它项目的历史不动。
4. **保存失败不清栈**：验证错误、xlsx 被 Excel 占用、写盘失败都保留历史，让用户修。
5. **`.data` 不承担撤销栈**。撤销是会话内状态；`.data` 继续只放列宽等本机用户习惯。
6. **跨项目复制粘贴按目标项目记账**：复制不产生事务，粘贴到 B 才是 B 的一个事务。

### 1.1 为什么不把撤销栈放进 `.data`

- 保存成功即清栈，持久化历史没有使用场景。
- 保存前改名/删除的磁盘动作本来就延迟到保存（@02.26.1），内存回滚足够；保存后再撤销需要反向操作磁盘，复杂且危险。
- 分支切换后旧历史是 stale 的，持久化会制造「撤销到另一个分支」的歧义。
- 多项目分栈用内存 map 很自然；放进 `.data` 还要处理 project 维度、版本和序列化。

## 2. 现状与差距

| 现状 | 影响 |
|---|---|
| `ProjectEngine.projects: Vec<Project>` + `active_idx` 已支持多项目同时打开 | 不需要新增工作区模型 |
| 工具栏「保存全部」调用 `save_all_projects()` | 改为保存 active project；`save_project(id)` 已有 |
| `save_all_projects()` 有全局验证闸门 | 一个项目有错会挡住所有项目；按项目保存后自然解耦 |
| 改名 / 删除的磁盘动作延迟到保存（`apply_pending_renames`、`deleted` 标记） | 保存前撤销只需回滚内存，和提交点天然对齐 |
| 没有历史栈 | 需要新增 `EditHistory`、事务快照、撤销/重做 API |
| 树用 `⭐` 标 active project | 保留；但它不足以表达「撤销按钮作用于谁」，Toolbar 需要明确标签 |
| 列宽等视图状态走 `.data` | 保持独立，不进业务撤销栈 |

## 3. 事务模型

### 3.1 一次用户动作 = 一个事务

| 操作 | 事务粒度 |
|---|---|
| 单元格提交（Enter / 失焦） | 1 步；不按每个按键记 |
| 区域粘贴 / 多格清空 | 1 步 |
| 行插入 / 删除、列插入 / 删除 | 1 步 |
| 表头字段、规则、显示字段修改 | 1 步 |
| 节点重命名 / 删除 / 粘贴 | 1 步 |
| Group 新建 / 重命名 / 删除 / 粘贴 | 1 步 |
| 复制到剪贴板 | **不产生事务**（源项目不变） |
| 粘贴到另一个项目 | 目标项目 1 步 |
| 打开 / 关闭 / 新建 / 删除项目 | **不进项目撤销栈** |
| 保存、导出、重新加载 | **不进撤销栈** |
| 列宽、展开、选中、滚动 | **不进撤销栈**（视图状态） |

节点重命名会连带改引用、schema 投影等，必须把受影响内容放在**同一个事务**里；撤销时一次全退。

### 3.2 快照作用域

遵循 @07.S28 已定的「快照式」方向：不为每个操作手写 apply/undo 逆函数，撤销/重做都是把一份快照写回状态。按改动范围分三档，避免每一步都 clone 整个 Project：

| 类型 | 用途 | 内容 |
|---|---|---|
| `CellSnapshot` | 数据格 / 表头格 | `project + group + kind + node + row + col + before + after` |
| `NodeSnapshot` | 单节点内修改：行增删、字段、规则、显示字段 | 节点的可编辑内容 + `saved` / `deleted` 等结构状态 |
| `ProjectSnapshot` | 跨节点 / 跨组：节点或 Group 改名、粘贴、Group 增删、列删除 | 项目可编辑内容（groups / schema meta+separators / config）+ 结构状态 |

约束：

- **快照不包含 `original_*` 基线，也不直接恢复 `dirty`。** 撤销/重做后由现有 `update_dirty()` / `is_dirty()` 重新算；否则保存部分失败时会把基线一起拉回去。
- 快照恢复后调用 `resync_schema()` 或对应节点的同步逻辑，再 revalidate；不要绕过正常写回路径。
- 结构操作少，`ProjectSnapshot` 可以接受整项目内容快照；单元格编辑必须走 `CellSnapshot`，否则万行表会很重。
- 每个 Project 的历史上限 **100 步**（与 Excel 默认 100 级一致）；超出丢最旧。上限是常量，后续可调。

### 3.3 历史栈与生命周期

```text
ProjectEngine
  histories: HashMap<ProjectId, EditHistory>

EditHistory {
  undo: Vec<Transaction>,
  redo: Vec<Transaction>,
}

Transaction {
  label: String,          // 日志 / 将来 tooltip 用，如「输入单元格」「重命名节点」
  ops: Vec<EditOp>,       // CellSnapshot / NodeSnapshot / ProjectSnapshot
}
```

| 事件 | 对历史栈的处理 |
|---|---|
| 切换 active project | 不清；按钮状态切到该项目的栈 |
| 新事务 | push 到该项目 undo，清空该项目 redo |
| 撤销 | 从 undo 弹出，恢复 before，push 到 redo |
| 重做 | 从 redo 弹出，恢复 after，push 到 undo |
| 保存该 Project 成功 | 清空该项目的 undo + redo |
| 保存失败 | 保留 |
| 关闭 Project / 删除 Project | 删除该项目的栈 |
| 重新加载工作区 | 清空全部栈（模型已整体替换） |
| 外部 xlsx 重载 | 清空该项目的栈（这是新基线，不是编辑器动作） |
| 规则面板「取消」 | 恢复到打开面板时的历史检查点，面板内的临时规则事务一起收掉 |

撤销/重做执行期间必须进入「禁止记录」状态，不能把恢复动作再记成新事务。

## 4. UI 设计

### 4.1 Toolbar 布局

现有 Toolbar 只有 `[保存全部] [重新加载]`。改成：

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ [撤销] [重做] │ [保存] [重新加载]  当前项目：SLG 测试 ●                      │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **左侧第一组**：`撤销` / `重做`。按钮文字用「撤销」「重做」，不用 `↶` / `↷` —— 现有字形表已证明这类箭头在 Windows 字体链里不可靠（@04.10）。
- **术语**：这里的「撤销 / 重做」就是历史栈里的「后退 / 前进」；UI 采用 Excel / VSCode 的「撤销 / 重做」叫法，避免和页面导航的「前进 / 后退」混淆。
- **左侧第二组**：`保存` / `重新加载`。`保存` 的作用域从「全部项目」改为「active project」。
- **按钮组后方**：`当前项目：<name>`，紧接在「重新加载」之后（不再依赖布局 stretch 把它推到远端；Slint 的 `horizontal-stretch` 在 Toolbar 里实测不生效）。
  - 名字使用树当前显示口径：`[ui] show_meta_id` 为 true 时显示 id，否则显示 name。
  - 无 active project 时显示 `当前项目：—`，撤销/重做/保存禁用。
  - 有未保存改动时名字后加 `●`（颜色用主题的修改/警告色，具体色值实现时定），无改动不显示。
- **Toolbar 仍是单行 32px**，不引入第二行。最小窗口 800px 下四个按钮 + 标签仍可容纳；若实际测量不够，优先缩短标签为「项目：<name>」，不要隐藏撤销/重做。
- **「保存全部」不在主按钮区**：
  - 工具栏主按钮只保存当前项目，符合 Excel 心智。
  - 如仍需要全部保存，放进 MenuBar 的 `文件` 菜单（见 @4.6），不占 Toolbar。
- **点击按钮前先 `drop-focus`**：现有 Toolbar 点击已经会提交正在编辑的单元格；撤销按钮点击后应撤销刚刚提交的那一步，行为一致。

### 4.2 为什么把「当前项目」放 Toolbar，而不是 StatusBar

- 撤销/重做是**项目级全局命令**，目标必须显示在按钮附近；StatusBar 属于 GridSection，跟当前选中节点走，用户没选中节点时表达力更弱。
- Tree 的 `⭐` 继续保留，作为「哪个项目是 active」的空间提示；Toolbar 标签是命令目标的明确文字说明。两者不冲突，也不需要在 StatusBar 再复制一份。
- 也不放 GridRibbon：GridRibbon 是**表级**控件区（显示引用名称、Excel 编辑等），而撤销栈是**项目级**；放那里会让人误以为只撤销当前表。
- 若以后需要显示「撤销 N 步 / 重做 M 步」，也放在 Toolbar 标签右侧或按钮 tooltip，不放进 StatusBar。

### 4.3 树的 active 标记

- 保持现有 `⭐` 和项目行脏标记，不改树结构。
- 切换 active 时，Toolbar 标签和撤销/重做按钮状态必须同步刷新。

### 4.4 按钮启用规则

| 控件 | 启用条件 | 点击结果 |
|---|---|---|
| 撤销 | active project 存在且 `can_undo` | 撤销该项目的上一步 |
| 重做 | active project 存在且 `can_redo` | 重做该项目的下一步 |
| 保存 | active project 存在 | 保存该项目；无修改时只记日志；成功清该项目的 undo/redo |
| 重新加载 | 工作区已加载 | 有未保存改动先确认；确认后重载并清空全部历史 |

- 保存失败时按钮保持可用，历史不清。
- 无 active project（全部项目关闭）时三个项目级按钮全部禁用。
- 撤销/重做后立刻刷新按钮状态；清空后按钮自动变灰。

### 4.5 键盘快捷键

| 快捷键 | 行为 |
|---|---|
| `Ctrl+Z` | 无文本编辑焦点时：撤销 active project |
| `Ctrl+Y` / `Ctrl+Shift+Z` | 无文本编辑焦点时：重做 active project |
| `Ctrl+S` | 无文本编辑焦点时：保存 active project |

关键边界：

- **正在编辑单元格 / 公式栏 / 搜索框时，`Ctrl+Z` 是文本框自己的撤销**，不能抢。现有 `focus-sink` 只在没有 `LineEdit` / `TextEdit` 抢焦点时收到按键（@05），沿用这条规则即可。
- 点击 Toolbar 的撤销/保存按钮会先 `drop-focus`，即先提交编辑，再执行命令；因此点按钮撤销可以撤掉刚提交的编辑。
- `Ctrl+S` 第一版只在非编辑焦点下生效；编辑中先按 Enter 提交再保存。若实现时发现 Slint 侧能稳定拦截编辑框的 `Ctrl+S`，再补「提交后保存」。

### 4.6 可选：MenuBar 入口（P2）

第一版可以只做 Toolbar + 快捷键。若需要保留「全部保存」和提供可发现的快捷键说明，再加：

```text
文件：保存当前项目  Ctrl+S
      全部保存
      重新加载

编辑：撤销  Ctrl+Z
      重做  Ctrl+Y
```

菜单项的 enabled 状态与 Toolbar 按钮同源，不另算一套。

### 4.7 撤销/重做后的刷新

每次撤销/重做后统一走一次 refresh：

- `revalidate` 对应 Project，更新 `validation_errors` / warnings；
- 刷新树（脏标 / `!`）、grid、公式栏、对话框、日志；
- 若当前选中的节点被撤销掉（例如撤销粘贴、撤销删除的逆操作），选中回退到所属 Group 或 Project，避免选中一个已不存在的节点；
- 清掉不再有效的树展开项 / 列宽运行时缓存；
- 更新 Toolbar 的 active project 标签与按钮状态。

## 5. 保存语义

### 5.1 保存当前项目

- Toolbar「保存」调用 `save_project(active_id)`，不再调用 `save_all_projects()`。
- `save_project` 只检查**该项目**的验证错误；其它项目的错误不阻断。
- 保存成功后：
  1. 写 dirty / deleted 节点，更新 `original_*`；
  2. 清空该项目的 undo/redo；
  3. 刷新树上的 🟡、日志和 Toolbar 标签；
  4. 日志追加一句「已保存 …（撤销历史已清空）」，避免用户疑惑 Ctrl+Z 没反应。
- 保存失败（验证错误 / xlsx `~$` 锁 / 外部改动 / 写盘失败）：
  - 不清历史；
  - 保持 active project 和当前选中；
  - 日志给出原因。

### 5.2 成功判定必须先修可靠

`save_project_files` 目前对 `.tbl` 的 `std::fs::write` 失败没有完整汇总到 `failed`，调用方可能误以为保存成功。实现本机制前必须：

- 让所有节点写失败都进入 `failed`；
- 只有「验证通过 + 无失败」才返回成功；
- 只有成功才清历史。

否则会出现「文件没写进去，撤销历史却被清空」。

### 5.3 保存全部（可选）

如果保留 `保存全部`：

- 逐个项目调用该项目的保存；
- 每个项目成功后清该项目的历史；
- 失败的项目保留历史；
- 不再使用「任一项目有错就全部不保存」的全局闸门。

### 5.4 重新加载 / 关闭项目

| 操作 | 行为 |
|---|---|
| 重新加载 | 若 `is_dirty_any()`，先确认「将丢弃所有未保存改动」；确认后 `engine.reload()`，清空全部历史，重新探测 VCS |
| 关闭 dirty project | 沿用现有确认；确认丢弃后关闭，删除该项目的 history |
| 关闭 clean project | 直接关闭，删除 history |
| 删除 project | 删除 history，不进撤销栈 |
| 外部 xlsx 重载 | 清空该项目的 history |

## 6. 跨项目复制粘贴

- `clipboard_copy_node` / `clipboard_copy_group` 只是深拷贝到进程内剪贴板，**源项目不产生事务**。
- `paste_node_to` / `paste_group_to` 在目标项目产生**一个事务**。
- 粘贴成功后把 active 切到目标项目，并选中新节点；这样 Toolbar 的「当前项目」和 Ctrl+Z 立即指向正确的项目。
- B 保存后清 B 的历史；A 的历史、剪贴板内容都不受影响。
- 跨项目引用不自动补齐：粘贴后由验证报错，用户自行处理；这次粘贴仍可整步撤销。
- 目前没有「剪切」。若以后做跨项目剪切，必须定义成 A 删除 + B 粘贴两个事务，并处理 B 粘贴失败时 A 不删除；不要做成跨项目共享一个撤销栈。

## 7. 边界与暂不做

| 项 | 处理 |
|---|---|
| 撤销跨保存 | 不做。保存即清栈（Excel 心智）；以后若改成 VSCode 式，只需不清栈 |
| 跨重启撤销 | 不做。撤销是会话内状态 |
| 撤销栈写 `.data` | 不做 |
| 列宽 / 展开 / 选中 / 滚动 | 不进撤销；列宽继续走 `.data` 用户习惯 |
| 项目打开/关闭/新建/删除 | 不进撤销 |
| 导出 / 生成代码 / 保存 | 不进撤销 |
| 全局设置（`tablet.toml`） | 工作区级，不并入项目撤销；它有独立的编辑缓冲和取消 |
| 项目设置（meta / export / separators） | 已接入：字段编辑 / 字段级 ↺ / 全部还原各走一次 `edit_project` 事务；关窗后仍可撤销 |
| Schema 合并 / 导入 | 已接入：一次 `edit_active_project` 事务；外部文件重载仍是新基线 |
| Excel 回写 | 已接入：一次 `edit_project` 事务；Excel 同步面板落盘后清该项目历史（内存与工作簿同时变了） |
| 外部 git 分支切换 | 重新加载时重新探测并清空全部历史；是否在保存时主动拦截见 @7.1 |
| 大表内存 | 单元格用 `CellSnapshot`；只对结构操作使用项目快照；100 步上限 |

### 7.1 分支切换

沿用之前的结论：**不硬锁 Git 文件**（`index.lock` / 文件句柄都会伤害正常工具链），以检测和阻止保存为主。

- 重新加载时 `vcs::probe` 重读分支；
- P2 可增加保存前基线检查：当前 HEAD / 分支与加载时不一致时拒绝保存并提示重新加载；
- 分支变化后，用户确认重新加载即清空全部撤销历史。

## 8. 实施拆分

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | `ProjectEngine` 增加 per-project `EditHistory`、`Transaction`、100 步上限、`undo/redo/can_undo/can_redo`；只做核心单测 | 两项目互不影响；栈上限正确 |
| P1 | 单元格 / 表头格编辑接入 `CellSnapshot`；Toolbar 加撤销/重做按钮、当前项目标签、启用状态；快捷键 | 编辑一个格 → 撤销/重做；切项目只影响目标 |
| P2 | 行/列增删、节点改名/删除/粘贴、Group 操作接入 `NodeSnapshot` / `ProjectSnapshot`；项目设置 / Schema 导入 / Excel 回写接入项目事务；跨项目粘贴切 active；选中修复 | 改名带引用撤销；粘贴整步撤销；跨项目只进 B |
| P3 | 保存改为 active project；`save_project_files` 失败返回；保存成功清该项目历史；重新加载/关闭清历史；全部保存（可选） | 保存 A 只清 A；保存失败保留；重载清空 |
| P4 | 文档同步（@04.5.1 / @04.5.5 / @02.26.4 / @07.S28）、日志文案、GUI 手工验收 | 文档与实现一致 |

建议顺序：P0 → P1 → P2 → P3 → P4。P3 的「active 保存」也可以提前到 P1 前，但清历史必须等 P0 完成。

## 9. 测试计划

### 9.1 核心单测

1. 两个项目各自 undo/redo；切换 active 后只操当前项目。
2. 保存 A 成功只清 A 的栈，B 的栈保留；保存 A 失败不清。
3. 撤销单元格编辑回到保存状态时，`dirty` 变 false；重做再变 true。
4. 节点改名（带引用重写）撤销/重做后，名字、引用、schema 投影都恢复。
5. 节点粘贴 / Group 粘贴撤销后节点消失；重做后同名节点恢复。
6. 行/列增删撤销后 records / fields / rules 恢复。
7. 100 步上限：第 101 步丢最旧。
8. 历史不包含 `original_*`；保存部分失败不会把基线撤回去。
9. 跨项目复制粘贴：A 无历史变化，B 多一步；B 撤销不影响 A。
10. 外部 xlsx 重载 / reload 清空对应历史。

### 9.2 GUI 手工验收

- 1280px 和 800px 最小窗口下 Toolbar 不溢出；当前项目标签可读。
- 打开两个项目：切换树节点时标签/按钮状态跟随；A 有历史、B 无历史时按钮状态正确。
- 编辑单元格 → Ctrl+Z / Ctrl+Y；在 LineEdit 内 Ctrl+Z 仍是文本撤销。
- 点 Toolbar 撤销前正在编辑：先提交再撤销。
- 保存 A 后 A 的按钮变灰，B 的仍可用。
- 跨项目粘贴后 active 切到 B，Ctrl+Z 撤销的是粘贴。
- 重新加载 dirty 工作区有确认，确认后历史全空。
- 关闭项目后重新打开，历史为空。

## 10. 风险清单

1. **编辑入口没收拢**：任何绕过统一 mutation 路径的编辑都会成为撤销空洞。先盘点 grid / 表头 / 规则 / schema 面板 / 剪贴板 / xlsx 回读的写入点。
2. **文本编辑抢快捷键**：Ctrl+Z 必须优先给 LineEdit / TextEdit；Toolbar 按钮走 `drop-focus` 提交后撤销。
3. **快照恢复破坏基线**：不要把 `original_*` / `dirty` 放进快照；恢复后重算。
4. **保存部分失败却清栈**：先修 `save_project_files` 的失败汇总。
5. **结构操作跨节点**：改名/删除列/粘贴必须捕获完整受影响范围；不要只存一个格子。
6. **撤销后的选中/展开**：节点可能已不存在；刷新时做选中回退和展开集清理。
7. **跨项目 active**：事务必须按 project id 记账，不能按 `active_idx`；粘贴后切 active。
8. **内存**：项目快照只用于结构操作；单元格快照保持小对象；100 步上限先落地，实测再调。
9. **xlsx 外部变化**：外部重载清栈；保存前继续走现有 `~$` / mtime+size 预检。

## 11. 已确认的产品决策

- 继续叫「保存」，不改名「发布」。
- `Ctrl+S` / 保存按钮 = 保存当前项目，不是全部项目。
- 保存成功清空当前项目的撤销/重做；保存失败不清。
- 撤销/重做按 Project 分栈，切换项目不清栈。
- 节点复制改名、Group 操作和 Excel sheet 操作一样可撤销；复制动作本身不产生事务。
- 当前项目显示在 Toolbar 按钮组后方（撤销/重做/保存之后）；StatusBar 不重复。
- `.data` 不存撤销栈；列宽等视图状态继续独立。
