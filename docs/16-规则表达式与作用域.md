# 规则表达式与作用域

> 状态：设计定稿，按本文重构 `crates/core` 与规则面板（@04.6.10）。
> 本文是规则函数目录、类型分层、存储格式与求值语义的**单一真理源**；
> 实现与文档冲突时以本文为准，先改本文再改代码。

## 1. 目标与边界

把节点级校验从「一堆验证器枚举 + `when` 特例」收敛成一个小型、带类型的规则表达式语言：

- **一套函数、一份实现**：`unique()` 与 `unique(col)` 是同一个函数，只是主列参数在列级作用域里省略、由锚点补；不允许写两份逻辑。
- **两个作用域**：`column`（列级）与 `table`（表级）。行级约束是表级函数的一种**求值粒度**，不是第三种作用域。
- **组合与高阶函数**：`when / and / or` 都是函数，与验证器同级；`when` 是行过滤函数，**不是组**。条件层另有 `and / or / not`。任意规则由「叶子 + 函数」构成。
- **函数分域**：函数声明自己能出现在哪种作用域、读哪些列、逐行还是全表求值；UI/文档/校验从同一份函数目录派生。

明确不做：

- 不做通用查询 DSL（Mongo 风格）或用户自定义函数；
- 不做跨表条件（`ref(...)` 只预留语法位，v1 报「尚未支持」）；
- 不做规则级 `not`；
- 不做第三种作用域（行级不单独成 scope）。

## 2. 类型与业务层级

```text
L0 值 Scalar
 ├─ L1 条件原子 Condition ── L2 条件组合 Condition ──┐
 └─ L3 验证器原子 RuleExpr ──────────────────────────┴─ L4 规则组合 RuleExpr
                                                          └─ L5 规则绑定 Rule
                                                                └─ L6 系统内置 Rule（只读）

判断域：L0–L2    校验域：L3    编排域：L4    归属域：L5    系统保证：L6
```

| 等级 | 业务层 | 类型签名 | 依赖 | 可用位置 |
|---|---|---|---|---|
| L0 | 数据 | `Scalar` | — | 任何参数位置 |
| L1 | 判断原子 | `(Scalar, Scalar) -> Condition` | L0 | `when` 条件、L2 |
| L2 | 判断组合 | `(Condition...) -> Condition` | L1 / L2 | `when` 条件 |
| L3a | 列域校验原子 | `(Scalar col, ...) -> RuleExpr` | L0 + scope | 列级规则体；表级规则体（显式列） |
| L3b | 行级校验原子 | `(Scalar col...) -> RuleExpr` | L0 + Table | 表级规则体 |
| L3c | 全表校验原子 | `(...) -> RuleExpr` | Table | 表级规则体 |
| L4 | 规则组合 | `(Condition, RuleExpr) -> RuleExpr` / `(RuleExpr...) -> RuleExpr` | L2 / L3 / L4 | 规则体 |
| L5 | 规则绑定 | `(RuleExpr, Scope, Level) -> Rule` | L4 | `.tblschema` / `project.tblmanifest` |
| L6 | 系统内置 | `Rule(source=builtin)` | L5 | 自动生效、只读 |

L1/L2 只产生布尔，**不能单独作为规则体**；L3/L4 产生违规集合；L5 才把规则挂到列/表上。

## 3. 作用域与求值粒度

| 概念 | 取值 | 说明 |
|---|---|---|
| scope（作用域） | `column <列名>` / `table` | 规则归属、错误锚点、省略主列参数的来源 |
| granularity（粒度） | `Row` / `Table` | 函数求值方式，决定错误归属；不是用户可选的作用域 |
| primary_column | `Option<usize>` | 列域函数的主列参数下标；列级作用域里可省略，由锚点补 |

- **列级**：目标列存在且是标量；规则体只能使用列域函数（L3a）与组合子（L4）。主列参数省略时补锚点列；列级规则**不允许显式写主列参数**（需要别的列请用表级规则）。
- **表级**：`table:` 只能用于 Table 节点。可使用列域函数（列参数必须显式）、行级函数、全表函数与组合子。
- 行级/全表函数没有主列参数，只能在 `table:` 里使用。

粒度与 scope 的组合：

| scope | 典型粒度 | 错误归属 |
|---|---|---|
| column | Row（`non_empty` 等）或 Table（`unique`） | 锚点列单元格；`unique` 报在重复行 |
| table · 行级函数 | Row | 行号 + 受影响列 |
| table · 全表函数 | Table | 表级错误，或可定位到行（`id_contiguous`） |

## 4. 存储格式

```toml
# @rule column <列名>: <表达式> [error|warn|info]
# @rule table: <表达式> [error|warn|info]
```

- 级别缺省 `error`；行尾 `[...]` 与现状一致。
- `column` 的列名 = 错误锚点 + 省略主列参数时的默认列。
- 规则只住在 `project.tblmanifest` 的段内；不写 `.tbl`、不进 Excel。
- 旧格式 `# @rule: <列> = <表达式>` **废弃**，加载时直接报错（项目不做旧格式兼容，@CLAUDE.md）。

### 4.1 多规则与整体结果

- 同一作用域可以有多条 `# @rule` 行，**规则之间完全独立**：不共享括号，也不能跨规则写
  `and/or`。需要组合时把成员放进同一条规则。
- 每条规则有自己的级别（`error` / `warn` / `info`）。级别属于规则边界，不属于单个验证器。
- 校验结果是**聚合**：各规则分别求值，Issue 按级别汇总；`error` 阻断保存，
  `warning` / `info` 默认只报告。项目策略（`project.toml` 的 `[validate]`）可以改变
  各等级的处置；`validate --strict` 把所有「仅提示」也算失败。
- 不要用「一条规则内混级别」来表达告警：拆成多条规则各带级别。

## 5. 函数目录

### 5.1 L0 数据（Scalar，不是函数）

| 写法 | 参数描述 | 作用 | 说明 |
|---|---|---|---|
| `列名` | 裸标识符 | 取本节点当前行的列值 | 条件、验证器通用 |
| `"字符串"` | 引号字符串 | 字面量 | 含逗号/空格/正则时加引号；反斜杠原样保留 |
| `1` / `1.5` / `true` | 数字 / 布尔字面量 | 字面量 | 不加引号 |
| `ref(关联列, 节点.列)` | 关联列 + 目标节点.列 | 跨表取值 | **预留，未实现**；写入报错 |

### 5.2 L1 条件原子（Condition）

| 函数 | 参数描述 | 作用 | 约束 |
|---|---|---|---|
| `eq(a, b)` / `ne(a, b)` | a/b = Scalar（列或字面量） | 等于 / 不等于 | 按列类型归一化（`01 == 1`） |
| `lt(a, b)` / `le` / `gt` / `ge` | 同上 | 大小比较 | 两边必须是数值 |
| `in(col, v1, v2, ...)` | 第一个必须是列，后面是字面量 | 属于候选集合 | 至少一个候选值 |
| `match(col, "正则")` | 第一个必须是列 | 正则匹配 | 整串匹配写 `^...$` |

条件允许列与列比较（`eq(a, b)`），两边都显式；条件只读本节点当前行，不支持跨表。

### 5.3 L2 条件组合（Condition）

| 函数 | 参数描述 | 作用 | 约束 |
|---|---|---|---|
| `and(c1, c2, ...)` | ≥ 2 个 Condition | 全部成立 | 只能读本节点当前行 |
| `or(c1, c2, ...)` | ≥ 2 个 Condition | 任一成立 | 同上 |
| `not(c)` | 1 个 Condition | 取反 | 同上 |

### 5.4 L3a 列域校验原子（RuleExpr）

列级写法省略主列参数；表级写法必须显式。

| 函数 | 参数（列级 / 表级） | 作用 | 粒度 | 适用列 | 状态 |
|---|---|---|---|---|---|
| `unique(col)` | `unique()` / `unique(col)` | 非空值在节点内不重复 | Table | 全部标量 | 现有 |
| `non_empty(col)` | `non_empty()` / `non_empty(col)` | 必填；整行全空占位行不算 | Row | 全部标量 | 现有 |
| `range(col, min, max)` | `range(min, max)` / `range(col, min, max)` | 数值区间，留空一侧不限 | Row | int / long / float | 现有 |
| `len(col, min, max)` | `len(min, max)` / `len(col, min, max)` | 字符数区间，留空一侧不限 | Row | str / txt | 现有 |
| `one_of(col, v...)` | `one_of(v...)` / `one_of(col, v...)` | 值属于候选集合 | Row | 全部标量 | 现有 |
| `matches(col, "正则")` | `matches("正则")` / `matches(col, "正则")` | 正则匹配 | Row | str / txt | 现有 |
| `ref_exists(col, 节点.列)` | `ref_exists(节点.列)` / `ref_exists(col, 节点.列)` | 值必须存在于目标列 | Row | 全部标量 | 现有 |
| `compare(col, op, other)` | `compare(op, other)` / `compare(col, op, other)` | 与另一列比较；`op` = `< <= > >= == !=` | Row | int / long / float | 现有（显式化） |
| `positive_int(col)` | `positive_int()` / `positive_int(col)` | 必须是正整数 | Row | int / long | 开放给用户 |
| `upper_snake(col)` | `upper_snake()` / `upper_snake(col)` | 必须 UPPER_SNAKE_CASE | Row | str / txt | 开放给用户 |

**语法糖（仅解析，不序列化）**

| 函数 | 展开 | 说明 |
|---|---|---|
| `required_if(条件列, 值)` / `required_if(col, 条件列, 值)` | `when(eq(条件列, 值), non_empty(col))` | 列级省略 `col`；表级显式 |

### 5.5 L3b 行级校验原子（RuleExpr，仅 table）

| 函数 | 参数描述 | 作用 | 粒度 | 状态 |
|---|---|---|---|---|
| `all_non_empty(col1, col2, ...)` | ≥ 2 个标量列 | 这些列都必须有值 | Row | 新增 |
| `at_least_one(col1, col2, ...)` | ≥ 2 个标量列 | 至少一列有值 | Row | 新增 |
| `exactly_one(col1, col2, ...)` | ≥ 2 个标量列 | 恰好一列有值 | Row | 新增 |

### 5.6 L3c 全表校验原子（RuleExpr，仅 table）

| 函数 | 参数描述 | 作用 | 粒度 | 状态 |
|---|---|---|---|---|
| `row_count(min, max)` | 最小/最大非占位行数；可空一侧 | 行数在区间内 | Table | 新增 |
| `id_contiguous()` | — | id 集合恰好是 `1..=N`（N = 非占位行数） | Table | 新增 |
| `unique_combination(col1, col2, ...)` | ≥ 2 个标量列 | 列组合在表内不重复；任一分量为空的行跳过 | Table | 新增 |
| `no_empty_rows()` | — | 不允许整行全空的占位行 | Table | 第二批（先不实现） |

### 5.7 L4 规则组合（RuleExpr）

| 函数 | 参数描述 | 作用 | 约束 |
|---|---|---|---|
| `when(条件, 规则表达式)` | L2 Condition + RuleExpr | 条件成立的行才执行 | 作为**行集合过滤器**：全表函数也只统计命中的行（`unique` 带条件 = 命中行内查重） |
| `and(规则表达式...)` | ≥ 1 个 RuleExpr | 全部通过；各叶子失败各自报错 | 列级/表级均可 |
| `or(规则表达式...)` | ≥ 2 个 RuleExpr | 任一通过；全失败合成一条错误 | 仅允许 Row 粒度的子表达式（v1） |
| `not(...)` | — | 不支持 | `not` 只用于条件 |

`when` 是函数（行过滤），不是组；组只由 UI/表达式里的括号和嵌套表达。条件和验证器都按行用 `and/or` 连接。

### 5.8 L6 系统内置（只读）

| 节点 | 内置规则 |
|---|---|
| Table | `id`：`unique` / `non_empty` / `positive_int` |
| Enum | `id`：`unique` / `non_empty` / `positive_int`；`name`：`unique` / `non_empty` / `upper_snake` |

- 内置规则由同一套函数构造，`source = Builtin`；不落盘、不可编辑、不可删除。
- 用户规则与内置规则完全等价（同目标列 + 同一个无条件的单验证器）时，只报一条 `RuleRedundant` 非阻断警告。

## 6. 解析与序列化规则

### 6.1 主列参数

- 列级规则：列域函数的 `primary_column` **一律省略**，由 `column <列名>` 补；写出来也报错（避免两种写法）。
- 表级规则：列域函数的所有列参数必须显式；行级/全表函数的列参数本来就是显式列表。
- 这条规则保证同一个函数只有一套签名与一份实现，不出现 `unique` / `unique(col)` 两套逻辑。

### 6.2 序列化

- 列级规则 → 列域验证器一律省略主列，无论是否包在 `when/and/or` 里：
  `non_empty()` / `when(eq(type, 1), matches("^\\d+$"))`。
- 表级规则 → 一律显式：`all_non_empty(value, price)` / `non_empty(value)`。
- `required_if` 只解析、不序列化；加载后展开成 `when(...)`。
- 规范输出顺序不变：段头 → 字段行 → `# @display` → `# @rule` → `# @preset`。

### 6.3 条件

- `when` 第一个参数是条件上下文；`and/or/not` 在条件上下文里组合条件。
- 规则体 / `when` 第二个参数是规则上下文；`and/or` 在规则上下文里组合规则表达式。
- 同名 `and/or` 由上下文决定类型，不需要不同函数名。

## 7. 求值与错误归属

- 每个验证器叶子产生 `Issue { row, column, affected, message, code }`。
- `and`：合并所有子表达式的 Issue。
- `when`：按条件过滤行，再求值 `inner`。
- `or`（Row 粒度）：逐行判断；任子表达式在该行通过则通过；全部失败时合成一条 Issue，`message` 列出候选，`affected` 取并集，锚点取第一个受影响列。
- 列级规则：错误锚定 `column <列名>`；`unique` 的 Issue 落在重复行。
- 表级行函数：`row` = 当前行，`affected` = 函数声明的列，锚点 = 第一个列。
- 表级全表函数：
  - `row_count` / `no_empty_rows`：表级错误（`row = TABLE_ROW`）；
  - `id_contiguous` / `unique_combination`：能定位到行时带行号，否则表级。
- `ValidationError` 新增 `affected: Vec<String>`；新增 `TABLE_ROW` 哨兵（区别于 `SCHEMA_ROW`）。
- 级别：整条规则一个 `level`；`or` 合成错误沿用规则级别。

## 8. Schema 校验

加载/保存前必须拦下：

- `column` 目标列不存在、是复合类型；`table` 用在 Enum / Constant 上。
- 函数不在当前 scope（例如列级规则里出现 `all_non_empty`、`row_count`）。
- 列参数不存在、是复合类型、类型不满足函数要求。
- 主列参数在列级规则里被显式写出；表级规则里缺少列参数。
- `range/len` 两端都空、`row_count` 两端都空、边界不是数字、下限大于上限。
- `matches` 空正则或非法正则；`one_of` 无候选；`row_count` 非法。
- `and` 少于 1 个子项；`or` 少于 2 个子项；`or` 含 Table 粒度子表达式。
- 条件列不存在/复合；大小比较用在非数值；条件两边都是字面量；`in`/`match` 第一个参数不是列。
- 重复规则；与内置规则等价（`RuleRedundant`，非阻断）。
- `ref_exists` 目标节点不存在/重名/目标列不存在/复合；不能是本列自己（同节点同列）。
- `compare` 引用的列不能是本列自己；两列都必须是数值。
- 表级函数引用的列不能重复？允许重复但报参数无意义（v1 可报 `RuleParamInvalid`）。

## 9. UI 模型（@04.6.10）

**列规则和表级规则共用同一套逐行组合编辑器**。一个组是「条件函数行 + 验证器行」的混合列表；
**组和函数都通过每行的 `and/or` 连接**：

- `eq/ne/lt/le/gt/ge/in/match` 是**条件函数**，不是组、也不是 `when` 容器；
  `unique/...` 是**验证器函数**。两者都是同一层的函数行。
- 条件行是**同组验证器的行过滤**：`type=1 and unique()` 编译为 `when(eq(type,1), unique())`；
  嵌套组继承外层条件。
- `when` 是磁盘上的**函数**（行过滤函数），不是 UI 里的组节点；UI 只显示条件函数行和验证器行。
- 同一组内按行序编译：`and` 优先、`or` 分段；显式括号就是子组。
  例：`A and B or C and D` = `or(and(A,B), and(C,D))`。

UI（@04.6.10）：

- 顶部 Tab：`列规则` / `表级规则`（Table 才有后者；Enum 只有列规则）。
- 右侧编辑器只有两个视图：`自定义规则` / `系统规则`。系统规则只读，不参与编辑和合并。
- **自定义规则 = 纵向规则卡片**，一条规则一张卡，没有单独的规则列表：
  - 卡片头：`规则 N` + 级别下拉 + 截断的表达式摘要 + `收起/展开` + `删除`。
  - 卡片体：隐式根组（不画外层括号，右侧 `合并`）+ 逐行组合树 + 表达式预览。
  - 卡片之间完全独立；保存时按卡片顺序写成多条 `# @rule`。
  - 未保存改动全局标记；顶部 `还原` 丢弃草稿，`保存规则` 一次写回全部卡片。
  - 有未保存改动时切换作用域 Tab / 列：显示内联确认条（`丢弃并切换` / `取消`），
    确认后重新加载目标作用域，未保存草稿随之丢弃。
  - 底部固定「＋ 新建规则」，新增一张只含一个默认验证器的卡片。
- 每张卡片都使用同一套逐行组合编辑器，不再有「简单 / 高级 / 高级2」模式：
  - 普通行：类型标签 + 只读函数摘要（条件显示列/运算符/值，验证器显示当前参数）
    + 行尾 `and/or` + 固定操作列。
  - 组头：`(` + 「组」；组尾：`)` + 对外 `and/or` + 操作列。
  - 操作列：`+行`（插入默认函数行）、`+组`（插入一个默认带一行的组）、`删除`；
    组尾额外有 `分散`（取消组、成员原位展开到上一层）。
  - 根组右侧 `合并`：把根层所有成员包进一个组（根层少于 2 项时置灰）。
  - 新插入的连接默认 AND；空组被删空后自动移除；新组默认带一个成员。
- 参数和说明在**下方 Inspector**，不在行内：
  - 上面是卡片滚动区，下面是固定高度 Inspector；左侧参数、右侧说明/适用/示例。
  - 点击任意卡片里的条件 / 验证器行选中并加载 Inspector；`+行` 新增后自动选中。
  - 未选中时显示占位提示；选中项被删除后 Inspector 清空。
  - 卡片区滚动、Inspector 内部滚动；固定高度避免界面跳动。
- 列级主列由左侧锚点提供；表级规则在 Inspector 显式选主列。
- 规则改动是草稿：`保存规则` 写回节点，`确定` 写回并关闭，`取消` 恢复到打开面板时的快照。
- 存储不变：manifest 仍是每条规则一行 `# @rule`；多条规则 = 多行，按行序执行。
  条件归一化为 `when(条件组, 验证组)`；`not(...)` / 列与列比较条件 v1 仍由 schema 手写。
- 不做单独的文本模式；行内只读摘要，完整参数/说明统一在下方 Inspector。

## 10. 扩展指南

新增一个验证器：

1. 在函数目录（本文 §5）加一行：名字、scope、primary_column、粒度、参数、状态、说明。
2. 在 `rules.rs` 的验证器枚举加一个变体（带类型化参数）。
3. 在 parser 的“名字 → 变体”分支加一条；参数解析复用目录里的签名。
4. 在 evaluator 加一个分支：按粒度逐行或全表求值，产出 Issue。
5. 在 schema 校验里补列类型/参数检查。
6. 测试三件套：解析→序列化往返、合法/非法 schema、求值与错误归属。
7. 文档/技能从本文同步。

组合子（`when/and/or`）与作用域只允许在上述模型内扩展；不要为单个验证器新增 `xxx_if` 变体——用 `when`。

## 11. 迁移与实施顺序

1. **核心模型**：`RuleTarget` / `RuleExpr` / 验证器枚举 / 函数目录 / `Rule.affected` 错误模型。
2. **Parser/序列化**：新 directive（`column` / `table`）、主列参数省略规则、`required_if` 展开、旧格式报错。
3. **求值**：Row/Table 粒度、`and/or/when`、错误归属、`TABLE_ROW`。
4. **Schema 校验**：scope/域/参数/重复/内置冲突。
5. **UI**：表级 pseudo-item、函数面板分域、条件常态化、去掉 `when` 类型。
6. **全量迁移**：`# @rule` 语法、内置规则、测试、docs、skills。

## 12. 明确不做 / 预留

| 项 | 状态 |
|---|---|
| `ref(...)` 跨表取值/条件 | 预留语法位，v1 报「尚未支持」 |
| 规则级 `not` | 不做 |
| 第三种 scope（row） | 不做；行级是粒度 |
| 用户自定义函数 / 通用查询 DSL | 不做 |
| `no_empty_rows` | 第二批 |
| 行级/全表函数的条件（`when`） | 允许；`when` 统一作为行集合过滤器 |
| `or` 组合全表函数 | v1 禁止 |
| 跨表规则/聚合 | 不做 |

## 13. 关键决策记录

1. **一个函数一份实现**：主列参数由 scope 省略/补齐，不写 `unique` 与 `unique(col)` 两套。
2. **两个 scope，不是三个**：列级与表级；行级是表级函数的求值粒度。
3. **列级规则保留**：它是最常用心智模型、内置规则的归属、错误锚点与 UI 主流程；不是第二套引擎。
4. **`when/and/or` 同级**：都是 L4 组合子；`and/or` 在条件/规则两个上下文同名复用。
5. **存储格式换掉 `col = expr`**：`column col:` / `table:` 显式表达归属，避免赋值歧义。
6. **组合里显式写列**：只有“列级 + 单个验证器”允许省略主列；其余一律显式，文件自解释。
7. **错误归属按粒度**：列级锚点列；行级行 + affected；全表表级/可定位行。
8. **保持函数集封闭**：像 Excel 一样丰富，但不做用户自定义函数；新增函数按 §10 的固定套路。
