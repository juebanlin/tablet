# 项目设置对话框 - 导出配置功能设计文档

## 1. 需求概述

在现有的项目设置对话框（2 个 tab：身份 + 分隔符）基础上，增加第 3 个 tab "导出配置"，允许用户可视化配置 `project.toml` 中的 `[export]` 相关字段。

### 1.1 背景
- 当前分隔符配置存储在 `project.tblschema` 的 `# @sep` 行
- 导出配置应存储在 `project.toml`，与全局 `tablet.toml` 按字段 deep-merge
- 用户目前需要手动编辑 `project.toml`，对 UI 用户不友好

### 1.2 目标
- 提供友好的 UI 界面配置导出路径
- 自动处理与全局配置的 merge 关系
- 空字段表示"使用全局默认值"
- 保存时自动写入 `project.toml`

## 2. 配置字段清单

根据 `docs/03-CLI工程.md` 和 `crates/core/src/model.rs` 的 `ExportConfig` 结构：

### 2.1 全局设置（2 项）
- `[export]` encoding (utf-8 / ...)
- `[export]` line_ending (lf / crlf)

### 2.2 数据格式设置（2 项）
- `[export.json]` empty_as (null / omit)
- `[export.xml]` empty_as (empty / omit)

### 2.3 服务端设置（13 项）
- `[export.server]` data_output (路径)
- `[export.server.java]` package, code_output
- `[export.server.go]` package, code_output
- `[export.server.cpp]` namespace, code_output, json_lib (nlohmann / rapidjson)
- `[export.server.csharp_dotnet]` namespace, code_output
- `[export.server.typescript]` output

### 2.4 客户端设置（10 项）
- `[export.client.lua]` output
- `[export.client.gdscript]` output
- `[export.client.typescript]` output
- `[export.client.csharp_unity]` namespace, code_output
- `[export.client.csharp_godot]` namespace, code_output

**总计：27 个配置项**

### 3.3 控件类型

- **下拉框 (ComboBox)**：
  - encoding: 文本框（带验证提示，识别 utf-8/gbk/gb2312 等常见编码）
  - line_ending: **lf, crlf**（空选项表示使用全局默认）
  - json_empty_as: **null, omit**（空选项表示使用全局默认）
  - xml_empty_as: **empty, omit**（空选项表示使用全局默认）
  - cpp_json_lib: **nlohmann, rapidjson**（空选项表示使用全局默认）

- **文本框 (LineEdit)**：
  - encoding: 带实时验证，不常见编码显示橙色警告提示（不阻止保存）
  - 所有路径字段 (output, code_output, data_output)
  - 所有包名/命名空间字段 (package, namespace)

### 3.4 交互说明

1. **空值语义**：字段为空 = "使用全局默认值"，不写入 project.toml
2. **提示文本**：每组添加提示 `"留空表示使用全局配置"`
3. **恢复默认按钮**：不在此 tab 显示（不同于分隔符有明确的默认值）
4. **保存逻辑**：点击"确定"时，非空字段写入 `project.toml` 的对应段

## 5. 实现步骤

### 5.1 Slint UI 层（project_settings.slint）

1. **TabBar 增加第三个 tab**
   ```slint
   Rectangle {
       width: 96px;
       background: root.current == 2 ? Theme.bg-row-selected : transparent;
       Text { text: "导出配置"; }
       TouchArea { clicked => { root.changed(2); } }
   }
   ```

2. **添加导出配置面板**
   ```slint
   if root.tab == 2: ScrollView {
       vertical-stretch: 1;
       VerticalLayout {
           padding: Theme.sp-4;
           spacing: Theme.sp-3;
           
           // 分组 1: 全局设置
           // 分组 2: 数据格式
           // 分组 3: 服务端输出
           // 分组 4: 客户端输出
       }
   }
   ```

3. **定义 properties**
   ```slint
   // 导出配置 buf（27 个字段）
   in-out property <string> export-encoding;
   in-out property <string> export-line-ending;
   // ... 其他 25 个字段
   ```

4. **定义 callback**
   ```slint
   callback export-config-edited(string, string);  // (key, value)
   ```

### 5.2 Rust 逻辑层（project_settings.rs）

1. **`open_for` 函数扩展**
   - 从 `project.config.export` 读取当前配置
   - 填充到 `export_buf`
   - 空字段保持为空字符串（表示使用全局默认）

2. **`push` 函数扩展**
   - 将 `export_buf` 的所有字段推送到 UI properties

3. **`wire` 函数扩展**
   - 监听 `export-config-edited` callback
   - 更新 `export_buf` 对应字段

4. **`run` 函数扩展**（保存逻辑）
   - 读取 project.toml（如果存在）
   - 将 `export_buf` 非空字段写入对应的 toml 段
   - 空字段从 toml 中移除（回退到全局默认）
   - 写回 `<project_root>/project.toml`

### 6.3 集成测试

## 7. 风险和限制

### 7.1 风险
- **配置字段多**：27 个字段，UI 可能显得冗长
  - 缓解：使用 ScrollView + 清晰分组
- **TOML 写入错误**：可能导致 project.toml 损坏
  - 缓解：写入前备份，失败时回滚

### 7.2 限制
- **不支持全局 tablet.toml 编辑**：本功能仅编辑项目级配置
- **不支持 encoding/line_ending 的子级覆盖**：暂不支持 `[export.json] encoding` 等细粒度覆盖
