# 导出功能

## 导出选项

导出分为三个独立操作，可单独执行或全部执行：

| 选项 | 说明 | 默认输出目录 |
|------|------|-------------|
| 生成数据文件 | 将 .tbl 数据导出为 JSON，供 Java 端运行时加载 | gen/server/data/ |
| 生成后端模板类 | 生成 Java 接口 + Tpl 类 + TplHolder | gen/server/code/ |
| 生成前端文件 | 生成 Lua 文件，数据内嵌，require 即用 | gen/client/ |

以上目录为默认值，可在 tbl-tool.toml 中修改：

```toml
[export.server]
lang = "java"
package = "com.game.config"
data_output = "gen/server/data"
code_output = "gen/server/code"

[export.client]
lang = "lua"
output = "gen/client"
```

UI 上提供：
- "全部导出"按钮 — 一键执行三项
- 菜单中可单独选择某一项执行

## 命名规则

生成的类名/文件名与 Group 下的 .tbl 文件名一致，使用**大写驼峰 + Tpl 后缀**：

| .tbl 文件名 | Java 类名 | Lua 文件名 | JSON 数据文件 |
|-------------|-----------|------------|---------------|
| HeroBase.tbl | HeroBaseTpl | HeroBase.lua | HeroBase.json |
| HeroSkill.tbl | HeroSkillTpl | HeroSkill.lua | HeroSkill.json |
| GlobalConst.tbl | GlobalConstTpl | GlobalConst.lua | GlobalConst.json |

## 导出规则

JSON 数据文件和后端模板类是给 server 用的，仅包含"前后端"和"服务器"标记的字段。Lua 前端文件直接从 .tbl 读取生成，仅包含"前后端"和"客户端"标记的字段。

| export 标记 | 数据文件 (JSON) | 后端模板类 (Java) | 前端文件 (Lua) |
|-------------|-----------------|-------------------|----------------|
| 前后端 | 生成 | 生成 | 生成 |
| 服务器 | 生成 | 生成 | 跳过 |
| 客户端 | 跳过 | 跳过 | 生成 |
| 不导出 | 跳过 | 跳过 | 跳过 |

## 导出前验证

执行导出时，工具会对比当前 .tbl 文件与已有生成产物：

1. **检测已删除/重命名的配置** — 如果生成目录中存在 JSON/Java/Lua 文件，但对应的 .tbl 已不存在
2. **列举差异，弹出确认** — 展示将被删除的旧文件列表，策划/程序确认后才执行
3. **确认后执行生成** — 删除旧文件，生成新文件

这确保重命名或删除配置后，生成产物不会残留脏文件。

## 生成后端模板类（Java）

### 接口定义

接口放在 package 根目录：

**ITpl.java：**

```java
package com.game.config;

public interface ITpl {
    int getId();
}
```

**IConstTpl.java：**

```java
package com.game.config;

public interface IConstTpl {
}
```

### types 子包 — 自定义类型实现

**IntPair.java：**

```java
package com.game.config.types;

public class IntPair {
    public final int first;
    public final int second;

    public IntPair(int first, int second) {
        this.first = first;
        this.second = second;
    }
}
```

### Table 模式 → Tpl 实体类

放在 `{group}` 子包，实现 `ITpl`：

**HeroBaseTpl.java：**

```java
package com.game.config.hero;

import com.game.config.ITpl;

public class HeroBaseTpl implements ITpl {
    private int id;
    private String name;
    private int hp;
    private int[] skills;

    @Override
    public int getId() { return id; }
    public String getName() { return name; }
    public int getHp() { return hp; }
    public int[] getSkills() { return skills; }
}
```

### Constant 模式 → Tpl 常量类

同样放在 `{group}` 子包，实现 `IConstTpl`：

**GlobalConstTpl.java：**

```java
package com.game.config.global;

import com.game.config.IConstTpl;

public class GlobalConstTpl implements IConstTpl {
    private int maxLevel;
    private int[] startPos;

    public int getMaxLevel() { return maxLevel; }
    public int[] getStartPos() { return startPos; }
}
```

字段名转换规则：.tbl 中的 snake_case（`max_level`）→ Java 中的 camelCase（`maxLevel`）。

### TplHolder — 统一查询入口

放在 package 根目录。TplHolder 内部硬编码所有 Tpl 类的注册列表（由工具生成时写入），启动时递归扫描 dataDir 按 group 子目录加载对应 JSON。

**TplHolder.java：**

```java
package com.game.config;

import java.util.Map;
import java.util.HashMap;

public class TplHolder {
    private static final Map<Class<?>, Map<Integer, ? extends ITpl>> tables = new HashMap<>();
    private static final Map<Class<?>, IConstTpl> constants = new HashMap<>();

    public static void loadAll(String dataDir) {
        // 递归扫描 dataDir 下按 group 分目录的 JSON 文件
        // 注册列表由代码生成时写入：
        loadTable(dataDir + "/hero/HeroBase.json", HeroBaseTpl.class);
        loadTable(dataDir + "/hero/HeroSkill.json", HeroSkillTpl.class);
        loadConst(dataDir + "/global/GlobalConst.json", GlobalConstTpl.class);
    }

    @SuppressWarnings("unchecked")
    public static <T extends ITpl> T get(Class<T> clazz, int id) {
        Map<Integer, ? extends ITpl> map = tables.get(clazz);
        return map != null ? (T) map.get(id) : null;
    }

    @SuppressWarnings("unchecked")
    public static <T extends ITpl> Map<Integer, T> getAll(Class<T> clazz) {
        return (Map<Integer, T>) tables.get(clazz);
    }

    @SuppressWarnings("unchecked")
    public static <T extends IConstTpl> T getConst(Class<T> clazz) {
        return (T) constants.get(clazz);
    }

    private static <T extends ITpl> void loadTable(String path, Class<T> clazz) { /* ... */ }
    private static <T extends IConstTpl> void loadConst(String path, Class<T> clazz) { /* ... */ }
}
```

**业务使用示例：**

```java
import com.game.config.TplHolder;
import com.game.config.hero.HeroBaseTpl;
import com.game.config.global.GlobalConstTpl;

TplHolder.loadAll("config/server/data");

HeroBaseTpl hero = TplHolder.get(HeroBaseTpl.class, 1001);
GlobalConstTpl consts = TplHolder.getConst(GlobalConstTpl.class);
```

## 生成数据文件（JSON）

数据文件供 Java 端 TplHolder 加载。按 Group 子目录存放，仅包含"前后端"和"服务器"标记的字段。

### Table 模式

**hero/HeroBase.json：**

```json
[
  {"id": 1001, "name": "战士", "hp": 100, "skills": [1, 2, 3]},
  {"id": 1002, "name": "法师", "hp": 80, "skills": [4, 5]}
]
```

### Constant 模式

**global/GlobalConst.json：**

```json
{
  "maxLevel": 100,
  "startPos": [5, 10]
}
```

JSON 中字段名使用 camelCase，与 Java Tpl 类字段一致。

## 生成前端文件（Lua）

Lua 文件**数据内嵌**，直接从 .tbl 读取生成（不经过 JSON），`require` 即可使用。仅包含"前后端"和"客户端"标记的字段。按 Group 子目录存放。

### Table 模式

**hero/HeroBase.lua：**

```lua
local HeroBase = {
    [1001] = {id=1001, name="战士", hp=100, skills={1,2,3}},
    [1002] = {id=1002, name="法师", hp=80, skills={4,5}},
}
return HeroBase
```

### Constant 模式

**global/GlobalConst.lua：**

```lua
local GlobalConst = {
    max_level = 100,
    start_pos = {5, 10},
}
return GlobalConst
```

**前端使用示例：**

```lua
local HeroBase = require("config.hero.HeroBase")
local hero = HeroBase[1001]

local Const = require("config.global.GlobalConst")
print(Const.max_level)
```

## 输出目录结构

```
gen/
├── server/
│   ├── data/                               ← JSON 数据文件（按 Group 分目录）
│   │   ├── hero/
│   │   │   ├── HeroBase.json
│   │   │   ├── HeroSkill.json
│   │   │   └── HeroConst.json
│   │   ├── item/
│   │   │   └── ItemBase.json
│   │   └── global/
│   │       └── GlobalConst.json
│   └── code/                               ← Java 模板类
│       └── com/game/config/
│           ├── ITpl.java                   ← Table 接口
│           ├── IConstTpl.java              ← Constant 接口
│           ├── TplHolder.java              ← 统一查询入口（含注册列表）
│           ├── types/                      ← 自定义类型实现 + 类型解析
│           │   ├── IntPair.java
│           │   ├── IntTriple.java
│           │   └── TypeParser.java
│           ├── hero/                       ← Group（Table 和 Constant 共存）
│           │   ├── HeroBaseTpl.java
│           │   ├── HeroSkillTpl.java
│           │   └── HeroConstTpl.java
│           ├── item/
│           │   └── ItemBaseTpl.java
│           └── global/
│               └── GlobalConstTpl.java
└── client/                                 ← 前端 Lua（按 Group 分目录）
    └── config/
        ├── hero/
        │   ├── HeroBase.lua
        │   ├── HeroSkill.lua
        │   └── HeroConst.lua
        └── global/
            └── GlobalConst.lua
```

### 目录与 package 对应关系

| 目录 | Java package | 内容 |
|------|-------------|------|
| 根 | com.game.config | ITpl, IConstTpl, TplHolder |
| types/ | com.game.config.types | IntPair, IntTriple, TypeParser 等类型实现 |
| {group}/ | com.game.config.{group} | 该 Group 下所有 Tpl 类（Table 和 Constant 混合） |

## Java 与 Lua 导出对比

| 维度 | Java（后端） | Lua（前端） |
|------|-------------|-------------|
| 数据来源 | JSON 数据文件（仅服务器+前后端字段） | 直接从 .tbl 生成（仅客户端+前后端字段） |
| 模板类 | 生成 Tpl 类（纯结构，无数据） | 不需要，数据内嵌 |
| 加载方式 | TplHolder.loadAll(目录) | require("config.group.Name") |
| 查询方式 | TplHolder.get(Class, id) | table[id] |
| 目录结构 | 按 Group 分子目录 | 按 Group 分子目录 |
