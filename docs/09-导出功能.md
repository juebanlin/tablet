# 导出功能

## 导出选项

导出分为四个独立操作，可单独执行或全部执行：

| 选项 | 说明 | 默认输出目录 |
|------|------|-------------|
| 生成 JSON 数据文件 | 将 .tbl 数据导出为 JSON | gen/server/data/ |
| 生成 XML 数据文件 | 将 .tbl 数据导出为 XML（JDK 7+ 原生解析） | gen/server/data/ |
| 生成后端模板类 | 生成 Java 接口 + Tpl 类 + TplHolder | gen/server/code/ |
| 生成前端文件 | 生成 Lua 文件，数据内嵌，require 即用 | gen/client/ |

以上目录为默认值，可在 tbl-tool.toml 中修改：

```toml
[export]
# 生成文件编码: utf-8 (默认)
encoding = "utf-8"
# 生成文件换行符: lf (默认), crlf
line_ending = "lf"

[export.json]
# tbl 空值在 JSON 中的表达方式: "null" | "omit"
empty_as = "null"

[export.xml]
# tbl 空值在 XML 中的表达方式: "empty" | "omit"
empty_as = "empty"

[export.server]
lang = "java"
package = "com.game.config"
data_output = "gen/server/data"
code_output = "gen/server/code"

[export.client]
lang = "lua"
output = "gen/client"
```

UI 上提供：
- "全部导出"按钮 — 一键执行三项
- 菜单中可单独选择某一项执行

## JSON 导出策略

JSON 数据文件包装为 `{"_sep": {...}, "data": [...]}` 结构，`_sep` 嵌入项目的分隔符配置供 Java 端解析复合类型。

基础类型（int/long/float/double/bool）输出为 JSON 原生类型，复合类型（List/Set/Map/Tuple）保持原始分隔符字符串形式。

空值策略通过 `[export.json] empty_as` 配置：

| 策略 | 行为 | 示例 |
|------|------|------|
| `null`（默认） | 空值字段输出为 JSON null | `{"id":1, "hp":null}` |
| `omit` | 空值字段不写入 JSON | `{"id":1}` |

## XML 导出策略

XML 数据文件使用原生 JDK DOM API 可解析的格式（JDK 7+ 零依赖）。分隔符配置嵌入根元素属性。所有字段值输出为文本内容。

空值策略通过 `[export.xml] empty_as` 配置：

| 策略 | 行为 | 示例 |
|------|------|------|
| `empty`（默认） | 空值字段输出为空元素 | `<hp></hp>` |
| `omit` | 空值字段不输出 | 无该元素 |

## 代码模板加载策略

生成的 Java/Go 代码加载 JSON 时，对空值（null 或字段缺失）统一按**默认值策略**处理：

| 类型分类 | 空值处理 | Java | Go |
|---------|---------|------|----|
| 基础类型 | 零值 | int=0, boolean=false, String="" | int32=0, bool=false, string="" |
| 集合类型 | 空集合 | new ArrayList<>() | []T{} |
| 元组类型 | 不会出现 | — | — |

- 不使用包装类型（Integer/*int），字段永远有值，业务代码无需判空
- 元组类型由验证层保证非空，加载时不需要处理空值情况
- 详见 [02-类型系统 · 空值规则](02-类型系统.md#空值规则与默认值)

## 命名规则

生成的类名/文件名与 Group 下的 .tbl 文件名一致，使用**大写驼峰 + Tpl 后缀**：

| .tbl 文件名 | Java 类名 | Lua 文件名 | JSON 数据文件 | XML 数据文件 |
|-------------|-----------|------------|---------------|--------------|
| HeroBase.tbl | HeroBaseTpl | HeroBase.lua | HeroBase.json | HeroBase.xml |
| HeroSkill.tbl | HeroSkillTpl | HeroSkill.lua | HeroSkill.json | HeroSkill.xml |
| GlobalConst.tbl | GlobalConstTpl | GlobalConst.lua | GlobalConst.json | GlobalConst.xml |

## 导出规则

JSON 数据文件和后端模板类是给 server 用的，仅包含"前后端"和"服务器"标记的字段。Lua 前端文件直接从 .tbl 读取生成，仅包含"前后端"和"客户端"标记的字段。

| export 标记 | 数据文件 (JSON/XML) | 后端模板类 (Java) | 前端文件 (Lua) |
|-------------|---------------------|-------------------|----------------|
| 前后端 | 生成 | 生成 | 生成 |
| 服务器 | 生成 | 生成 | 跳过 |
| 客户端 | 跳过 | 跳过 | 生成 |
| 不导出 | 跳过 | 跳过 | 跳过 |

## 导出粒度控制

CLI 支持按格式独立导出，可任意组合：

```bash
tbl-cli export                    # 全部导出（JSON + XML + Java + Lua）
tbl-cli export --json --lua       # 只导出 JSON + Lua
tbl-cli export --java             # 只导出 Java 模板类
tbl-cli export --lua              # 只导出 Lua 前端文件
```

无 flag = 全部导出。指定 flag = 只导出对应部分。

## 导出产物同步

每次导出时，工具对比生成目录中已有文件和本次应生成的文件，自动同步：

| 状态 | 含义 | 操作 |
|------|------|------|
| 新增 | 之前不存在的文件 | 写入 |
| 修改 | 内容有变化 | 覆盖 |
| 不变 | 内容相同 | 跳过 |
| 删除 | 目录中存在但本次不再生成（.tbl 已删除/重命名） | 删除文件 |

### CLI 行为

默认删除多余文件，打印变化日志：

```
[JSON] 2 新增, 1 修改, 1 删除, 3 不变
  [新增] gen/server/data/json/hero/HeroSkill.json
  [修改] gen/server/data/json/hero/HeroBase.json
  [删除] gen/server/data/json/hero/OldTable.json
```

不变的文件不打印。

### UI 行为

弹窗展示变化列表（新增/修改/删除），确认后执行。操作日志窗口记录导出详情。

### 清理范围

- 只对**本次实际执行的导出格式**做残留检测
- 例如只导出 `--lua`，不会清理 JSON/XML/Java 目录
- 所有文件参与检测（包括框架文件如 ITpl.java、TplHolder.java）
- 同步后自动清理空目录

## 生成后端模板类（Java）

### 接口定义

接口放在 package 根目录：

**ITpl.java：**

```java
package com.game.config;

public interface ITpl {
    int getId();
}
```

**IConstTpl.java：**

```java
package com.game.config;

public interface IConstTpl {
}
```

### types 子包 — 自定义类型实现

**IntPair.java：**

```java
package com.game.config.types;

public class IntPair {
    public final int first;
    public final int second;

    public IntPair(int first, int second) {
        this.first = first;
        this.second = second;
    }
}
```

### Table 模式 → Tpl 实体类

放在 `{group}` 子包，实现 `ITpl`，类级 `@TblSource` 标识来源，字段级 `@TblType` 描述范式类型：

**HeroBaseTpl.java：**

```java
package com.game.config.hero;

import com.game.config.ITpl;
import com.game.config.TblType;
import com.game.config.TblSource;

@TblSource(group = "hero", name = "HeroBase", mode = "table")
public class HeroBaseTpl implements ITpl {
    @TblType("int")
    private int id;
    @TblType("str")
    private String name;
    @TblType("int")
    private int hp;
    @TblType("List<int>")
    private List<Integer> skills;

    @Override
    public int getId() { return id; }
    public String getName() { return name; }
    public int getHp() { return hp; }
    public List<Integer> getSkills() { return skills; }
}
```

### Constant 模式 → Tpl 常量类

同样放在 `{group}` 子包，实现 `IConstTpl`：

**GlobalConstTpl.java：**

```java
package com.game.config.global;

import com.game.config.IConstTpl;
import com.game.config.TblType;
import com.game.config.TblSource;

@TblSource(group = "global", name = "GlobalConst", mode = "constant")
public class GlobalConstTpl implements IConstTpl {
    @TblType("int")
    private int maxLevel;
    @TblType("Tuple2<int,int>")
    private Tuple2<Integer, Integer> startPos;

    public int getMaxLevel() { return maxLevel; }
    public Tuple2<Integer, Integer> getStartPos() { return startPos; }
}
```

字段名转换规则：.tbl 中的 snake_case（`max_level`）→ Java 中的 camelCase（`maxLevel`）。

### TplHolder — 统一查询入口

放在 package 根目录。TplHolder 通过静态 registry 注册所有 Tpl 类（由工具生成时写入），启动时扫描 dataDir 下的数据文件按需加载。

- `init(dataDir)` — 加载 XML 数据文件（默认）
- `initJson(dataDir)` — 加载 JSON 数据文件

字段值统一以字符串形式从数据文件读取，通过 `@TblType` 注解 + `TplUtil.parseField()` 解析为目标类型。

**TplHolder.java：**

```java
package com.game.config;

import java.util.Map;
import java.util.HashMap;

public class TplHolder {
    private static final Map<String, Class<?>> registry = new HashMap<>();

    static {
        registry.put("hero/HeroBase", HeroBaseTpl.class);
        registry.put("global/GlobalConst", GlobalConstTpl.class);
    }

    public static void init(String dataDir) { /* 扫描 .xml 文件 */ }
    public static void initJson(String dataDir) { /* 扫描 .json 文件 */ }

    public static <T extends ITpl> T get(Class<T> clazz, int id) { ... }
    public static <T extends ITpl> Map<Integer, T> getAll(Class<T> clazz) { ... }
    public static <T extends IConstTpl> T getConst(Class<T> clazz) { ... }
}
```

**业务使用示例：**

```java
import com.game.config.TplHolder;
import com.game.config.hero.HeroBaseTpl;
import com.game.config.global.GlobalConstTpl;

// XML 数据（默认）
TplHolder.init("config/server/data");

// 或 JSON 数据
TplHolder.initJson("config/server/data");

HeroBaseTpl hero = TplHolder.get(HeroBaseTpl.class, 1001);
GlobalConstTpl consts = TplHolder.getConst(GlobalConstTpl.class);
```

## 生成数据文件（JSON）

数据文件供 Java 端 TplHolder 加载。按 Group 子目录存放，仅包含"前后端"和"服务器"标记的字段。

### Table 模式

**hero/HeroBase.json：**

```json
{
  "_sep": {"list": ";", "tuple2": ",", "map_kv": ":", "map_entry": ";", ...},
  "data": [
    {"id": 1001, "name": "战士", "hp": 100, "skills": "1;2;3"},
    {"id": 1002, "name": "法师", "hp": 80, "skills": "4;5"}
  ]
}
```

### Constant 模式

**global/GlobalConst.json：**

```json
{
  "_sep": {"list": ";", "tuple2": ",", ...},
  "data": {
    "maxLevel": 100,
    "startPos": "5,10"
  }
}
```

JSON 中字段名使用 camelCase，与 Java Tpl 类字段一致。基础类型输出为 JSON 原生类型，复合类型保持分隔符字符串。`_sep` 对象包含项目配置的所有分隔符，供 Java 端 TplUtil 解析复合类型时使用。

## 生成数据文件（XML）

XML 数据文件与 JSON 并列，同样按 Group 子目录存放。使用原生 JDK DOM API 可解析。

### Table 模式

**hero/HeroBase.xml：**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<list sep_list=";" sep_tuple2="," sep_map_kv=":" sep_map_entry=";">
  <item>
    <id>1001</id>
    <name>战士</name>
    <hp>100</hp>
    <skills>1;2;3</skills>
  </item>
</list>
```

### Constant 模式

**global/GlobalConst.xml：**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<const sep_list=";" sep_tuple2="," sep_map_kv=":" sep_map_entry=";">
  <maxLevel>100</maxLevel>
  <startPos>5,10</startPos>
</const>
```

分隔符配置嵌入根元素属性（`sep_list`、`sep_tuple2` 等），所有字段值为文本内容。

## 生成前端文件（Lua）

Lua 文件**数据内嵌**，直接从 .tbl 读取生成（不经过 JSON），`require` 即可使用。仅包含"前后端"和"客户端"标记的字段。按 Group 子目录存放。

### Table 模式

**hero/HeroBase.lua：**

```lua
local HeroBase = {
    [1001] = {id=1001, name="战士", hp=100, skills={1,2,3}},
    [1002] = {id=1002, name="法师", hp=80, skills={4,5}},
}
return HeroBase
```

### Constant 模式

**global/GlobalConst.lua：**

```lua
local GlobalConst = {
    max_level = 100,
    start_pos = {5, 10},
}
return GlobalConst
```

**前端使用示例：**

```lua
local HeroBase = require("config.hero.HeroBase")
local hero = HeroBase[1001]

local Const = require("config.global.GlobalConst")
print(Const.max_level)
```

### 目录与 package 对应关系

| 目录 | Java package | 内容 |
|------|-------------|------|
| 根 | com.game.config | ITpl, IConstTpl, TplHolder, TblType, TblSource, TplUtil, 解析器 |
| types/ | com.game.config.types | Tuple2, Tuple3, Tuple4 |
| {group}/ | com.game.config.{group} | 该 Group 下所有 Tpl 类（Table 和 Constant 混合） |

## Java 与 Lua 导出对比

| 维度 | Java（后端） | Lua（前端） |
|------|-------------|-------------|
| 数据来源 | JSON 或 XML 数据文件（仅服务器+前后端字段） | 直接从 .tbl 生成（仅客户端+前后端字段） |
| 数据格式 | XML（默认，JDK 原生解析）或 JSON | Lua table 内嵌 |
| 模板类 | 生成 Tpl 类（@TblType 注解 + @TblSource 元数据） | 不需要，数据内嵌 |
| 加载方式 | TplHolder.init(目录) / TplHolder.initJson(目录) | require("config.group.Name") |
| 查询方式 | TplHolder.get(Class, id) | table[id] |
| 目录结构 | 按 Group 分子目录 | 按 Group 分子目录 |
