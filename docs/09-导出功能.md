# 导出功能

## 导出选项

导出分为五个独立操作，可自由组合执行：

| 选项 | 说明 | 默认输出目录 |
|------|------|-------------|
| JSON | 将 .tbl 数据导出为 JSON | gen/server/data/json/ |
| XML | 将 .tbl 数据导出为 XML（JDK 7+ 原生解析） | gen/server/data/xml/ |
| Java | 生成 Java 接口 + Tpl 类 + TplHolder | gen/server/java/ |
| Go | 生成 Go 结构体 + 加载框架 | gen/server/go/ |
| Lua | 生成 Lua 文件，数据内嵌，require 即用 | gen/client/ |

以上目录为默认值，可在 tbl-tool.toml 中修改：

```toml
[export]
encoding = "utf-8"       # 全局默认编码
line_ending = "lf"       # 全局默认换行符

[export.json]
empty_as = "null"
# line_ending = "lf"     # 可选，覆盖全局
# encoding = "utf-8"     # 可选，覆盖全局

[export.xml]
empty_as = "empty"
# line_ending = "lf"
# encoding = "utf-8"

[export.server]
data_output = "gen/server/data"
# line_ending = "lf"     # server 层级默认值
# encoding = "utf-8"

[export.server.java]
package = "com.game.config"
code_output = "gen/server/java"
# line_ending = "lf"     # 可选，覆盖 server → export
# encoding = "utf-8"

[export.server.go]
package = "config"
code_output = "gen/server/go"
# line_ending = "lf"
# encoding = "utf-8"

[export.client.lua]
output = "gen/client"
# line_ending = "lf"
# encoding = "utf-8"
```

编码和换行符的 fallback 链：各部分独立配置 > 上级节点（如 `[export.server]` / `[export.client]`）> `[export]` > 默认值（lf + utf-8）。

UI 上提供：
- "全部导出"按钮 — 一键执行三项
- 菜单中可单独选择某一项执行

## JSON 导出策略

JSON 数据文件包装为 `{"_sep": {...}, "data": [...]}` 结构，`_sep` 嵌入项目的分隔符配置供 Java 端解析复合类型。

基础类型（int/long/float/double/bool）输出为 JSON 原生类型，复合类型（List/Set/Map/Tuple）保持原始分隔符字符串形式。

空值策略通过 `[export.json] empty_as` 配置：

| 策略 | 行为 | 示例 |
|------|------|------|
| `null`（默认） | 空值字段输出为 JSON null | `{"id":1, "hp":null}` |
| `omit` | 空值字段不写入 JSON | `{"id":1}` |

## XML 导出策略

XML 数据文件使用原生 JDK DOM API 可解析的格式（JDK 7+ 零依赖）。分隔符配置嵌入根元素属性。所有字段值输出为文本内容。

空值策略通过 `[export.xml] empty_as` 配置：

| 策略 | 行为 | 示例 |
|------|------|------|
| `empty`（默认） | 空值字段输出为空元素 | `<hp></hp>` |
| `omit` | 空值字段不输出 | 无该元素 |

## 代码模板加载策略

生成的 Java/Go 代码加载 JSON 时，对空值（null 或字段缺失）统一按**默认值策略**处理：

| 类型分类 | 空值处理 | Java | Go |
|---------|---------|------|----|
| 基础类型 | 零值 | int=0, boolean=false, String="" | int32=0, bool=false, string="" |
| 集合类型 | 空集合 | new ArrayList<>() | []T{} |
| 元组类型 | 不会出现 | — | — |

- 不使用包装类型（Integer/*int），字段永远有值，业务代码无需判空
- 元组类型由验证层保证非空，加载时不需要处理空值情况
- 详见 [02-类型系统 · 空值规则](02-类型系统.md#空值规则与默认值)

## 命名规则

生成的类名/文件名与 Group 下的 .tbl 文件名一致，使用**大写驼峰 + Tpl 后缀**：

| .tbl 文件名 | Java 类名 | Lua 文件名 | JSON 数据文件 | XML 数据文件 |
|-------------|-----------|------------|---------------|--------------|
| HeroBase.tbl | HeroBaseTpl | HeroBase.lua | HeroBase.json | HeroBase.xml |
| HeroSkill.tbl | HeroSkillTpl | HeroSkill.lua | HeroSkill.json | HeroSkill.xml |
| GlobalConst.tbl | GlobalConstTpl | GlobalConst.lua | GlobalConst.json | GlobalConst.xml |

## 导出规则

JSON 数据文件和后端模板类是给 server 用的，仅包含"前后端"和"服务器"标记的字段。Lua 前端文件直接从 .tbl 读取生成，仅包含"前后端"和"客户端"标记的字段。

| export 标记 | 数据文件 (JSON/XML) | 后端模板类 (Java) | 前端文件 (Lua) |
|-------------|---------------------|-------------------|----------------|
| 前后端 | 生成 | 生成 | 生成 |
| 服务器 | 生成 | 生成 | 跳过 |
| 客户端 | 跳过 | 跳过 | 生成 |
| 不导出 | 跳过 | 跳过 | 跳过 |

## 导出粒度控制

CLI 支持按格式独立导出，可任意组合：

```bash
tbl-cli export                    # 全部导出（JSON + XML + Java + Go + Lua）
tbl-cli export --json --lua       # 只导出 JSON + Lua
tbl-cli export --java             # 只导出 Java 模板类
tbl-cli export --go               # 只导出 Go 模板代码
tbl-cli export --lua              # 只导出 Lua 前端文件
```

无 flag = 全部导出。指定 flag = 只导出对应部分。

## 导出产物同步

每次导出时，工具对比生成目录中已有文件和本次应生成的文件，自动同步：

| 状态 | 含义 | 操作 |
|------|------|------|
| 新增 | 之前不存在的文件 | 写入 |
| 修改 | 内容有变化 | 覆盖 |
| 不变 | 内容相同 | 跳过 |
| 删除 | 目录中存在但本次不再生成（.tbl 已删除/重命名） | 删除文件 |

### CLI 行为

默认删除多余文件，打印变化日志：

```
[JSON] 2 新增, 1 修改, 1 删除, 3 不变
  [新增] gen/server/data/json/hero/HeroSkill.json
  [修改] gen/server/data/json/hero/HeroBase.json
  [删除] gen/server/data/json/hero/OldTable.json
```

不变的文件不打印。

### UI 行为

弹窗展示变化列表（新增/修改/删除），确认后执行。操作日志窗口记录导出详情。

### 清理范围

- 只对**本次实际执行的导出格式**做残留检测
- 例如只导出 `--lua`，不会清理 JSON/XML/Java 目录
- 所有文件参与检测（包括框架文件如 ITpl.java、TplHolder.java）
- 同步后自动清理空目录

## 生成后端模板类（Java）

### 接口定义

接口放在 package 根目录：

**ITpl.java：**

```java
package com.game.config;

public interface ITpl {
    int getId();
}
```

**IConstTpl.java：**

```java
package com.game.config;

public interface IConstTpl {
}
```

### types 子包 — 自定义类型实现

**IntPair.java：**

```java
package com.game.config.types;

public class IntPair {
    public final int first;
    public final int second;

    public IntPair(int first, int second) {
        this.first = first;
        this.second = second;
    }
}
```

### Table 模式 → Tpl 实体类

放在 `{group}` 子包，实现 `ITpl`，类级 `@TblSource` 标识来源，字段级 `@TblType` 描述范式类型：

**HeroBaseTpl.java：**

```java
package com.game.config.hero;

import com.game.config.ITpl;
import com.game.config.TblType;
import com.game.config.TblSource;

@TblSource(group = "hero", name = "HeroBase", mode = "table")
public class HeroBaseTpl implements ITpl {
    @TblType("int")
    private int id;
    @TblType("str")
    private String name;
    @TblType("int")
    private int hp;
    @TblType("List<int>")
    private List<Integer> skills;

    @Override
    public int getId() { return id; }
    public String getName() { return name; }
    public int getHp() { return hp; }
    public List<Integer> getSkills() { return skills; }
}
```

### Constant 模式 → Tpl 常量类

同样放在 `{group}` 子包，实现 `IConstTpl`：

**GlobalConstTpl.java：**

```java
package com.game.config.global;

import com.game.config.IConstTpl;
import com.game.config.TblType;
import com.game.config.TblSource;

@TblSource(group = "global", name = "GlobalConst", mode = "constant")
public class GlobalConstTpl implements IConstTpl {
    @TblType("int")
    private int maxLevel;
    @TblType("Tuple2<int,int>")
    private Tuple2<Integer, Integer> startPos;

    public int getMaxLevel() { return maxLevel; }
    public Tuple2<Integer, Integer> getStartPos() { return startPos; }
}
```

字段名转换规则：.tbl 中的 snake_case（`max_level`）→ Java 中的 camelCase（`maxLevel`）。

### TplHolder — 统一查询入口

放在 package 根目录。TplHolder 通过静态 registry 注册所有 Tpl 类（由工具生成时写入），启动时扫描 dataDir 下的数据文件按需加载。

- `init(dataDir)` — 加载 XML 数据文件（默认）
- `initJson(dataDir)` — 加载 JSON 数据文件

字段值统一以字符串形式从数据文件读取，通过 `@TblType` 注解 + `TplUtil.parseField()` 解析为目标类型。

**TplHolder.java：**

```java
package com.game.config;

import java.util.Map;
import java.util.HashMap;

public class TplHolder {
    private static final Map<String, Class<?>> registry = new HashMap<>();

    static {
        registry.put("hero/HeroBase", HeroBaseTpl.class);
        registry.put("global/GlobalConst", GlobalConstTpl.class);
    }

    public static void init(String dataDir) { /* 扫描 .xml 文件 */ }
    public static void initJson(String dataDir) { /* 扫描 .json 文件 */ }

    public static <T extends ITpl> T get(Class<T> clazz, int id) { ... }
    public static <T extends ITpl> Map<Integer, T> getAll(Class<T> clazz) { ... }
    public static <T extends IConstTpl> T getConst(Class<T> clazz) { ... }
}
```

**业务使用示例：**

```java
import com.game.config.TplHolder;
import com.game.config.hero.HeroBaseTpl;
import com.game.config.global.GlobalConstTpl;

// XML 数据（默认）
TplHolder.init("config/server/data");

// 或 JSON 数据
TplHolder.initJson("config/server/data");

HeroBaseTpl hero = TplHolder.get(HeroBaseTpl.class, 1001);
GlobalConstTpl consts = TplHolder.getConst(GlobalConstTpl.class);
```

## 生成后端模板代码（Go）

Go 后端生成 **flat package**：所有文件平铺在 `[export.server.go] code_output` 指向的目录下，包名取自 `[export.server.go] package`。零反射，每张表/常量生成专用 `Get` 函数。

### Table 模式 → Tpl 结构体

**hero_base_tpl.go：**

```go
package config

type HeroBaseTpl struct {
    Id     int32   // int
    Name   string  // str
    Hp     int32   // int
    Skills []int32 // List<int>
}

var HeroBase_data = map[int32]*HeroBaseTpl{}

func parseHeroBase(row map[string]string, sep SepConfig) *HeroBaseTpl {
    obj := &HeroBaseTpl{}
    if raw, ok := row["id"]; ok && raw != "" {
        obj.Id = parseInt32(raw)
    }
    if raw, ok := row["name"]; ok && raw != "" {
        obj.Name = parseStr(raw)
    }
    if raw, ok := row["hp"]; ok && raw != "" {
        obj.Hp = parseInt32(raw)
    }
    if raw, ok := row["skills"]; ok && raw != "" {
        obj.Skills = parseListInt32(raw, sep.List)
    }
    return obj
}

func init() {
    registerTable("hero/HeroBase", func(rows []map[string]string, sep SepConfig) {
        m := map[int32]*HeroBaseTpl{}
        for _, row := range rows {
            obj := parseHeroBase(row, sep)
            m[obj.Id] = obj
        }
        HeroBase_data = m
    })
}

func GetHeroBase(id int32) *HeroBaseTpl       { return HeroBase_data[id] }
func GetAllHeroBase() map[int32]*HeroBaseTpl  { return HeroBase_data }
```

字段名规则：.tbl 中 snake_case（`max_level`）→ Go 中 PascalCase 导出（`MaxLevel`），数据文件 key 与 Java 保持一致（camelCase `maxLevel`）。

### Constant 模式 → Tpl 结构体

**global_const_tpl.go：**

```go
package config

type GlobalConstTpl struct {
    MaxLevel   int32             // int
    StartPos   Tuple2[int32,int32] // Tuple2<int,int>
    ServerName string            // str
}

var GlobalConst_data = &GlobalConstTpl{}

func init() { /* registerConstant ... */ }

func GetGlobalConst() *GlobalConstTpl { return GlobalConst_data }
```

### 类型映射

| TblType | Go 类型 |
|---------|---------|
| int / long / float / double / bool / str | int32 / int64 / float32 / float64 / bool / string |
| List\<T\> | []T |
| Set\<T\> | map[T]struct{} |
| Map\<K,V\> | map[K]V |
| Tuple2\<A,B\> | Tuple2[A,B]（泛型结构体，字段 F0/F1） |
| Tuple3 / Tuple4 | Tuple3[A,B,C] / Tuple4[A,B,C,D] |
| List\<Tuple2\<...\>\> | []Tuple2[...]，等等 |
| Map\<K,Tuple_\<...\>\> | map[K]Tuple_[...]，等等 |
| Map\<K,List\<V\>\> | map[K][]V |

### 加载入口

`loader.go` 暴露：

```go
config.Init(dataDir string) error      // 加载 XML 数据文件（默认）
config.InitJSON(dataDir string) error  // 加载 JSON 数据文件
```

实现细节：每个 `*_tpl.go` 在 `init()` 时把 `<group>/<name>` 注册到 loader registry。`Init` 扫描 dataDir 下所有匹配后缀的文件，按相对路径解析为 key，调用对应注册函数完成加载。

### 业务使用示例

```go
import "yourmodule/gen/server/go/config"

func main() {
    if err := config.Init("config/server/data/xml"); err != nil {
        panic(err)
    }

    hero := config.GetHeroBase(1001)
    fmt.Println(hero.Name, hero.Hp, hero.Skills)

    c := config.GetGlobalConst()
    fmt.Println(c.MaxLevel, c.StartPos.F0, c.StartPos.F1)
}
```

注意：生成的 Go 代码不包含 `go.mod`，由用户自己的项目通过包路径 import。

## 生成数据文件（JSON）

数据文件供 Java 端 TplHolder 加载。按 Group 子目录存放，仅包含"前后端"和"服务器"标记的字段。

### Table 模式

**hero/HeroBase.json：**

```json
{
  "_sep": {"list": ";", "tuple2": ",", "map_kv": ":", "map_entry": ";", ...},
  "data": [
    {"id": 1001, "name": "战士", "hp": 100, "skills": "1;2;3"},
    {"id": 1002, "name": "法师", "hp": 80, "skills": "4;5"}
  ]
}
```

### Constant 模式

**global/GlobalConst.json：**

```json
{
  "_sep": {"list": ";", "tuple2": ",", ...},
  "data": {
    "maxLevel": 100,
    "startPos": "5,10"
  }
}
```

JSON 中字段名使用 camelCase，与 Java Tpl 类字段一致。基础类型输出为 JSON 原生类型，复合类型保持分隔符字符串。`_sep` 对象包含项目配置的所有分隔符，供 Java 端 TplUtil 解析复合类型时使用。

## 生成数据文件（XML）

XML 数据文件与 JSON 并列，同样按 Group 子目录存放。使用原生 JDK DOM API 可解析。

### Table 模式

**hero/HeroBase.xml：**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<list sep_list=";" sep_tuple2="," sep_map_kv=":" sep_map_entry=";">
  <item>
    <id>1001</id>
    <name>战士</name>
    <hp>100</hp>
    <skills>1;2;3</skills>
  </item>
</list>
```

### Constant 模式

**global/GlobalConst.xml：**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<const sep_list=";" sep_tuple2="," sep_map_kv=":" sep_map_entry=";">
  <maxLevel>100</maxLevel>
  <startPos>5,10</startPos>
</const>
```

分隔符配置嵌入根元素属性（`sep_list`、`sep_tuple2` 等），所有字段值为文本内容。

## 生成前端文件（Lua）

Lua 文件**数据内嵌**，直接从 .tbl 读取生成（不经过 JSON），`require` 即可使用。仅包含"前后端"和"客户端"标记的字段。按 Group 子目录存放。

### Table 模式

**hero/HeroBase.lua：**

```lua
local HeroBase = {
    [1001] = {id=1001, name="战士", hp=100, skills={1,2,3}},
    [1002] = {id=1002, name="法师", hp=80, skills={4,5}},
}
return HeroBase
```

### Constant 模式

**global/GlobalConst.lua：**

```lua
local GlobalConst = {
    max_level = 100,
    start_pos = {5, 10},
}
return GlobalConst
```

**前端使用示例：**

```lua
local HeroBase = require("config.hero.HeroBase")
local hero = HeroBase[1001]

local Const = require("config.global.GlobalConst")
print(Const.max_level)
```

### 目录与 package 对应关系

**Java:**

| 目录 | Java package | 内容 |
|------|-------------|------|
| 根 | com.game.config | ITpl, IConstTpl, TplHolder, TplRegistry, TblMeta, TblType, TblSource, TplUtil, 解析器 |
| types/ | com.game.config.types | Tuple2, Tuple3, Tuple4 |
| {group}/ | com.game.config.{group} | 该 Group 下所有 Tpl 类（Table 和 Constant 混合） |

**Go:**

Go 输出采用 **flat package**：所有生成文件都在同一个 package 目录下，文件名使用 snake_case，不分 group 子包。原因是 Go 的初始化顺序按 import 图保证，flat 结构避免循环依赖、调用更直观。

| 文件 | 内容 |
|------|------|
| loader.go | `Init(dir)` / `InitJSON(dir)` 入口，扫描数据目录调用 registry |
| parser.go | 基础类型/List/Set 解析函数 |
| sep.go | `SepConfig` 结构 + JSON/XML 元数据反序列化 |
| tuples.go | `Tuple2/3/4` 泛型结构 + `ParseTuple_/ParseListItems/ParseMap` |
| {Name}_tpl.go | 每张表/常量一个文件，包含结构体定义、`Get{Name}`/`GetAll{Name}` 函数、`init()` 注册解析器 |

## Java / Go / Lua 导出对比

| 维度 | Java（后端） | Go（后端） | Lua（前端） |
|------|-------------|-----------|-------------|
| 数据来源 | JSON 或 XML 数据文件 | JSON 或 XML 数据文件 | 直接从 .tbl 生成 |
| 字段过滤 | 仅服务器+前后端 | 仅服务器+前后端 | 仅客户端+前后端 |
| 数据格式 | XML（默认）或 JSON | XML（默认）或 JSON | Lua table 内嵌 |
| 模板类 | Tpl 类 + 注解（反射加载） | 结构体 + 生成的 parse 函数（零反射） | 不需要 |
