# 分表工作簿组（Split Xlsx Group）

> 状态：**设计稿，尚未实现**。落地时以本文为准；实现完成后把状态改为“已实现”。

## 1. 背景与目标

策划希望一个逻辑表由多人分文件维护：一份主表负责四行表头和节点结构，数据行按人拆到多个
工作簿里，每个人只改自己的文件，从而把 Git 冲突限制在自己的分部内。

目标：

- 磁盘上仍是普通 `.xlsx`，策划可以用 Excel/WPS 直接编辑；
- 工具内看到**一张合并后的逻辑表**，验证、引用、导出只有一套规则；
- 编辑按主表 / 分部进行，保存只写有改动的文件；
- 合并视图只读，避免“合并后的中间插入到底写哪个分部”的歧义。

## 2. 磁盘布局与识别

xlsx 组的组名来自文件名本身，所有 xlsx 都放在 `config/` 根目录：

| 磁盘形态 | 含义 |
|---|---|
| `config/<group>/` 目录 | Tbl 组（目录名 = 组名） |
| `config/<group>.xlsx` | 普通 Xlsx 组（文件名干 = 组名） |
| `config/<group>.xlsx` + `config/<group>#<part>.xlsx` | **分表 Xlsx 组** |
| `config/<group>#<part>.xlsx`（没有主表） | 非法：分表组缺少主表 |

规则：

- **主表必需**：`config/<group>.xlsx` 是结构主表；`#1` 不是主表。
- 分部：`config/<group>#<part>.xlsx`。`#` 不能出现在合法组名里，因此
  `Item#1.xlsx` 可以无歧义地识别为“组 `Item` 的分部”；`Item_1.xlsx` 是普通组 `Item_1`。
- 出现任意 `#<part>` 文件时，该组必须是分表模式（schema/manifest 的 storage =
  `xlsx_split`）。磁盘与 manifest 不一致时报错，不静默切换。
- 主表与分部不能和 Tbl 组同名目录共存：`config/Item/` 与 `Item#1.xlsx` 同时出现 → 报错。
- 分部文件不递归子目录；只扫描 `config/` 根下的 `*.xlsx`。

## 3. 主表与分部职责

- **主表**：四行表头 + 全部 sheet（节点）的结构真相源；可以带数据行，也可以只留表头。
- **分部**：只放数据行；表头必须与主表逐字一致；可以只包含主表节点的子集。
- **sheet 名 = 逻辑节点名**，遵循与普通组相同的 PascalCase 规则，
  **不允许 `#`**；分片编号只出现在文件名里，不进入 sheet 名。
- 分部缺少某个节点的 sheet → 该分部对该节点贡献 0 行，属于正常情况。
- 分部出现主表没有的 sheet → 加载错误（分部只能承载主表已有的结构）。
- 一期分表只支持 **Table**；Constant / Enum 只能放在主表。
- 合并顺序：主表在前，分部按 `#` 后的部分做自然排序（全数字按数值，否则按字典序）；
  行顺序只影响展示，表的身份仍是 id。

## 4. 内存模型与分层

**内存里始终是一张普通表**，分表差异只存在于存储适配器：

```
存储层（xlsx_split 适配器）
  A.xlsx + A#N.xlsx
  ├─ 加载：校验表头/节点归属 → 合并成普通 Table
  └─ 保存：按行来源分发回各分部，只重写有改动的文件
        ↓
内存层（与普通组完全一致）
  Project → Group → Table / Constant / Enum
        ↓
验证 / 规则 / 引用 / 导出 / GUI 预览 / Excel 映射
  （零改动，只看到合并后的普通表）
```

行来源不放在 Group 上，而是放在节点内部，保证撤销/重做一致：

```rust
// Table / Constant / EnumDef
/// 与 records / entries 等长的分部索引；普通组为空。
pub row_parts: Vec<u32>,
```

- 单元格编辑不改 `row_parts`；
- 插入/删除行在对应入口同步维护；
- `with_node_tx` 快照整个节点，`row_parts` 随快照回滚，不会出现“数据回滚、来源错位”；
- 验证器、导出器、引用索引完全不感知 `row_parts`。

**不采用“每个分部独立表 + 验证时虚拟合并”**：节点重名、`@Ref`、导出、UI 预览都需要合并层，
会把复杂度扩散到所有消费者；集中到存储适配器改动最小。

## 5. 加载与结构校验

1. 扫描 `config/*.xlsx`，按文件名分组；有 `#` 的归入对应主表组。
2. 读取主表，复用现有 `table_from_sheet` 解析 4 行表头与数据。
3. 逐个读取分部 sheet：
   - sheet 名必须存在于主表节点集合，否则报错（文件 / sheet 定位）；
   - 表头（描述 / 导出 / 类型 / 字段名）必须与主表逐字一致，否则报错并指出差异列；
   - 数据行追加到合并记录，同时写入 `row_parts`。
4. 合并后做结构检查：
   - 主表缺失 → 报错；
   - 分部文件打不开 / 不是 xlsx → 报错并定位文件；
   - id 在合并后必须唯一；重复时错误信息带两个来源分部（文件 + sheet + 行）；
5. 分部某节点无 sheet：贡献 0 行；整个分部没有任何节点 sheet：允许，但记一条警告日志。

## 6. 编辑与写回

合并视图**只读**；编辑只在“主表 / 某个分部”范围内进行：

- **主表范围**：主表行可编辑；下方按分部追加灰色只读预览，可开关；
- **分部范围**：只显示该分部的行，可编辑；插入/删除只影响该分部；
- 表头 / 节点结构只能在主表改；分部表头只读，加载时校验。

写回规则：

- 编辑主表 → 只写 `A.xlsx`；编辑分部 → 只写 `A#N.xlsx`；
- 每个 part 保存上次落盘的行基线，未变化的文件一个字节都不重写（避免无意义 Git diff）；
- 表头变更需要同步到所有分部；分部表头不一致时保存前报错；
- 分部数据被删空 → 该 sheet 保留，只写表头；
- 新节点只会加到主表；分部的 sheet 集合不能自己扩张。

撤销：所有改行数的操作都走节点事务，`row_parts` 与数据一起回滚；合并视图不可编辑，
因此不存在跨分部的插入归属歧义。

## 7. GUI 展示

- **树**：分表组显示为一个组节点（图标 📚，后缀“· 分表 N”），子节点仍是逻辑上的
  Table/Constant/Enum；不把分部做成树节点。右键「查看分部…」弹窗列出
  `文件 / sheet / 行数`，可打开所在目录或用 Excel 打开某个分部。
- **主表视图**：主表行正常色、可编辑；下面一条分隔行
  `── 以下为分部预览（只读） ──`，每个分部前一条灰色横幅
  `▸ A#2 分部 · 只读 · 80 行`，其后为灰色只读数据行。
- **来源信息的位置**：
  - 行号格保持纯数字，不写 `A#1`；行号格加小色点/底色并带 tooltip
    （`来源：config/A#2.xlsx / sheet Item`）；
  - 分块横幅是主要的来源标识；
  - 状态栏显示 `主表 340 行 + 分部 2 个 / 200 行（只读）` 与颜色图例；
  - 不新增数据列；如确需逐行文字，后续再加独立的只读“来源”gutter 栏，
    不参与 schema、复制与导出。
- **范围选择器**：`主表 / A#1 / A#2 …`；切换后表格只显示该范围并允许编辑。
- 打开某个分部时锁定组结构操作（与现有 Excel/Univer 锁语义一致）。

## 8. Excel / Univer

- **Excel 快速编辑**：对分表组先选择主表或某个分部，打开对应原文件；
  保存后只回读该文件并重新合并到内存（不落盘，主界面保存才落盘）。
- **Univer**：同样只打开一个工作簿（主表或某个分部），回写只改这一部分；
  合并预览不提供 Univer 入口。
- 合并视图、分部预览均不可编辑，避免合并回写破坏行来源。

## 9. 验证 / 引用 / 导出

- 全部基于合并后的内存表：规则一套、引用 id 集合合并、导出为一张表。
- ID 全组唯一，跨分部重复由现有校验拦截；加载时额外给出带来源的结构错误。
- 业务规则（range / unique / ref_exists / when…）不进入存储层；
  存储层只做结构检查（主表存在、表头一致、sheet 归属、id 重复）。

## 10. 模式转换

- 普通组 → 分表组：显式动作。manifest storage 改为 `xlsx_split`，
  按需生成 `A#1.xlsx`、`A#2.xlsx`（复制主表表头，数据区留空）。主表本身不变。
- 分表组 → 普通组：显式动作。先把分部数据合并回主表，删除分部文件，
  storage 改回 `xlsx`。
- 只在旁边多出 `A#1.xlsx` 不会自动切换模式；加载报错并提示切换或移走文件。
- 可选：加载时检测到分部文件后提示“是否启用分表模式？”，必须人工确认。

## 11. 实施拆分

1. **core**：`GroupStorage::XlsxSplit`、节点 `row_parts`、分表加载器、分表保存器、
   改行数入口维护来源、结构校验、单元测试。
2. **CLI**：分表组导入/导出（导入要求主表存在）、`validate` 走合并模型。
3. **Tauri**：树图标、范围选择器、只读分部预览行、分部弹窗、
   按分部 Excel/Univer、模式转换入口。
4. **文档/skill**：storage 语法 `xlsx_split`、磁盘布局、限制。

## 12. 非目标与待定

- 不支持合并视图编辑、不支持分部结构编辑、不支持 sheet 名带 `#`。
- 不支持 `config/<group>/` 目录形式的分表（与 Tbl 组冲突）。
- 不支持分部之间行搬移；需要搬移时用剪切/粘贴到目标分部。
- 行顺序固定为“主表 → 分部文件名排序”，不提供跨分部拖动排序。
- 表头物理保护（Excel Sheet Protection）暂不做，仅严格校验；如需要，
  后续在“生成分部模板”时可选保护前 4 行。
- Constant / Enum 一期不参与分表。
