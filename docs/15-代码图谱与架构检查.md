# 代码图谱与架构检查

> 定位：本地开发辅助，不属于产品运行时，也不作为构建/CI 的硬依赖。

## 1. 工具选择

使用 [codegraph](https://github.com/colbymchenry/codegraph)（MIT，已安装 3.17.0）：

- 本地 SQLite 代码知识图谱，索引放在 `.codegraph/`；
- Rust 全量支持，native 引擎；
- 提供 CLI、MCP server、HTML 依赖图；
- 能查 callers / callees / impact / affected tests / cycles / communities / structure。

⚠️ 不是 Meta 的 CodeGraph（`facebookarchive/pfff` 的 GTK 工具）。那个项目已归档，主要面向 C/Java/PHP，不适合这个 Rust workspace。

## 2. 仓库约定

- `.codegraph/`、`.codegraph-wsl/` 已在 `.gitignore`，索引进 Git 视为错误；
- 索引只读使用，不提交、不作为构建产物、不写进发布包；
- 大改结构后重建一次：

```bash
codegraph build .
codegraph stats
codegraph cycles
codegraph structure
```

## 3. 常用查询

```bash
# 改一个文件前：谁依赖它
codegraph impact crates/core/src/ops.rs

# 函数级影响面 / 调用者 / 被调用者
codegraph fn-impact import_tbl_files
codegraph callers import_tbl_files
codegraph callees save_project_files

# 文件/符号上下文与数据流
codegraph context build_manifest
codegraph dataflow summarize

# 架构健康
codegraph cycles
codegraph structure
codegraph communities
codegraph roles
codegraph complexity

# 可视化
codegraph plot          # 生成交互式 HTML 依赖图
codegraph export --format mermaid
```

## 4. MCP 接入（可选）

```bash
codegraph install --target=claude --yes
```

然后重启 Claude Code。默认只暴露 `codegraph_explore`；需要更多工具时设置
`CODEGRAPH_MCP_TOOLS`。

索引仍需按项目单独建：

```bash
cd D:/workerspace/git/tablet
codegraph build .
```

## 5. 与 Rust 原生工具的分工

| 工具 | 用途 |
|---|---|
| `codegraph` | 调用链、影响面、模块社区、循环依赖、HTML 图 |
| `cargo modules` | Rust 模块树与模块依赖；看 crate 内部层级 |
| `cargo tree --duplicates` | 重复 crate 依赖 |
| `cargo machete` | 未使用的依赖 |
| `cargo deny check` | 许可证 / 依赖策略 / 安全公告 |
| `cargo clippy` | 代码级问题 |

架构规则仍然要显式守：

- `tablet-core` 不依赖 `tablet-cli` / `tablet-slint`；
- `app-cli` / `app-slint` 只依赖 `core` 的公开 API；
- 领域模块之间通过 trait / 窄接口组合，不跨层直接引用；
- 新增跨 crate 引用前先看 `codegraph impact`，不要靠“看起来能编过”。

## 6. 当前基线（3.17.0 首次索引）

```text
228 files / 6483 nodes / 13548 edges
Rust 106 files
文件级循环：2
  model.rs ↔ tblschema.rs
  history.rs ↔ ops.rs
最大文件：ops.rs 6458 行、validate.rs 2140 行、tblschema.rs 2102 行
```

这些是**观察**，不是立刻要改的清单。真正做架构收敛时优先看：

- `ops.rs` 是否按“项目 / 节点 / 历史 / 导入导出”拆模块；
- `model.rs ↔ tblschema.rs` 的结构类型是否应该下沉到独立 `schema_types`；
- `history.rs ↔ ops.rs` 是否可以通过 trait 或回调解除双向依赖。

## 7. 使用边界

- codegraph 的 call confidence 不是 100%，Rust 宏、trait 分发、动态调用可能漏边；
- “dead” 结果里有大量 FFI / 入口误报，不能直接拿来删代码；
- 它是辅助定位工具，不是正确性证明；验证仍以下面为准：
  - `cargo test --workspace`
  - `tests/run_all.sh --skip-perf`
  - `cargo check --workspace --all-targets`
